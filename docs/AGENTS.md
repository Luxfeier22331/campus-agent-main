# 文档写作规范

本文件维护 `docs/` 的放置和写作规则；修改模块 README 时也使用这些原则。
分区入口见 [README](./README.md)，分工理由见
[ADR-0038](../.agents/notes/implemented/process/2026-07-16-adr-0038-documentation.md)。
决策记录的专用格式与生命周期由[笔记规则](../.agents/notes/README.md)维护。

## 放置与范围

- 先确定读者要完成的操作或查询的问题，再找最近的所有者；能修改已有文档时不新建。
- 每个事实由一处维护。父文档只概述子项的目的、职责和主要行为，细节链接所属文档；
  参考文档也只能详述自己的主题，不复制下级合同、测试清单或模块目录。
- 模块配置、消费接口和局部限制放模块 README；跨模块结构放架构文档，接口和数据语义
  分别放合同与数据文档，可重复操作放 runbooks。一个窄能力无需为每种分区复制正文。
- 普通文档描述当前有效事实与明确标识的长期约束，不把目标、提案或一次运行结果当作当前实现。
  选择理由与被否方案放决策笔记；真实故障的经过与漏检原因放[事故复盘](./postmortem/README.md)。

## 组织与表达

- 步骤型指南说明前置条件、按依赖排序的操作、可观察的成功结果及相关失败处理；查询型参考
  按读者查找的问题组织，说明行为和限制。两类内容都较多时分开，少量混合时明确小节用途。
  这是写作分工，不新增 `doc_type` 枚举或要求批量改写现有元数据。
- 正文使用简体中文；代码、命令、路径、字段、状态值和产品正式名称保留原值。
- 写清主体、行为、条件与后果。删去推演过程和重复说明时，保留消费者依赖的失败语义、
  时序、所有权、例外、禁止行为及兼容承诺；篇幅短不能替代合同完整。
- 代码、schema、配置和测试承载实现事实。文档链接这些所有者，不手抄可生成的目录和清单。
  保留仍有用的理由与已知限制，不为追求简短删除决策内容。
- `docs/` 文档保留 `doc_type`、`owner_boundary` 和 `status: active` 元数据，使用相对 Markdown
  链接引用仓内文件；编号只用于已有历史记录，新决策使用话题名。

## 修改与验证

先更新事实所有者，再调整索引和引用；移动或删除文档时同批修复入站链接。
新增或变更命令说明时，以实际入口核实行为；已有等价验证可复用，未执行的外部操作明确说明，
不为验证文档擅自部署或修改外部状态。检查选择见[测试与验证](./reference/verification.md)。

入口预算由[预算配置](../scripts/docs/doc-budgets.json)维护。超限先移动不属于本层的细节，再压缩
重复表达；确有新增职责才调整预算并说明原因，不以删减必要合同满足行数。
归档笔记不参与当前文档的措辞和格式整理；引用历史时显式查阅，不作为当前行为依据。
