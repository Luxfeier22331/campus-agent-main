# 复盘 0001：归档命令失效，却被报告为已完成

## 摘要

2026 年 9 月 16 日的文档治理中，归档命令先写出带 `Archived:` 标记的目标文件，再将原文件移动到
同一目标，覆盖了刚写入的标记；格式检查还错误要求归档的状态值改为 archived。归档目录为空且
已有测试没有执行真实归档，这两个问题没有被完成前的检查发现，归档功能被错误报告为已经完成。
后续修复保留原文和状态、一次写入带标记的目标，并以实际归档、拒绝覆盖及冻结行为测试验证。
教训是：空集合上的检查通过不能证明一次真实操作可用，完成报告必须与实际覆盖的行为一致。

## 影响

交付说明声称归档命令和校验已完成，但实现不能生成符合约定的归档结果；维护者会据此高估功能的
可用性。缺陷在本地文档治理工作区被发现并修复，没有证据表明已有历史笔记因此丢失，也没有证据
表明该版本已进入生产环境。修复不等同于代码已合并或部署。

## 经过

初版是尚未独立提交的工作区代码；下列顺序依据当时的编辑、检查输出和完成报告，不存在可引用的
初版修复前 commit。此处保留关键故障片段，当前实现和回归验证链接见后文。

1. 新增归档命令、归档检查、模板和 Skill。命令通过追加写入目标再移动原文件来完成归档。
2. 第一次文档检查因 templates 被当作未知 lifecycle 失败；排除模板后，文档检查和既有 9 个测试通过。
3. 当时没有正式归档文件，测试也没有执行归档命令。完成报告仍将这些通过结果作为归档能力完成的依据。
4. 后续治理检查代码时发现标记被覆盖，以及原状态与格式检查不一致；随后修复实现并新增实际行为测试。
5. 修复后的 17 个文档测试、文档检查和相关静态检查通过。本文引用这组现有行为覆盖，不新增复盘专用测试。

## 根因

初版的关键操作顺序如下，其中 `content` 是原文加归档标记，`absolute` 是原文件，`target` 是归档位置：

```text
appendFileSync(target, content);
renameSync(absolute, target);
```

在该 Linux 环境中，第二步会用原文件替换已存在的目标文件。原文件没有 `Archived:`，所以第一步
写出的归档标记丢失；目标已存在时也没有拒绝覆盖的保护。命令执行成功不代表结果满足归档合同。

另一个不一致在格式检查中：它要求 `Status` 与 archived 目录同名，而归档规则要求保留
`Status: implemented`。因此即使修正标记写入，合法的保留状态仍会被普通格式检查拒绝。

## 为什么检查没发现

- 归档检查只遍历已存在的归档文件。目录为空时，没有任何文件接受标记检查，却仍输出检查通过。
- 当时的 9 个测试覆盖 frontmatter、链接、活动笔记格式和预算，没有验证从 implemented 到 archived 的实际结果。
- 树检查接纳 archived 目录、命令文件存在及检查退出码为零，被错误地合并成“归档能力可用”的结论。
  完成报告没有区分已验证的结构与未经执行的操作。
- “保留原状态”的文字规则和格式检查要求没有通过一个真实归档场景联合验证，矛盾一直隐藏。

## 修复与回归验证

[归档实现](../../scripts/docs/archive-agent-note.ts)保留原始字节和状态，将原文与唯一归档行合并，
以不覆盖目标的写入方式创建归档，成功后才移除源文件；提供替代目标时验证目标并生成相对链接。
普通格式检查跳过归档正文，标记、原状态与已提交归档的冻结边界由
[专用检查器](../../scripts/docs/check-archived-agent-notes.ts)维护。

[行为测试](../../scripts/docs/notes-governance.test.ts)覆盖下列真实结果：

| 场景 | 验证内容 |
| --- | --- |
| 实际归档 | 原文和 implemented 状态保留，目标有归档标记及正确的相对替代链接 |
| 目标已存在或输入不合法 | 拒绝覆盖、错误路径、缺失替代目标或参数；相应场景保留源文件和已有目标 |
| 缺失或重复归档标记 | 检查明确失败 |
| 已提交归档被修改或删除 | Git HEAD 冻结检查明确失败 |
| 归档保留旧章节和失效出站链接 | 不受当前正文要求阻塞；当前文档指向归档的入站链接仍检查 |
| 模板参与检查 | 模板不被识别为正式 lifecycle 或笔记 |

第一项会直接捕获初版丢失标记的问题；实际归档后的格式检查会捕获原状态冲突。其余场景验证
已约定的拒绝覆盖、冻结和历史正文边界，不依赖在真实仓库中先创建历史归档。

## 长期教训

验收证据须对应完成声明：检查器没有发现问题、操作成功退出、实际输出满足合同，是不同结论。
对新增的文件变换命令，应观察变换后的内容以及源、目标文件状态；一次空目录扫描不具有同等效力。
已经覆盖这些行为的有效测试应复用，不为报告完成而重复运行或增加另一套检查。

决策笔记的保留、取代、归档和验证边界由
[决策笔记树治理](../../.agents/notes/implemented/process/2026-09-16-agent-notes-tree.md)维护。
本篇保留故障与漏检经过，不重复定义该治理规则，也不把每次局部修复升级为事故复盘要求。
