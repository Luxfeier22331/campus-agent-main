# 校园地图制图流程

## 目标和边界

本文说明从空 QGIS 工程开始，制作可交给 Campus Web 消费的校园矢量地图的流程。制图者在仓库
外完成下载、比对、编辑和导出；QGIS 工程、GeoPackage、参考图、瓦片缓存、下载快照、地理配准
文件和临时导出都不进入仓库。仓库只接收真实接入时确定的最终 GeoJSON 和消费者明确需要的其他
最终资产。

这是一套适用于新校区的通用制图流程。当前丰台或海淀的 GeoJSON 只能用于现有产品回归和接入
核对，不能作为新地图的范围模板、坐标事实源或图层模板。两个校区的真实最终交付另行按本流程
制作，不在本手册中预先固定文件清单。

本手册只规定几何生产和交付边界。参考来源是制图时的人工对照资料，不在仓库形成独立的来源
数据集；本流程不新增 `release.json`、逐层 `license` 字段、许可审批表或下载快照。仓库已有的
Campus Web 资产 manifest、地点字段和验证命令仍以其当前代码和合同为准，等真实数据接入时再
执行，不把 QGIS 工作文件混入产品资产。

## 流程概览

1. 确定本次校区和产品覆盖范围。
2. 在仓库外收集 OSM vector 和其他人工参考资料。
3. 创建 QGIS 工程、GeoPackage、编辑图层和坐标系。
4. 划定校区边界，按目标比例尺绘制建筑和其他要素。
5. 对 OSM 缺失的建筑进行多来源核对后手工描边和标注。
6. 检查几何、位置、名称和导出结果。
7. 导出 `EPSG:4326` GeoJSON，重新载入复核，再交给 Campus Web 接入。

## 1. 确定制作范围

1. 明确校区名称、需要展示的对象和最终地图用途。常见对象包括校区边界、建筑、道路或步行
   路径、绿地、运动场、出入口和需要搜索的地点；没有实际内容或消费者需求的图层不创建。
2. 为参考资料准备校区工作区及其周边约 `50-100 m` 的上下文。周边道路、围墙和出入口有助于
   对齐位置；这段上下文不是要求最终 GeoJSON 必须扩大到固定距离。
3. 根据围墙、道路、出入口以及多项参考资料绘制工作边界。不要把当前某个校区的硬编码 bounds
   复制到新校区；最终 bounds 应从完成并复核的校区几何推导。
4. 对只应出现在校内的图层，在编辑图层的副本上使用 `Clip` 检查范围。跨越边界的道路、入口
   或校外接驳点按产品含义决定是否保留，不为了满足几何裁剪而删除有用的上下文。

## 2. 收集和对比参考资料

### OSM vector

1. 使用 QGIS 的 QuickOSM 或 Overpass 获取工作区及周边上下文的 OSM vector。至少检查与校区相关的
   `building`、道路、步道、校园边界、绿地和运动场等已有要素；查询结果只作为坐标框架和已有
   geometry 的参考。
2. 将原始 OSM vector 作为只读参考图层保存到仓库外。不要直接在原始图层上改名或修轮廓；把需要
   交付的结果绘制到独立的编辑图层中。
3. OSM tiles 可以作为 QGIS 画布上的视觉参考，但不是必须输入，也不是 Campus Web 运行时的
   basemap 依赖。没有瓦片时，OSM vector 仍足以提供坐标框架。

### 其他人工参考

1. 可在开发环境临时对照 Google Maps、Google Earth、学校公开校园图、其他可用地图或现场核对
   资料，用于比较建筑位置、朝向、道路关系和名称。这里的用途是多来源人工比对，不是从某个
   服务独立提取一份数据，也不把其瓦片、截图或缓存提交到仓库。
2. 学校抽象校园图适合核对名称、分区和相对关系；只有在图上存在足够稳定的控制点和合理比例时
   才使用 QGIS Georeferencer 将其配准。无法可靠配准的图不强行当作精确底图。
3. 至少用两项相互独立的线索检查重要建筑的位置和朝向。资料冲突、名称不明或只能确认大致位置
   时，在本地工作目录记录待核对项，不用单一模糊图像制造精确轮廓。

## 3. 配置 QGIS 工程

1. 在仓库外建立一个校区工程，保存 `.qgz` 和一个 `.gpkg`。在 GeoPackage 中将参考图层与编辑图层
   分开；编辑图层按实际内容使用单一几何类型，例如 `boundary`、`building`、`road`、`path`、
   `landuse` 和 `poi`。这些名称是制图阶段的工作名称，最终字段以消费者合同为准。
2. 编辑时使用当地适合大比例尺、以米为单位的投影坐标系。当前北京校区可将 `EPSG:4548` 作为
   起点，并先用已知道路或建筑关系检查是否对齐；不要为了修正 CRS 偏移而手工拖动整层数据。
   OSM 的经纬度数据可由 QGIS 进行图层转换，最终导出时再统一为 `EPSG:4326`。
3. 在 `Project > Snapping Options` 为编辑图层启用 `Vertex` 和 `Segment` 吸附，像素容差先从
   `10-12 px` 开始，并在少量对象上验证不会吸附到参考层的错误顶点。只有确实需要共享边界的
   对象才开启 `topological editing`；独立建筑通常不需要。
4. 使用 Rectangle、Advanced Digitizing 等工具绘制规则建筑，用 Geometry Checker 定期检查几何。
   临时颜色、标签和线宽只用于人工审阅，不把 QGIS 样式文件当作最终产品合同。

## 4. 按比例尺绘制

制图时同时观察全校和局部视图，使用稳定的画布比例尺。以下范围是起始建议，不是精度承诺：

| 工作内容 | 建议比例尺 |
| --- | --- |
| 全校覆盖和总体关系 | `1:3000-1:5000` |
| 校区边界、道路和出入口 | `1:1000-1:2000` |
| 建筑轮廓和建筑间关系 | `1:500-1:1000` |

没有测绘图、正射影像或其他高精度资料时，不要为了追踪屏幕细节无限放大，也不要把屋顶透视、
阴影或装饰物当作建筑基底。比例尺决定应保留的几何细节；地图运行时的 MapLibre zoom 和视口
配置在真实接入时另行由 Campus Web 决定。

## 5. 绘制建筑和学校地点

### 已有 OSM 建筑

1. 将 OSM 建筑与道路、围墙及其他参考资料叠加，逐区检查是否存在遗漏、错位、重复或明显过时
   的轮廓。
2. 轮廓与多来源资料一致时，可以在独立编辑图层中重用其位置；轮廓错误时按可确认的建筑基底
   修正，不把 OSM 的 `name` 或 `building` 标签自动当成学校正式名称或建筑分类。

### OSM 中缺失的建筑

1. 先用道路、路径、相邻建筑、校区图和可用影像确定建筑所在位置及朝向。
2. 再估计建筑外轮廓的可信范围，在 `building` 编辑图层中手工逐顶点绘制。规则矩形使用矩形或
   正交工具，不规则建筑只描出被资料支持的外轮廓。
3. 对同一建筑的多个连体部分，按产品展示和可识别性决定合并或拆分；不要为了贴合模糊影像加入
   没有证据的凹槽、屋檐或内部结构。
4. 建筑位置和范围都足够确定时发布 polygon。只能确认一个位置、不能可靠确认外轮廓时，在最终
   图层合同允许的情况下保留 point；若连位置也无法确认，只在本地待核对记录中保留，不发布猜测
   的 polygon。

### 建筑名称和地点标注

1. 名称优先使用学校资料或已核对的正式名称。名称未确认时保留稳定的内部制图 ID，名称留空或
   标记为待核对，不根据模糊地图标签猜名。
2. 建筑 polygon 表示物理轮廓；需要在产品中搜索、点击或导航的学校地点另按实际消费者需要
   建立 point 和地点属性。同一栋建筑可以承载多个地点，不能用建筑中心点替代所有入口或服务
   位置。
3. 每个跨次编辑需要保持身份的对象都应有稳定 ID。不要使用 QGIS 临时 `fid`、当前排序或外部
   服务的 element ID 作为未经确认的产品身份；最终字段和映射在 Campus Web 接入阶段确定。

### 其他要素

- 道路和步行路径按中心线绘制；广场、绿地和运动场等有面积的对象绘制为面。
- 出入口和设施点放在实际位置，不任意放在建筑中心。
- 一个区域完成后立即打开名称标签检查对象、文字和位置是否对应，再进入下一区域。

## 6. 几何和内容检查

1. 在 `1:5000`、`1:2000` 和 `1:1000` 左右的视图分别检查覆盖范围、建筑关系、道路连通关系和
   标签遮挡；同时关闭某一参考来源，确认结果不是误跟随单一图层。
2. 使用 QGIS Geometry Checker 检查自相交、无效环、重复节点、明显重叠和几何类型错误。逐项
   查看定位结果后人工修复；不要不经检查批量接受自动修复。
3. 检查每个对象的稳定 ID 不为空且不重复，名称与几何对象一致，建筑没有被错误吸附或意外裁切。
4. 检查校区边界、工作区外的上下文对象和待核对项，确保不把参考图层本身误导出。

## 7. 导出和交给 Campus Web

1. 对实际需要交付的编辑图层使用 QGIS `Export > Save Features As`，格式选择 `GeoJSON`，编码选择
   `UTF-8`，目标 CRS 选择 `EPSG:4326`，并按 RFC 7946 输出经纬度坐标。
2. 只导出已确认需要的图层、要素和属性；不为了固定布局创建空文件，也不把 QGIS 样式、参考来源
   或工作备注写入产品字段。
3. 在一个新的 QGIS 工程中重新载入导出文件，核对坐标位置、经纬度顺序、中文、几何类型、对象
   数量和稳定 ID。发现转换后偏移或属性丢失时，修正导出设置后重新检查。
4. 真实接入时，把通过复核的最终 GeoJSON 交给 Campus Web 维护者，按当时的消费者合同生成或
   更新其静态资产和地点目录，并运行所属验证命令。不要提交 `.qgz`、`.gpkg`、OSM 下载文件、
   瓦片缓存、参考截图、Georeferencer 输出、QGIS 备份或其他中间文件。
