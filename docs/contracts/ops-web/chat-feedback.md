# 回答反馈查询

Ops Web 的 `/chat-feedback` 供运营只读查看当前回答反馈。浏览器通过同源
`/api/ops/chat-feedback` 调用 Ops 服务端，后者沿用既有 Ops 准入和内部 Bearer token，
读取 App API 的 `/api/internal/admin/chat-feedback`。两端均提供列表和 `/:feedbackId` 详情。
精确字段和参数由 `packages/contracts/src/chat-feedback.ts` 维护。

## 查询口径

- 列表支持评价类型、最近反馈时间范围、精确 `requestId` 和游标分页；默认每页 50 条，上限 100 条。
- 时间范围使用反馈 `updatedAt`，起点包含、终点不包含；按 `updatedAt`、`feedbackId` 同向降序分页。
  页面日期按北京时间解释，结束日期包含当天；未选择日期时不限时间。
- 响应返回当前页、下一页游标和匹配总数、有帮助数、没有帮助数。统计应用全部筛选条件，
  不应用分页游标；列表和统计在同一数据库读取快照内计算。跨次查询读取当时的当前反馈。
- 切换评价覆盖当前记录，撤回删除记录；本接口不统计历史提交次数，不保存反馈历史。
- 已软删除会话的反馈不进入列表、详情和统计；本查询不修改其存储或清理周期。
- 回答按反馈的消息 ID 读取，对应问题按回答的 `parentMessageId` 在同一会话内关联。
  无法关联时问题为 `null`，页面显示“原问题不可用”，不以其他轮次的问题替代。
- 列表返回最多 160 字符的问答摘要，详情返回完整文本、已保存来源和关联 ID。已有原因码按语义展示，
  空数组显示“未提供原因”；本项不增加用户端原因采集或用户搜索。所属会话查看见 [会话只读查询](./chat-conversations.md)。

## 页面与失败状态

筛选和当前分页位置保存在 URL；改变筛选重置分页。新查询等待时不展示上一查询的记录，
同条件刷新保留已有内容。详情按需读取；URL 中的 `feedbackId` 控制选中的反馈，不参与列表查询和统计。刷新或直接打开链接可以恢复详情，关闭后焦点回到对应查看按钮，记录已离开列表时回到筛选控件。
详情可跳转对应请求或所属会话，并通过 `from` 返回链接恢复反馈列表筛选、分页和选中的反馈。

列表、详情及 Ops 转发的失败响应使用 `no-store`。非法筛选或游标返回 `400`；
反馈已撤回、所属会话已删除或记录不存在时详情返回 `404`。后端不可用显示错误和重试入口，
不能伪装为空列表；原有用户反馈写入与撤回接口保持不变。
