# 会话只读查询

## 历史会话列表

`GET /api/ops/chat-conversations` 返回按会话聚合的摘要列表；每条记录代表一个会话，运行 request
作为会话轮次的诊断入口。列表支持会话内容、用户、状态、失败和时间范围筛选，并使用游标分页。
完整消息继续由详情接口提供。摘要问题、回答与状态均来自最新 dispatch：问题关联其 user_message_id，回答关联其 assistant_message_id 与 request_id；缺失时返回 null，不能回退到其他轮次。

`ownerQuery` 接受用户名称、邮箱片段或完整用户 ID（去除首尾空格，最多 320 字符）。名称和邮箱
不区分大小写，按字面包含匹配；用户 ID 精确匹配。`ownerId` 保留已有精确过滤语义。
用户条件与内容 `q`、时间和其他条件取交集，均在数据库分页前应用；不先截取一页再查用户。

`hasFailures` 接受 `true`、`false`，缺省表示全部；非法值返回 400。状态按最新 dispatch 判定，
产品终态优先。dispatch 为 `accepted` 时，关联执行记录的 `running`、`streaming`，以及执行已结束但
产品尚未终结的 `completed`、`failed`、`expired`、`canceled` 均显示 `RUNNING`；其余显示 `PENDING`。
状态和失败条件在数据库分页前筛选；列表与运行诊断采用同一状态规则。

时间筛选遵守[统一时间范围](./runtime.md#时间范围)，默认今日，按会话最近活动时间过滤。
日期以北京时间填写和回显，URL 的 `from`、`to` 保留 ISO 时间，查询包含开始日零点、
不包含结束日次日零点。清除筛选回到今日并清空其他输入与游标；前进后退或从详情返回时
恢复已应用条件，手动刷新保留未提交的输入。部署顺序为先应用两列只读授权 migration，再发布
App API 和 Ops Web。

## 接口与所有权

- 浏览器：`GET /api/ops/chat-conversations/:conversationId`，沿用 Ops 准入。
- App API：`GET /api/internal/admin/chat-conversations/:conversationId`，沿用内部 Bearer token。

App API 拥有会话读取；Ops 转发并使用现有来源链接转换。会话列表只返回摘要，不提供聊天写操作。
返回会话 ID、标题、创建与更新时间、活动请求 ID，以及全部当前保存消息。消息包含 ID、角色、
answer/error 类型、正文、创建时间、父消息 ID、请求关联、产品来源和当前反馈。DTO 由
`packages/contracts/src/chat-conversations.ts` 维护，不返回账号资料、session slots 或模型内部输入。

消息按创建时间、轮次、角色（用户在先）、消息 ID 稳定排序；问答关联依据父消息 ID，不猜测相邻消息。
用户消息缺少请求 ID 时，通过同一会话的 dispatch/user-message 关联读取。来源只消费已保存的
`source_items` 产品投影，不从正文重建引用。反馈只关联同一会话、消息和会话所有者。
会话与消息在一个只读数据库快照内读取；归档不影响读取，软删除或不存在返回 404。

所有响应使用 `no-store`。非法 ID 返回 400，后端不可用显示读取失败；不能替代为空会话。
编辑截断删除的消息不重建；已删除会话不展示旧缓存。现有运行记录的保留与查询行为不变。

## 页面与导航

筛选区位于整个会话工作台顶部。用户、会话内容与最近活动时间常驻；状态、反馈、失败条件在
“更多筛选”中展开。文本与状态条件点击“搜索”或回车后应用，时间预设即时应用。
已应用的用户与其他条件显示可移除标签；窄屏阅读正文时隐藏筛选，返回队列后恢复。

`/conversations?conversationId=...&messageId=...` 在列表工作台中打开会话。宽桌面保留左侧队列和右侧
阅读区并分别滚动；窄屏在队列与正文间切换，返回队列时聚焦原会话。上一条、下一条只在当前页
结果内移动。筛选与翻页清除当前选择；刷新和执行详情返回保留筛选、游标、选中会话与消息定位。
列表 URL 的 `from`、`to` 仍是查询时间，不用于返回路径。轮次选择和首末轮按钮定位正文。

`/conversations/:conversationId?messageId=...&from=...` 从运行或反馈详情进入。
初次读取或目标改变时定位消息，目标不存在时保留当前会话并提示定位消息不可用。
有请求关联的轮次可以进入运行详情；返回链接保留原筛选、分页、反馈和消息定位。
`from` 只允许站内问答概览、运行列表、执行详情、反馈列表、历史会话列表或会话详情。

页面展示已保存快照，手动刷新保留阅读位置，不订阅实时流。活动请求提供运行详情入口。
首次失败、刷新失败、空会话、目标消息缺失和会话不可用分别展示。
运行、反馈与会话页面共用 Ops 的回答正文和来源组件，来源编号、片段及访问规则保持一致。

正文中的相对通知、文档引用通过本条回答已归一化的来源动作解析，使用与来源卡片相同的
Campus Web 绝对地址（包括文档锚点）。没有匹配的可用来源动作时保留引用文字，不生成 Ops
站内死链；外部绝对链接保持原地址。会话、运行详情和反馈详情共用这一渲染行为，不改写已保存正文。
