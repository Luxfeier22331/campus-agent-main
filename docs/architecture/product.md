# 产品定位

## 文档边界

本文定义 `campus-agent` 服务谁、解决什么问题、向用户承诺什么，以及哪些能力不属于产品
范围。当前已经实现的界面和服务由最近的产品、系统、领域和合同文档及可执行实现维护；技术所有权
和运行方式由目标架构、合同、数据文档和决策笔记维护。

## 核心定位

`campus-agent` 是面向学校信息与校园服务的校园助手。它帮助访客、学生和教职工查找可信的
学校资料、理解校园规则并读取已经开放的校园服务信息。

它不是开放域聊天机器人。系统只使用已开放的校园工具、已发布学校知识和当前回答中可见的
公开校园网页证据；无法可靠确认时，应要求用户澄清或明确说明无法回答，不得用模型猜测补齐
缺失事实。

## 用户

- 潜在考生、家长和校外访客：查询公开的学校、专业、制度和校园信息；
- 学生和教职工：查询制度、培养方案、校园服务和地点信息；
- 运营人员：通过独立的受控后台维护配置并排查运行问题。

运营人员不是主问答能力的终端用户。采集、评测、发布和运维操作不得包装成普通用户可调用
的工具。

## 解决的问题

- 高频校园问题长期依赖人工重复答复；
- 学校资料分散，用户难以定位当前有效且可追溯的答案；
- 文档、问答和校园地图需要共享一致的身份与校园事实。

## 产品承诺

- 回答范围限定在学校信息和已经开放的校园服务；
- 答案依据必须可追溯，来源不足时不得强行作答；
- 尚未进入 Campus Docs 的公开校园信息可以通过模型托管的网页搜索取得可见来源；
- 只有具备真实数据、明确合同、运行实现和验证覆盖的能力才能向用户开放；
- 主问答不按学生、教职工或院系拆出不同的工具集合；受限资料仍可按身份控制访问；
- 账号、会话和额度可以限制使用，但不能改变事实来源或降低回答要求；
- 状态页、文档页、地图和问答页可以分别呈现，但不得各自维护一份相互冲突的事实。

当前开放范围由代码注册表、产品配置和所属产品、领域合同共同验证。schema、配置、
页面占位或测试数据的存在不代表能力已经向用户开放。

## 产品界面

产品可以通过以下界面承载不同任务：

- AI 助手：问答、澄清和已开放工具的统一入口；
- 文档站：浏览和阅读规范文档；
- 校园地图：浏览地点和地图信息；
- 账号页面：管理身份、会话和个人设置。

这些界面属于同一个产品，但不要求所有功能都经过聊天或模型工具。当前界面是否存在及其
运行边界见 [产品运行时](./system/product-runtime.md)，环境是否部署由环境仓选择和运行状态证明。

## 扩展边界

新增校园能力必须先确认真实用户需求和数据所有者，再决定使用页面、查询接口还是模型工具。
不得为了预留未来能力先建立空工具、空服务或未被消费的数据结构。

地点查找和路线导航尚未作为模型工具开放。其长期边界由
[ADR-0027](../../.agents/notes/implemented/architecture/2026-07-16-adr-0027-navigation.md) 记录；当前地图地点读取见
[place.md](../domains/place.md)。Primary Agent 可以使用 Agents SDK 原生 `web_search` 补充或核验
公开校园网页信息；它只服务校园问题，由模型根据问题和工具声明决定是否调用，不是
`campus_search` 失败后由代码自动触发的回退。Finalization 校验 SDK 原生引用，把网页依据转换为
正文中的编号来源链接与 `web_page` 来源卡；Web Search 仍不写入本地 `tool_results` 或工具轨迹，
也不保存供应商原始搜索结果。通用开放域联网问答仍需另行作出产品决策。

## 不属于本产品

- 通用开放域聊天，或与校园问题无关的联网搜索；
- 替代学校 ERP、OA、预约、支付或事务办理系统；
- 让浏览器、用户或模型选择数据库、索引、供应商或内部集合；
- 把运维、采集、评测和发布能力暴露为普通用户工具；
- 用临时回退路径掩盖缺少数据、合同或下游故障；
- 在没有路线事实时由模型生成导航路径。
