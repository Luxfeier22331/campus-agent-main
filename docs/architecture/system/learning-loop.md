# 学习闭环

## 文档边界

本文定义线上使用如何转化为可复核的改进输入，以及 app-api、Langfuse 和评测包之间的所有权。
具体字段、评分方法和操作命令由合同、代码和评测参考维护。

## 主链

```text
线上请求与用户反馈
-> 问题记录或所属模块修复
-> 评测输入或所属模块修复
-> 离线评测与回归
-> 所属模块修改及验证
```

线上反馈和 trace 只是输入信号，不能自动改变提示词、工具、索引、模型或发布结果。
发布和环境运行结果由相应所有者单独判断，不是本文定义的固定闭环阶段。

## 输入信号

问题分析可以参考：

- 用户对答案的有用或无用反馈及原因码；
- 取消、重试、重复提问和无法回答等产品行为；
- 请求失败、工具失败、证据不足和终结失败；
- 执行策略、问题覆盖、证据与引用缺口；
- 上下文准备、Provider 首 token、工具轮次、浏览器首答案、总耗时、模型用量和稳定错误分类；
- Langfuse 或 Ragas 的评分和人工标注。

app-api 只保存产品运行所需的反馈、请求关联和受控观测字段，不复制原始提示词、回答、
模型响应、工具输入输出、记忆正文或观测平台原始记录。Langfuse 运行 trace 也只保存受控元数据；
需要正文的评测输入由调用方显式提供，不能从生产 trace 隐式提取。

## 当前实现

仓库没有独立的问题选择任务、候选存储区或候选发布器。需要评测时，由调用方选择并显式提供所需
输入；数据处理、标识和保存方式由具体任务决定。不需要评测输入的问题由对应模块直接建立 issue
或修复任务。

## 复核与改进

人员判断问题属于执行策略、问题分解、提示词、检索来源、工具合同、工具选择、模型性能、延迟预算
还是产品体验。若需要回归覆盖，调用方直接提供适合该任务的 Agent case；接受的
改进必须由真正的代码或数据所有者实施，并运行对应合同测试、评测或本地产品路径检查。

评测输入不等于训练集，也不等于允许发布。微调不是默认改进方式；只有在提示词、检索、上下文、
工具和模型选择均无法解决已确认问题时，才另行评估数据、隐私和验证要求。

## 所有权

| 所有者 | 负责 |
| --- | --- |
| `apps/app-api` | 保存消息反馈、请求观测和关联标识 |
| `apps/agent-control` | 保存运行、步骤、工具结果和终结的受控记录 |
| `apps/agent-runtime` | 发出 Agents SDK 与模型调用轨迹，不保存问题状态 |
| `packages/eval-langfuse` | Agent case 解析、产品路径评测和评分适配 |
| Langfuse | 在线轨迹和按需发布的评分 |

Ops Web 显示排查请求所需的运行摘要并维护在线模型配置；它不是质量复核和数据集
管理界面。

## 不允许的形态

- 让在线回答依赖 Langfuse 是否可用；
- 从生产请求自动训练或自动发布改动；
- 在 app-api 或 PostgreSQL 再建一套 Langfuse 原始数据副本；
- 把原始对话、记忆、检索正文或供应商响应放入普通运维投影；
- 用观测轨迹存在代替工作流成功、终态或发布结论；
- 为学习闭环另建自研标注平台或通用质量后台。
