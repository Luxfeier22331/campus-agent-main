# ADR-0038 文档治理

## 背景

仓库曾同时保留入口清单、当前说明、计划、审计记录和历史归档。同一事实因此出现多份
版本，过期计划也容易被误读为当前架构。

## 决策

### 每类事实只有一个所有者

- 产品、架构、合同、数据、操作、决策和参考资料按读者需求分工。
- `docs/README.md` 只提供分区入口；具体事实和所有权由最近的目录 README、所属文档和可执行
  来源维护。
- 其他文档可以链接或简要说明所有者结论，但不得重新定义同一事实。
- schema、配置或 fixture 的存在不证明能力已经实现、开放或部署。

### 人类可读文档使用简体中文

- 仓库自有的人类可读正文、标题、表头和图表标签使用简体中文。
- 能用清晰中文表达的仓库自有概念不用英文黑话；代码标识放在反引号中，并在首次出现时
  说明中文含义。
- 文件名和目录继续使用简短 ASCII；代码、命令、路径、环境变量、API 字段、schema
  标识、状态枚举和产品正式名称保持原值。
- OpenAPI 和 JSON Schema 的字段名保持不变，面向人的 `title`、`description` 使用中文。
- 法定文本、上游版权声明和明确标注的外部原文可以保留原语言；仓库自有说明仍使用中文。
- 不维护中英两套平行文档。出现真实英文读者需求后，再单独决策翻译和发布方式。

### 当前分支只保留仍有消费价值的文档

- 当前架构、有效合同和可重复操作步骤保留在所属文档中。
- 未合并的计划、待办和执行记录不作为默认分支的长期文档；完成记录、一次性审计和实施
  快照由 git history 保存。
- 被取代的正文只有在仍承载明确外部迁移约束时才保留；其余直接删除，不保留跳转页或归档目录，
  历史由 Git 保存。
- 不创建文档清单、清理流水账或 Markdown 树镜像。

### 生命周期按文档用途表达

- ADR 使用 `proposed` 或 `accepted`。完全被取代且不再承载独立理由的 ADR 直接删除；替代 ADR
  可以在 frontmatter 中保留已删除的决策编号。
- 运行中的长期文档使用 `active`；不建立历史文档状态或 archive 目录。
- 决策改变时新增或更新替代 ADR，不把新决策改写成旧决策当时的内容。

### 文档保持短而聚焦

- 目录表达上下文，文件名只表达对象。
- 一个窄能力只保留一份权威人类文档；架构、合同、数据和配置说明不得为
  同一窄能力各建一份重复正文。
- OpenAPI、JSON Schema、registry 和 fixture 可以作为可执行合同独立存在。
- README 只做入口路由，不维护完整文件目录。
- 长期文档不保留 agent 专属提示、临时命令输出、固定日期的执行状态或未来实施清单。

## 后果

- 新增文档前必须先确认是否已有所有者；能更新现有文档时不新增文件。
- 删除重复或过期正文时，迁移仍有效的唯一事实和引用，清理历史由 git 记录。
- 文档检查只验证可自动判断的结构不变量；代码、schema 和部署事实仍由所属实现验证。

## 未采用方案

- **永久保留全部计划和清理记录**：默认分支会成为不可判读的历史仓库。
- **用一个总文档复制全仓库事实**：所有权变化后必然产生第二份过期内容。
- **为每个文档规则增加中央扫描器**：领域语义应由所有者评审或所有者测试负责。
