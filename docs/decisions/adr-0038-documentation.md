# ADR-0038 文档治理

## 背景

仓库曾同时保留入口清单、当前说明、计划、审计记录和历史归档。同一事实因此出现多份
版本，过期计划也容易被误读为当前架构。

## 决策

长期文档按读者问题和事实所有者分工，README 只提供入口；一个窄能力能由一篇文档说明时，不建立
架构、合同、数据和操作的重复正文。代码、schema、配置和测试是当前实现来源，人类文档不得把
目标或一次运行结果写成当前事实。

仓库自有的长期人类可读文档使用简体中文；代码、命令、路径、字段、状态值和产品正式名称保持原值。
只保留当前有效事实、仍有独立解释价值的 ADR 和有效外部迁移约束；计划、执行记录、一次性审计和
被取代且无独立理由的正文由 Git 历史保存。普通文档使用 `active`，ADR 使用 `accepted`；完全被取代
的文档直接删除，不建立跳转页或归档目录。

本 ADR 只记录上述文档边界及其理由，不维护全仓文档清单、当前快照或额外治理扫描器；具体事实仍由
所属文档和可执行来源维护。

## 后果

- 新增文档前先确认已有所有者；能更新现有文档时不新增文件。
- 删除重复或过期正文时保留仍有效的事实和直接引用，历史由 Git 记录。
- 文档检查只验证可自动判断的结构不变量；领域事实仍由所属实现和合同验证。

## 未采用方案

- **永久保留全部计划和清理记录**：默认分支会成为不可判读的历史仓库。
- **用一个总文档复制全仓库事实**：所有权变化后必然产生第二份过期内容。
- **为每个文档规则增加中央扫描器**：领域语义应由所有者评审或所有者测试负责。
