# ADR-0010 可观测性

## 背景

系统跨越 Cloudflare Workers、自托管服务、Temporal workers 和模型运行时。
一次请求需要在产品状态、工作流、模型调用、日志、指标和错误之间关联，但这些数据面
不共享同一种保留期、访问权限或正文边界。

把仓库合同绑定到某个观测供应商，或让每个运行时自行向多个平台写入同一事件，都会
造成字段分叉、重复发送和敏感信息扩散。

## 决策

### 使用 OpenTelemetry 关联运行时信号

- 跨运行时 trace 使用 W3C Trace Context；运行时拥有的 trace、metric 和结构化事件
  优先使用 OpenTelemetry 语义和仓库定义的有限属性。
- `packages/contracts` 和领域逻辑保持供应商无关。供应商字段只能存在于运行时适配器、
  Collector 配置或对应平台的集成代码中。
- 配置、schema 或 exporter 存在只证明设计入口存在，不证明某个环境已收到可查询数据。

### Collector 负责通用 OTLP 信号的处理和分发

- 通用 OTLP 信号默认先进入 OpenTelemetry Collector，由它完成入口认证、资源补充、
  禁止字段删除、采样、批处理、重试和按信号分发。
- 运行时只有在平台能力确实需要时才使用供应商 SDK，例如 Worker 错误捕获或 Langfuse
  的 Agent SDK instrumentation。这类集成仍须传播统一关联标识，且不得反向定义仓库合同。
- 业务代码不为同一类通用事件维护多套供应商写入逻辑。

### 各数据面保留各自真相

- PostgreSQL 运行投影保存产品请求状态和有限排查摘要。
- Temporal 保存工作流历史、重试、超时、取消和任务队列真相。
- OpenObserve 保存内网可查询的日志、指标和调用链。
- Langfuse 保存受信任的模型与工具调用 trace，以及数据集、评分和评测流程。
- Sentry 用于应用错误、异常和性能排查。
- Axiom 用于外部结构化事件、指标、查询和告警。

这些平台是互补的消费面，不得改写产品请求状态。某个输出未在环境中启用时，不得由
代码或文档推断其已经可用。

### 按数据类别限制正文

- credential、secret、认证材料、Cookie、JWT 和数据库连接信息不得进入任何观测面。
- 通用日志、指标、运行事件、产品投影、Sentry 和 Axiom 不保存原始提示词、用户问题、
  回答、会话正文、检索片段、文档正文或长期记忆正文。
- 受信任的 Langfuse trace 可以在明确的访问控制和保留策略下保存模型输入输出、记忆
  上下文和已授权检索内容；这些正文不得复制到产品投影或其他通用观测面。
- 用户关联优先使用受控标识或哈希；高基数字段不得进入指标标签。

具体事件名、允许字段、采样、保留期、告警和完成度由所属运行时、Collector 配置与
reference 文档维护，本 ADR 不复制这些动态清单。

## 后果

- 新增观测信号时，必须明确 owner、数据类别、关联标识、允许字段、消费面和验证方式。
- 新增输出平台时，必须先定义访问控制、禁止字段、保留策略和故障边界。
- 输出失败不能伪造或覆盖产品状态；排查页面只能按所属数据面的合同读取或关联。
- 供应商替换主要发生在适配器和部署配置，不要求领域合同迁移。

## 未采用方案

- **单一平台保存所有运行和产品真相**：权限、保留期和查询职责无法保持清晰。
- **每个运行时直接写入所有平台**：会复制认证、清理、采样和重试逻辑。
- **把原始观测正文镜像进产品数据库**：扩大敏感数据范围，并产生第二份不一致真相。
