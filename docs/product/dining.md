# 食堂产品需求

## 目标

学生可以从食堂和楼层进入地图，快速找到档口、查看菜品与参考价格，并阅读与具体菜品绑定的公开
评价。

## 用户行为

- 按校区、食堂和楼层切换内容；
- 在地图与列表中定位档口，并保持两者选择一致；
- 查看档口菜品、标签和可用的参考价格；
- 查看当前菜品的公开评价、评分、支付价格和图片；
- 在当前食堂范围内搜索档口、菜品和标签；
- 通过 URL 分享当前食堂和楼层。

切换食堂或楼层时清除不再有效的档口和菜品选择。地图加载失败时保留列表、菜品和评价，不用空白
页面替代可用内容。没有正式地图的食堂使用明确的占位布局，不伪造真实位置。

## 内容规则

- 菜品名称保留来源中的自由名称，不自动合并相似名称；
- 价格是参考信息，不承诺当前成交价；
- 评价只有在审核通过且绑定到明确食堂、窗口、档口和菜品后公开；
- 评价姓名按来源允许的展示值呈现，不增加虚构身份前缀；
- 目录更新不得静默覆盖已经发布的人工校正。

## 内容运营

内容维护人员通过 Ops Web 处理来源观测、目录草稿、发布版本和评价治理：

- 来源同步后人工重建草稿，并保留仍然有效的人工校正；
- 发布前查看完整校验结果，校验失败时不能发布；
- 发布创建不可变版本，回滚也创建新版本，不修改历史记录；
- 查看评价的审核和绑定状态，并执行隐藏、恢复、重新绑定或复检；
- 始终能区分来源记录、当前草稿、已发布内容和学生端可见状态。

内容运营不能直接编辑已发布快照，也不能绕过地图兼容、目录完整性或评价公开条件。页面入口、
权限体验和通用错误要求见 `ops-web.md`。

## 非目标

当前不承诺实时营业状态、排队、库存、份量规格、实时售价、窗口备注或推荐排序。Dining 也不提供
模型可见工具或让在线请求直接访问 Feishu/Lark。

## 验收

- 用户能完成食堂切换、档口定位、菜品查看、搜索和评价阅读；
- 键盘、触控和缩放操作不会遮挡主要内容，选择变化不会造成布局跳动；
- 发布版本变化后页面更新目录，只有评价修订变化时不重置目录选择；
- 不可用地图、空评价和接口错误分别显示对应状态，且不影响仍可使用的区域；
- 未审核、已隐藏或绑定不完整的评价不会出现在学生端。
- 来源同步不会自动发布；内容维护人员可以完成草稿校验、发布、回滚和评价治理。

架构、字段和操作分别见 `../architecture/domains/dining.md`、`../data/dining.md` 和
`../runbooks/dining.md`。
