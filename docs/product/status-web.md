# 产品可用性状态页

## 边界

本文定义公众如何理解 Campus Agent 产品入口的当前可用性和近期历史。状态页不承载班车、食堂营业
等校园业务状态，也不展示内部组件、数据库、工作流或观测平台健康。

精确服务 ID、顺序、状态枚举和快照字段由
`packages/contracts/schemas/product-availability-snapshot.v1.schema.json` 维护；探测输入、缓存、
过期时间和环境配置由 Worker 实现与环境仓维护。

## 用户目标

- 无需登录即可确认校园问答和其他学生服务当前是否可用；
- 查看每项服务过去 30 天的按日状态；
- 在状态数据过期或刷新失败时区分产品故障与监控数据不可用；
- 从状态页返回 Campus 产品的公开入口。

## 服务与状态

页面标题后直接展示“校园问答”和“其他服务”两个服务行，不增加内部组件、分组、服务计数或常态
整体汇总。每行包含当前状态、最近检查时间和 30 天时间线。

服务状态只使用公共快照合同定义的值。历史中没有记录的日期显示为“无历史数据”，不能伪装成
`unknown`；只有探测明确得到未知结果或快照已经过期时，当前状态才显示为未知。日期和页面时间
统一按北京时间展示。

第一版不建立 incident、维护窗口、通知、订阅或管理后台。新增公共服务必须先扩展产品信息架构和
公共快照合同，不能根据域名或内部组件自动生成服务行。

## 新鲜度与失败

页面按固定间隔自动读取同源快照，常态不提供手动刷新按钮：

- 首次读取期间显示与服务行结构一致的静态骨架；
- 首次读取失败时保留骨架和明确错误，等待下一次自动读取；
- 已有快照后刷新失败时保留最近结果，并说明当前无法更新；
- 快照过期后保留历史时间线，但当前状态统一显示为未知；
- 正常快照不重复展示全局更新时间，异常时可以显示最近成功更新时间。

刷新失败、快照过期和服务自身故障必须保持不同语义，不能互相改写。

## 时间线交互

所有 viewport 使用同一组 30 天数据并完整显示时间线，不依赖页面级横向滚动。每项服务以一个复合
slider 作为键盘停靠点；方向键逐日移动，`Home` 和 `End` 选择首尾日期，指针或触摸选择最近日期。
日期结果由共享提示层展示，时间线视觉条不单独进入 Tab 顺序。

状态不能只依赖颜色。正常、受影响、中断、未知和无历史数据同时使用填充、空隙或边框线型区分，
forced-colors 下继续可识别。页面只播报首次成功、状态变化、过期、失败和恢复，不播报自动刷新的
相对时间或用户浏览时间线的每一步。

禁用 JavaScript 时，在服务列表中显示启用要求，不能把加载骨架伪装成状态结果。

## 导航与隐私

状态页是匿名公共面，不读取账号、session 或 App API 用户接口。桌面和移动导航与 Campus 产品顺序
一致，通过固定公开入口返回问答、文档、通知、地图、食堂、同好群和反馈。重定向不接受任意外部
目标，也不会创建额外服务身份。

页面不展示环境标签、探测地址、用户问题、内部请求标识、原始响应、日志或模型 trace。

## 验收

- 两个服务行的当前状态、最近检查和 30 天历史与公共快照一致；
- 无历史、未知、过期、首次失败和刷新失败分别呈现；
- 320px 起无页面横向溢出，桌面和移动端使用同一语义数据；
- 键盘、触控、焦点、提示层、live region、forced-colors 和 reduced-motion 行为可用；
- 页面匿名读取同源快照，导航只前往登记的 Campus 入口；
- 页面不存在 incident、维护、订阅、环境徽标或内部组件健康。
