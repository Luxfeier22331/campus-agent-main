# Ops Web 产品需求

## 文档边界

本文定义 Ops Web 的操作者任务、页面体验、权限表现和验收要求。系统职责见
`../architecture/system/ops-observability.md`，HTTP 语义见 `../contracts/ops-web/README.md`，Dining
内容规则见 `dining.md`。本文不固定组件库、数据库结构、供应商配置或部署参数。
共同的信息层级、状态、响应式和无障碍底线由 [ui.md](./ui.md) 维护。

## 产品定位

Ops Web 是受访问保护的运维和内容运营界面，面向值班人员、运行服务负责人和内容维护人员。
它帮助操作者判断系统状态、查看单次产品运行并完成少量明确准入的管理操作；只有发现异常后，
操作者才进入排障流程。Ops Web 不替代 Temporal、Langfuse、Sentry、Axiom 等平台的完整界面。

浏览器只能获得完成当前任务所需的有界数据，不获得数据库、观测平台、密钥存储或下游管理
凭据。

## 操作者任务

### 查看运行概况

操作者可以选择预设时间范围，查看请求量、成功情况、耗时趋势、关键服务、Temporal 队列和
已配置观测信号的状态。

不同数据来源独立显示结果。无数据、查询失败、部分响应和使用旧缓存必须呈现为不同状态；单个
来源失败不能抹掉其他可用结果，也不能改写产品请求状态。

整体状态只回答产品请求、执行队列和已配置服务是否可用；Axiom 观测覆盖单独展示，不把“暂时查
不到日志”表述成产品故障。页面只在“当前问题”区域汇总可操作根因，整体状态和状态表不重复同一
错误说明。没有配置探针或外部 HTTPS 入口时隐藏对应项目，不以未知故障或空链接占位。

### 查看运行记录

运行记录表示一次已准入的产品请求及其有界执行投影。它不是完整对话、Langfuse Trace、Temporal
Workflow Execution 或 Sentry Issue。操作者可以按时间、状态、关键词和已知关联标识查找记录，
使用可分享的 URL 保留筛选条件，并通过游标继续浏览结果。

列表必须把“最近运行”和“需要关注”作为明确视图，而不是用隐藏排序混合两种任务：

- “最近运行”按开始时间倒序，供操作者还原刚刚发生的用户请求；
- “需要关注”只聚合终态缺少会话结果、失败和等待用户的记录，并在该视图内按可操作性排序；
- 运行中、已完成和已取消继续作为状态筛选，不把正常活动记录默认为异常。

“最近运行”和“需要关注”都以发起时间、截断问题预览、产品处理路径、产品状态、Agent token
总量和一次总耗时为主。“需要关注”另外明确显示产品失败、等待用户或终态缺少会话结果。终态缺少
结果是数据完整性异常，不能把产品状态改写成失败，也不能伪装成普通空结果。

产品处理路径只表达用户可理解的产品节点，例如“Campus Web → 在线问答 Agent → 查询班车时刻 →
回答已写入会话”。同一能力的内部调用和重试合并为一个业务动作；memory、finalization、原始 step、
attempt 和工具 ID 不进入默认路径。没有业务能力调用时表达为 Agent 直接处理，不制造工具步骤。
业务动作投影查询失败时必须显示“记录不可用”，不能以空数组冒充“未调用业务能力”；
同样，Agent 用量投影查询失败时显示用量不可用，不影响请求和会话结果的展示。

Agent token 只表示主 Agent run 已上报的 input、output 和 cached input token，不代表 Hindsight、
Embedding 或其他组件的全链路总量。列表只显示 total token，详情显示 input、cached input、output 和
total；cached input 是 input 子集，不重复加入 total。运行中的数字是服务端 `generatedAt` 时刻的快照；
终态只有部分用量时用独立说明表达，不把“进行中”或“部分”拼进数字。

详情页默认使用单页连续结构展示本轮完整用户问题、入口和轮次、产品处理路径、已经写入会话的完整
产品回答、Campus Web 实际展示的来源、一次总耗时和 token 明细。非终态没有助手消息是正常等待；
产品终态缺少对应助手消息时明确显示数据完整性异常。页面只能表述“回答已写入会话”，没有浏览器
确认事实时不能声称用户已经收到。

“系统记录”是独立次级页面，列出关联标识、技术错误、运行版本、Langfuse、Temporal 等外部入口，
并按来源加载 Sentry、应用日志和调用链。完整 Generation、Agent Graph、模型输入输出、成本、评分、
Temporal history 和原始执行步骤继续由所属平台展示，Ops Web 不重建第二套 Trace tree 或工作流历史。

详情不根据运行状态或外部记录推断根因、结论或建议操作。模型、访问控制、关联标识和原始时间等
技术字段不与用户结果争夺首屏层级。

错误、应用日志和调用链按来源加载。操作者点击某一来源的加载按钮后，只查询该来源；各来源可
独立刷新，未加载时不触发外部查询。页面按来源的真实对象命名内容，不把这些关联记录统一描述成
已经形成结论的“诊断证据”。

页面支持复制关联标识。外部观测数据只提供分析线索；失败、无记录或部分响应不能改变运行记录的
持久状态。需要查看完整模型输入输出、工作流历史、错误事件或任意日志查询时，操作者进入所属
外部平台。

### 维护模型配置

页面维护在线问答当前使用的模型能力，不使用角色、连接版本或发布记录表达模型用途。

在线问答分别展示 LLM 和 Embedding。LLM 可以维护服务商、Base URL、API key、model 和 transport；
Embedding 明确展示固定模型、维度和 transport，只开放实际可变的连接字段。保存前
必须完成真实供应商验证，失败不能覆盖当前配置。并发变化使用隐藏 ETag 阻止覆盖，页面不把 ETag
展示成产品版本。

页面直接展示 Base URL、模型和 API key，将服务商和接口类型收纳到高级设置。固定参数使用
只读摘要，不表现为禁用输入。保存按钮只在存在修改时启用；重新验证只验证已保存配置。切换页签或
离开页面会确认是否放弃未保存修改。Hindsight 配置由环境仓维护，不进入本页面。

所有 API key 输入在成功后清空，服务端后续只返回是否配置和末四位。服务身份不能进入 Ops Web。

### 管理账号

账号准入页面维护非校园邮箱的逐地址邀请和非 production 测试授权；校园邮箱不创建授权。用户管理
页面查询账号状态、访问来源和有效会话，并进入详情发送验证或重置邮件、签发一次性显示的临时密码、
封禁或恢复账号、撤销会话。账号操作记录和注销任务使用独立页面，保留筛选和游标位置。

页面不提供创建用户、模拟登录、直接删除用户、修改角色或手工标记邮箱已验证。账号后端不可用只
影响这些页面，不影响运行记录和内容运营。

### 维护内部门户 TGC

操作者可以查看固定 TGC 的更新时间、认证 CronJob 最近调度时间、最近一次成功使用时间和最近任务
状态，并替换原始 TGC。页面不显示当前值、摘要或末尾字符，不预测过期时间，也不把一次历史成功
表述为当前仍有效。

替换成功后页面清空输入，并显示当前值尚无更新后的成功记录；现有 30 分钟 CronJob 后续成功时才
更新该状态。页面不提供即时执行、通知同步、文件发布提交、任意 Secret 选择或 Kubernetes 管理。

### 维护食堂内容

内容维护人员可以编辑全部食堂地图、保存完整草稿、发布不可变版本并恢复历史版本。页面明确
区分画布未保存修改、数据库草稿和当前学生端版本。独立任务页用于维护即时生效的菜单、查看和
处理评价、处理举报；不提供采集、来源同步、预览、导入导出或开发 Seed 操作。具体规则和验收由
`dining.md` 维护。

### 维护同好群目录

内容维护人员可以增删、重命名和排序分组，也可以新增、修改、删除、排序或跨组移动群。每次操作
提交完整目录，成功后立即改变学生端读取的数据。页面不提供 Wiki 导入、来源同步、草稿、发布、
历史版本、操作记录或回滚。

## 信息结构

一级导航包含：

- 运行概览；
- 运行记录；
- 模型配置；
- 内部门户；
- 账号准入；
- 用户管理；
- 账号操作记录；
- 注销任务；
- 食堂；
- 同好群。

运行详情默认提供连续的请求旅途，并从独立“系统记录”页面进入技术信息。Ops Web 不提供通用日志
搜索、数据库浏览、任意外部查询或工作流控制台。

## 交互要求

- 桌面端使用语义表格支持高密度扫描；移动端将运行记录转换为按任务排序的纵向列表；
- 搜索保持可见，状态、时间和精确 ID 在桌面形成统一工具栏，在移动端进入筛选 Sheet；
- “最近运行”和“需要关注”是可分享 URL 的路由导航，不使用同页 Tabs 语义；
- 同一规范化查询刷新时可以保留当前结果；游标翻页读取期间可以保留当前页。视图或筛选改变时不得
  展示上一查询的结果；失败不能伪装为空数据。
- 输入无效、权限不足、依赖不可用、并发冲突和操作成功使用不同反馈。
- 其余表单、焦点、状态和响应式要求遵守 [ui.md](./ui.md)。

## 数据与权限体验

- 页面不展示完整用户身份、整段会话、原始提示词、供应商原始响应、记忆正文或检索正文；运行详情
  可以展示该轮已经由 app-api 净化并写入会话的完整用户问题、产品回答和产品化来源。
- Cloudflare Access policy 决定获准人员，Ops Web 不维护按页面或操作拆分的第二套人员名单。
- 写操作必须执行同源和所属领域的输入或资源边界校验。
- 页面不能让浏览器选择任意查询语言、数据集、组织、项目、时间范围、字段投影或返回上限。
- 管理依赖不可用只影响对应页面，不应使仍可使用的运行记录页面失效。

## 非目标

- 修改、重跑或取消产品请求和工作流；
- 复制外部观测、工作流或评测平台的完整功能；
- 提供任意 SQL、日志查询、外部 API 代理或通用 Secret 管理；
- 镜像外部平台正文、模型 trace、评测数据集或人工标注状态；
- 在线登录学校门户或编辑任意 Temporal Schedule；
- 承担学生产品 API 或拆出没有独立所有权的第二个运维后端。

## 验收

- 所有一级页面、请求旅途和独立系统记录页面均可从导航到达并正确恢复 URL 状态。
- 运行概况分别展示请求、服务、Temporal 队列和已配置观测信号。
- “最近运行”保持时间倒序，“需要关注”聚合失败、等待用户和终态缺少会话结果；状态计数筛选、固定每页 50 条的
  向前游标翻页、空状态、刷新失败和关联标识复制可用。
- 运行详情展示完整问题、产品处理路径、完整会话结果、用户可见来源、一次总耗时和 token；系统记录
  独立按需加载外部来源，页面不生成根因、结论或建议操作。
- 列表和详情不显示步骤数、模型请求数、工具调用数、重试数或原始工具 ID；完整、部分、运行中和
  不可用的 Agent token 用量保持真实可区分。
- 无数据、来源失败、部分响应、旧缓存和权限不足均有可区分的反馈。
- 获准人员可以保存并验证在线问答模型设置，以及完成食堂地图、菜单、评价、举报和同好群目录
  增删改的对应操作；其他身份只能
  看到其权限允许的内容。
- 获准人员可以维护邮箱准入、查询用户、执行固定账号操作并重试需要处理的注销任务；临时密码不
  进入 URL、浏览器存储或查询缓存。
- 获准人员可以替换固定 TGC 并查看定期认证状态，页面和接口均不返回凭据内容或扩展到其他
  Kubernetes 资源。
- 同好群页面可以维护分组与群的展示顺序，且不出现 Wiki 导入、草稿、发布、历史版本或回滚入口。
- 浏览器不能获得服务端凭据或扩展服务端固定的数据访问范围。
- 所有接口错误保留错误状态，不改写为成功空数据或未说明的部分成功。
- 键盘、移动端和桌面端布局满足本文交互要求。
