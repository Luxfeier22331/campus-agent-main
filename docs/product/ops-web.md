# Ops Web 产品需求

## 边界

本文定义 Ops Web 的操作者任务、页面体验、权限表现和验收要求。HTTP 语义见
`../contracts/ops-web/README.md`，运行信号边界见 `../reference/telemetry.md`，Dining 内容规则见
`dining.md`。本文不固定组件库、数据库结构、供应商配置或部署参数。
共同的信息层级、状态、响应式和无障碍底线由 [ui.md](./ui.md) 维护。

Ops Web 不替代 Temporal、Langfuse、Sentry、Axiom 的完整平台界面，也不是数据库浏览器、通用
Secret 管理器或任意工作流控制台。

## 查看运行概况

操作者可以查看产品请求量、结果和耗时趋势，并进入已配置的外部平台。整体状态只依据持久产品请求
投影，不把日志、trace、队列、探针或 Collector 状态改写成产品健康。

无数据、读取失败、部分结果、旧缓存和正常结果必须保持不同状态。单个数据来源不可用时，其他区域
继续展示自身结果；没有配置的外部入口直接隐藏，不显示空链接或虚构故障。

## 查看运行记录

运行记录表示一次已准入产品请求及其有界执行投影，不是完整对话、Temporal history、Langfuse trace
或 Sentry Issue。

操作者可以：

- 查看按时间倒序的最近运行；
- 查看失败、等待用户或终态缺少会话结果等需要关注的运行；
- 按时间、状态、关键词和已知关联标识筛选，并通过 URL 保留查询；
- 查看完整用户问题、产品结果、公开来源、阶段耗时、有限 Agent 用量和安全关联标识；
- 按需加载固定范围的应用日志或 Sentry Issue；
- 进入已配置的 Temporal、Langfuse、Sentry 或 Axiom 平台查看完整信息。

运行详情先展示用户结果，再提供独立的系统记录区域。页面不能根据外部记录推断根因、自动生成结论，
也不能用日志或 trace 改写持久产品状态。未加载的外部来源不自动查询；失败、无记录和部分响应分别
呈现。

## 维护在线模型配置

操作者可以维护在线问答实际使用的 LLM、Embedding 连接，以及通知分类 Job 使用的独立文本模型连接。
界面只显示真实可变字段，固定能力使用只读摘要，不伪装成禁用输入。

保存前必须使用当前候选配置完成真实供应商验证；验证失败不能覆盖已保存配置。保存成功后通过数据库
事务串行写入，并覆盖该 kind 的当前设置。API key 成功提交后从输入中清除，后续只显示是否已配置和
安全摘要；服务身份或完整密钥不能返回浏览器。

LLM 和通知分类页面分别编辑 provider、Base URL、API key、model 和 transport，不互相复用当前设置。
Embedding 页面只编辑 Base URL 和 API key，并只读展示固定 provider、model、transport 和 dimensions。
Embedding 保存和验证不依赖 Campus Docs 当前索引；页面不展示或编辑 `embedding_space_id`、collection
或制品 ID。

## 维护内部门户凭据

协作者可以保存多条具名门户 TGC，查看最近检查结果，立即检查、重命名、轮换、删除，并在开发需要时
显式显示当前值。系统不设置主凭据；运行采集时由 ingestion-control 依次验证候选并返回第一条可用
记录，source-collector 不按名称选择或直接读取凭据数据库。

新增和轮换必须先完成真实门户验证；失败不能创建记录或覆盖旧值。列表不显示明文，显示操作只能在
当前对话框中短暂呈现，关闭后从页面状态清除，不进入 URL、浏览器存储、查询缓存或日志。

操作者还可以创建和撤销具名自动化 token，供独立机器入口按合同维护凭据。自动化入口不创建 Ops Web
用户或角色，也不成为通用代理或凭据同步总线。

## 管理账号

账号页面维护非校园邮箱准入、用户状态和会话。获准操作包括发送验证或重置邮件、签发一次性临时
密码、封禁或恢复账号、撤销会话以及查看账号操作记录。

异步注销期间只读展示 App API 的清理状态。Ops Web 不提供直接删除账号、跳过清理、模拟登录、修改
角色、人工标记邮箱已验证或全局注销队列。

账号后端不可用只影响账号区域，不阻止运行记录和内容运营。

## 内容运营

- 食堂页面编辑完整地图草稿、发布不可变版本、恢复历史版本，并维护菜单、评价和举报；完整规则见
  [dining.md](./dining.md)。
- 同好群页面维护分组、群条目和展示顺序；提交成功后立即改变学生端目录，不建立未要求的草稿、
  历史版本或导入系统。

## 访问与交互

所有 API key 输入在成功后清空，服务端后续只返回是否已配置。服务身份不能进入 Ops Web。

### 内部门户凭据交互细则

协作者可以保存多条具名 `SSO_TGC`，查看最近检查结果，立即检查、重命名、轮换、删除，并在开发
需要时显示和复制某条记录的当前明文。Ops Web 通过 ingestion-control 完成这些操作，不持有 TGC
数据库表或门户验证实现。系统不设置主凭据，不按环境、用途或人员再拆状态，也不让
source-collector 按名称选择记录。采集消费者通过内部接口按检查状态逐条验证候选，页面不保存当前
选中项。

新增和轮换必须先建立真实 CAS 与门户会话。失败不得创建记录或覆盖旧值；CAS 刷新 TGC 时保存刷新
后的值。后台每 30 分钟顺序检查未暂停的记录，区分凭据被拒绝与检查依赖失败，旧检查不得覆盖检查
期间完成的轮换。凭据被明确拒绝后暂停定时检查，轮换或人工检查成功后恢复；依赖检查失败在下一
周期继续检查。该检查不保证延长 TGC 生命周期。

列表不显示明文。明文读取必须由操作者在对话框中显式触发，关闭后从页面内存清除，不进入 URL、
浏览器存储、查询缓存或日志。凭据保存在 ingestion-control PostgreSQL；普通 Pod 更新不会丢失，完整环境或
数据库重置后需要重新录入。

页面同时展示开发者自动化访问区域：操作者可以生成多条具名 token，复制机器端点和 token，重复查看
明文，或撤销 token。机器程序使用 `Authorization: Bearer` 调用独立端点创建、更新或删除凭据；一个有效
token 默认管理全部具名凭据。该区域不创建 Ops Web 用户、角色或 Cloudflare Access Service Auth，
也不让 source-collector 读取数据库；采集解析复用既有 `OPS_WEB_INTERNAL_TOKEN`，不使用这些
automation token。

### 账号管理交互细则

账号准入页面维护非校园邮箱的逐地址邀请和非 production 测试授权；校园邮箱不创建授权。用户管理
页面查询账号状态、访问来源和有效会话，并进入详情发送验证或重置邮件、签发一次性显示的临时密码、
封禁或恢复账号、撤销会话。账号操作记录使用独立页面并保留筛选和游标位置。

用户详情在注销进行中时只读展示 App API 的异步清理进度。系统先清理个人记忆和关联数据，最后
删除认证账号；重试由 App API 后台状态机自动推进。Ops Web 不提供全局注销队列、人工重试、跳过
清理、直接删除账号或恢复登录。

页面不提供创建用户、模拟登录、直接删除用户、修改角色或手工标记邮箱已验证。账号后端不可用只
影响这些页面，不影响运行记录和内容运营。

### 维护食堂内容

内容维护人员可以编辑全部食堂地图、保存完整草稿、发布不可变版本并恢复历史版本。页面明确
区分画布未保存修改、数据库草稿和当前学生端版本。独立任务页用于维护即时生效的菜单、查看和
处理评价、处理举报；不提供采集、来源同步、预览、导入导出或开发 Seed 操作。具体规则和验收由
`dining.md` 维护。

### 维护同好群目录

内容维护人员可以增删、重命名和排序分组，也可以新增、修改、删除、排序或跨组移动群。每次操作
提交完整目录，成功后立即改变学生端读取的数据。页面不提供 Wiki 导入、来源同步、草稿、发布、
历史版本、操作记录或回滚。

## 信息结构

一级导航包含：

- 运行概览；
- 运行记录；
- 模型配置；
- 内部门户凭据；
- 账号准入；
- 用户管理；
- 账号操作记录；
- 食堂；
- 同好群。

运行详情默认提供连续的请求旅途，并从独立“系统记录”页面进入技术信息。Ops Web 不提供通用日志
搜索、数据库浏览、任意外部查询或工作流控制台。

## 交互要求

- 桌面端使用语义表格支持高密度扫描；移动端将运行记录转换为按任务排序的纵向列表；
- 搜索保持可见，状态、时间和精确 ID 在桌面形成统一工具栏，在移动端进入筛选 Sheet；
- “最近运行”和“需要关注”是可分享 URL 的路由导航，不使用同页 Tabs 语义；
- 同一规范化查询刷新时可以保留当前结果；游标翻页读取期间可以保留当前页。视图或筛选改变时不得
  展示上一查询的结果；失败不能伪装为空数据。
- 输入无效、权限不足、依赖不可用、并发冲突和操作成功使用不同反馈。
- 其余表单、焦点、状态和响应式要求遵守 [ui.md](./ui.md)。

## 数据与权限体验

- 页面不展示完整用户身份、整段会话、原始提示词、供应商原始响应、记忆正文或检索正文；运行详情
  可以展示该轮已经由 app-api 净化并写入会话的完整用户问题、产品回答和产品化来源。内部门户
  TGC 只在操作者明确打开的明文对话框中显示。
- Cloudflare Access policy 决定获准人员，Ops Web 不维护按页面或操作拆分的第二套人员名单。
- 写操作必须执行同源和所属领域的输入或资源边界校验。
- 页面不能让浏览器选择任意查询语言、数据集、组织、项目、时间范围、字段投影或返回上限。
- 管理依赖不可用只影响对应页面，不应使仍可使用的运行记录页面失效。

## 非目标

- 浏览器提交任意查询语言、数据集、外部 URL、时间范围或返回上限；
- 重建 Temporal history、Langfuse trace tree、Sentry 事件或通用日志搜索；
- 创建、读取或修改 Kubernetes Secret、workload、Schedule 或任意 Workflow；
- 根据观测平台结果改变产品请求、账号或内容状态；
- 为每种管理能力建立独立角色系统、审批流或恢复状态。

## 验收

- 概览和运行记录保持产品状态与外部诊断状态分离；
- 外部平台按需、独立加载，失败不影响其他产品区域；
- 模型配置验证和 Secret 清理符合合同；
- TGC 只在明确显示动作中短暂进入页面，自动化 token 可以独立撤销；
- 账号、Dining 和同好群操作遵守各自所有者合同；
- 320px 起可完成核心任务，键盘、焦点、错误和权限状态可理解；
- 浏览器不能获得数据库、供应商、内部服务或部署凭据。
