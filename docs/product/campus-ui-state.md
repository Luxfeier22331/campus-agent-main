# Campus Web 用户可见状态治理

## 目标

Campus Web 的状态只表达用户需要判断的事实：当前任务是否还在进行、已有内容是否仍然可用、发生了什么，以及下一步可以做什么。

后台实现过程、Worker、索引、bootstrap、动态 import、原始工具参数、JSON 结果、request id 和内部异常不属于学生界面。

## 状态分类

| 状态 | 默认呈现 | 已有内容 | 恢复动作 |
| --- | --- | --- | --- |
| 初次加载 | 与最终页面形状一致的骨架 | 无 | 等待 |
| 刷新中 | 保留原内容，提供轻量反馈 | 保留 | 自动完成 |
| 空数据 | 明确对象和原因 | 不适用 | 调整筛选或创建 |
| 不存在 | 页面说明和返回入口 | 不适用 | 返回上级 |
| 失败 | 影响范围和就近操作 | 能保留则保留 | 仅在可重试时重试 |
| 暂时不可用 | 依赖不可用的说明 | 保留其他区域 | 局部重试 |
| 降级 | 缺少的能力和仍可使用的路径 | 必须保留 | 局部恢复 |
| 操作反馈 | 行内短反馈 | 保留 | 用户继续操作 |

成功状态通常由结果内容本身表达，不额外显示通用成功卡片。

## 展示层级

Campus Web 使用以下布局语义：

- `skeleton`：页面或区域初次加载，只模拟最终内容形状；
- `inline`：输入、按钮或列表行附近的短反馈；
- `section`：区域级空、失败和不可用状态，默认使用留白、标题和分隔线，不嵌套 Card；
- `page`：路由级错误、404 和整页依赖失败；
- `overlay`：地图、画布等局部覆盖层。

状态组件不得因为状态类型自动变成 Card。Card 只用于独立对象、对话框内容或确实需要边界的工具。

## 问答

运行中的问答只显示一行“正在回答”。后端 `queued`、执行阶段、时间和步骤是运行事实，不注册为用户可见阶段。

- 首个 `answer.delta` 到达前不创建空的 assistant 消息；
- 连接中断显示“连接已断开”，已接受的运行保留为活动运行，不自动发起第二个请求；
- 浏览器刷新或重新进入会根据 `activeRequestId` 和持久化事件恢复一次，已结束的运行直接读取规范会话内容；
- 失败通过回答错误消息表达，完成由回答内容本身表达；
- 用户消息和正常回答使用中性内容样式，聊天强调色只用于发送、当前会话等壳层交互。

工具和推理区域只显示用户可理解的摘要。生产界面不展示原始工具名、参数、JSON、chain-of-thought 或原始异常对象。

## 搜索

搜索索引、Web Worker、客户端建立索引和防抖属于实现细节。普通搜索不显示“正在载入搜索索引”“正在载入搜索”或“正在搜索”。

输入新查询时保留上一组结果，直到新结果到达。首次打开搜索面板可以显示输入框形状骨架；用户主动点击“继续显示”时可以显示按钮级进度。

搜索失败只影响搜索区域并提供局部重试，不要求刷新整个页面。

## 错误恢复

恢复范围必须与失败资源一致：

- 通知不存在返回通知目录；暂时请求失败才提供重试；正文异常不阻断附件和门户入口；
- 地图底图失败保留地点列表；地图数据失败只重试地图数据；
- 食堂平面图、菜单和评价各自独立恢复；
- 会话服务不可用不显示为聊天记录骨架；
- 页面级错误不得通过 `window.location.reload()` 作为默认恢复方式。

只有 React 根节点或文档应用初始化发生未捕获崩溃时，才可以把整页重新打开作为最后恢复手段；普通路由加载和依赖失败必须留在所属页面或区域内重试。

## 无障碍

- 初次骨架使用 `aria-busy` 和简短区域标签；
- `role="status"` 只用于需要播报的短状态；
- `role="alert"` 只用于需要立即注意的错误；
- 不把整个动态结果列表包在 `aria-live`；
- 不播报每秒计时、搜索输入变化或内部索引生命周期；
- 问答只播报开始、完成、失败、断线和恢复等重要转折。

## 变更规则

新增用户可见状态前，所属领域必须明确：状态事实来源、影响范围、展示层级、文案、恢复动作和无障碍播报。

状态注册表位于 `apps/campus-web/src/features/ui-state/state-policy.ts`；页面和领域组件负责把自身合同状态映射到该策略，不在共享 `packages/ui` 中加入 Campus 业务枚举或中文文案。

组件展示入口的职责、边界和本地评审方式见 [Campus Web README](../../apps/campus-web/README.md)。
