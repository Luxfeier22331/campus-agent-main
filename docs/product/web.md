# Campus Web 体验要求

## 边界

本文定义 Campus Web 学生端及 `/docs/*` 阅读面的跨页面体验、响应式、无障碍、状态和性能要求。
Dining、地图、问答、文档和账号的领域行为由各自产品或领域文档维护；组件路径、样式 Token、第三方
库和验证命令由 `apps/campus-web/README.md` 与代码维护。

## 体验原则

### 任务优先

- 第一屏直接承载查询、阅读、选择或提交任务，不以营销内容和功能介绍占据主要区域；
- 优先展示完成任务所需的信息，再渐进展示次要内容；
- 用户无需理解内部 API、schema、供应商和发布标识。

### 清晰稳定

- 信息层级明确，避免卡片堆叠、重阴影、过度圆角和无意义装饰；
- 一个视图只有一个主要交互重点，次要操作不抢占视觉权重；
- 异步内容预留稳定空间，读取、成功和错误状态切换时避免明显布局跳动。

### 产品连续

- 问答、文档、地图、食堂、反馈和账号使用一致的导航标签、顺序、选中状态和返回目标；
- 各入口可以采用适合任务的布局，但不建立另一套颜色、导航或控件行为；
- 来源卡片、搜索结果和详情页应提供连续、可返回的浏览路径。

### 移动端完整

- 移动端保留核心浏览、选择、提交、重试、关闭和返回能力；
- 页面支持 `320px` CSS viewport 重排，核心任务不依赖整页横向滚动；
- 主要触控操作和图标按钮提供至少 `44px` 的触控区域。

## 视觉与布局

- 普通页面使用克制的颜色、边框、阴影和圆角，品牌色、交互色、成功色与危险色语义明确；
- 不使用渐变、发光、装饰性模糊色块或嵌套卡片制造层级；
- 阅读任务限制正文行长，表单任务保持聚焦，扫描比较任务提供稳定工作区，地图等沉浸任务不套
  装饰性页面容器；
- 页面标题、正文、标签和状态文案允许换行，动态内容不得覆盖相邻控件；
- 字号不随 viewport 连续缩放，固定格式元素保留稳定尺寸。

## 导航与状态

- 移动端导航可以由键盘和触控打开、选择和关闭，关闭后焦点返回触发位置；
- 延迟加载的账号和导航内容必须保留稳定空间；
- 明确区分读取中、空内容、错误、局部降级、成功和不可操作状态；
- 空内容只表示成功读取后的空集合，读取失败不能显示成空内容；
- 局部依赖失败时保留仍可使用的主体验，并在受影响区域提供恢复动作；
- 表单错误靠近对应字段，提交结果和异步状态能够被辅助技术感知。

## 无障碍与输入

- 目标基线为 WCAG 2.2 A/AA；
- 所有交互具有可访问名称、正确状态、可见焦点和逻辑焦点顺序；
- 核心任务可以只用键盘完成，不产生键盘陷阱；
- 对话框和菜单关闭后恢复焦点，动态结果避免重复播报；
- 颜色不是状态或选择的唯一表达；
- 内容支持文本放大、`320px` 重排和 reduced motion；
- 使用可访问组件不能替代完整用户旅途验证。

## 动效

- 动效只用于解释状态、空间关系和操作反馈，不加入纯装饰动画；
- 优先改变 `transform` 和 `opacity`，避免触发布局抖动；
- reduced motion 下移除非必要移动，并避免同时展示多个高关注动画。

## 内容

- 默认使用直接、具体的中文，标题描述对象或任务；
- 不向普通用户展示 release ID、request ID、schema version、来源内部记录或供应商字段；
- 时间和版本只在用户需要判断时效或有效性时展示；
- 错误说明发生了什么，并在可恢复时提供重试、返回或反馈入口；
- 成功文案确认结果即可，不展示用户无法使用的内部回执。

## 性能

- 首屏不得因可并行请求、重复会话读取或非关键依赖形成请求瀑布；
- 已获得的集合项尽早展示，不等待非关键内容完成；
- 路由代码、非关键账号状态、地图运行时和评价内容按用户意图加载或预取；
- 生产 Web Vitals 以第 75 百分位衡量，目标为 `LCP <= 2.5s`、`INP <= 200ms`、
  `CLS <= 0.1`；
- 视觉修改不得以放宽现有 bundle budget 作为解决方案。

## 验收

- 桌面、平板、移动端和 `320px` 重排下无文本遮挡、失控横向滚动或不可达操作；
- 读取、空内容、错误、局部降级和成功状态与实际数据一致；
- 键盘、焦点恢复、可访问名称、状态播报和 reduced motion 已验证；
- 自动化无障碍检查没有未解释的 A/AA 问题，核心旅途完成真实浏览器检查；
- 受影响的类型检查、组件测试、构建预算和浏览器测试通过；
- 视觉调整不改变所属领域的接口和业务语义。
