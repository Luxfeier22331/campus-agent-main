# Campus Web 体验要求

## 边界

本文定义 Campus Web 学生端及 `/docs/*` 阅读面的产品连续性和性能要求。仓库共同的信息层级、
响应式、状态和无障碍要求由 [ui.md](./ui.md) 维护；Dining、地图、问答、文档和账号的领域行为由
各自产品或领域文档维护。组件路径、样式 Token、第三方库和验证命令由应用 README 与代码维护。

## Campus Web 连续性

- 问答、文档、通知、地图、食堂、同好群、反馈和账号使用一致的导航标签、顺序、选中状态和返回目标；
- 普通页面使用共同产品栏，问答和文档使用带领域工具的工作区产品栏，地图使用不遮挡主要画布的
  沉浸浮动产品栏；账号与法律页面只保留品牌返回和外观设置，不展示完整产品导航；
- 桌面产品导航使用文字标签，移动产品菜单使用图标和文字。文档目录、聊天记录、搜索和本页目录
  保持各自的领域入口，不能再次承载产品导航或主题设置；
- 来源、搜索结果和详情页提供连续且可返回的浏览路径；
- 通知目录的关键词、业务分类和发布日期筛选保存在 URL；来源、发布部门和门户栏目作为列表元数据展示，
  不提供用户侧筛选；站内通知进入产品详情，
  外链通知按 URL 显示微信公众号、采购平台、校内网站、媒体或具体站点来源，并在新标签页打开来源页面；
- 通知详情展示清洗后的正文和图片，附件 metadata 提供门户原生链接，附件字节不经过 App API；正文
  为空、格式异常或读取失败必须分别呈现；
  详情加载成功后提供需要门户 SSO 的原文入口，并在新标签页打开；
- 反馈：页面内反馈面板在打开时记录当前页面路由（pathname + search）作为 `routeContext`，
  面板存续期间不改写；独立反馈页（`/feedback`）沿用首次进入时记录的来源（`?source=…`）。
  界面展示来源标签，提交时保留记录的 `routeContext`；
  登录用户默认勾选"匿名提交"（不带联系方式），取消勾选后展示预填账号邮箱的可编辑联系方式框
  （校园邮箱仅作身份验证方式，联系方式可改成其他邮箱或留空）；
  匿名访客保留可选的手填联系方式；
- 阅读任务限制正文行长，表单任务保持聚焦，地图等沉浸任务不套装饰性页面容器；
- 普通学生界面不展示 release ID、request ID、schema version、供应商或来源内部记录；
- 问答、文档阅读、地图和账号可以使用所属领域的成熟组件，但不能建立第二套产品导航或改写共同
  状态语义；
- 延迟加载的账号、导航、地图和问答内容预留稳定空间，避免切换状态时明显跳动。

## 问答工作区布局

- 问答工作区 TopNav 和聊天记录侧栏 Header 使用 `52px` 统一高度；其他产品页面继续使用全局 TopNav
  高度，不能为了问答工作区改变所有页面；
- TopNav 的 `variant` 只定义宽度和定位等布局语义，`density` 独立定义高度；全宽工作区不能隐式切换为
  紧凑高度；
- 聊天记录侧栏在 `1024px` 及以上使用 `260px` 展开态和 `52px` 常驻图标轨道，低于该断点使用
  `260px` 临时 Sheet；切换按钮提供 `aria-expanded` 和准确文案，移动 Sheet 关闭后焦点返回唯一 opener；
- 侧栏 Header、历史滚动区和账号 Footer 分层，只有历史区滚动；桌面展开态和移动端显示完整账号行，
  收起态显示账号图标及 Tooltip，菜单不能被滚动容器裁剪；
- 侧栏收起状态属于界面偏好，可以在桌面端持久化，不改变导航权限、会话数据或请求状态。

## 账号体验

- 注册、登录、邮箱验证、密码恢复和账号设置统一使用 App API 的 Better Auth 能力；
- 登录、注册、验证邮箱、找回密码、重置完成和强制改密使用 Campus Web 的一致表单与状态页面，
  已登录账号设置可以使用 Better Auth UI，但不能建立第二套会话来源；
- 注册前必须在客户端明确勾选用户服务协议和隐私政策，法律链接在新标签页打开；重复邮箱注册使用
  与新账号相同的确认流程，不能在界面或响应中暴露邮箱是否已经注册；
- 非校园邮箱只有收到当前环境的逐地址邀请后才能注册，邀请链接预填邮箱但不绕过邮箱验证；
- 验证邮件发送成功后才开始 60 秒重发冷却；账号已创建但邮件发送失败时明确说明账号无需重复注册，
  并在当前页面提供重试。验证链接成功、过期、无效或已使用时分别显示可继续或可恢复操作；
- 未验证账号登录后由 Campus Web 显式发送验证邮件；发送结果、密码重置完成和注销受理只由刚刚完成
  的浏览器动作状态确认，查询参数或直接打开结果页不能声明成功或失败；
- 登录和注册成功后只返回经过校验的同源产品目标；临时密码登录后由根级守卫进入
  `/account/change-password`，完成后再返回原目标页面；
- “仅在此设备保持登录”默认开启；取消勾选后使用短会话。服务端返回 `X-Retry-After` 时，表单在对应秒数内显示倒计时并
  禁止重复提交；邮箱验证自动登录成功后显示 3 秒回跳倒计时，同时提供立即继续操作；
- 会话读取必须区分加载中、未登录和服务不可用。服务返回 `503` 时保留当前页面并提供重试，不能
  误跳登录；退出失败时明确说明用户仍保持登录状态；
- 账号设置提供注销入口，要求输入当前密码并明确展示已受理或失败状态；
- 已封禁、邮箱未验证、授权失效或正在注销时显示对应账号错误，不进入问答页面。

## 性能

- 首屏不得因可并行请求、重复会话读取或非关键依赖形成请求瀑布；
- 已获得的集合项尽早展示，不等待非关键内容完成；
- 路由代码、非关键账号状态和地图资源按用户意图加载或预取；
- 生产 Web Vitals 以第 75 百分位衡量，目标为 `LCP <= 2.5s`、`INP <= 200ms`、
  `CLS <= 0.1`；
- 应用 shell、路由和文档入口的 gzip 大小超过 `500 KiB` 时记录构建警告，但不得仅因大小警告阻塞发布；
- bundle 大小是定位回归的构建期信号，不是 Cloudflare 平台限制，也不能替代生产 Web Vitals、错误率和用户路径验收；
- bundle 图、入口、文件引用或已登记 vendor 资源缺失时必须终止构建；实际平台或上传命令拒绝仍属于发布失败。

## Campus Web 验收

- 问答、文档、通知、地图、食堂、同好群、反馈和账号的导航顺序与返回目标一致；
- 共同体验满足 [ui.md](./ui.md) 的验收要求；
- 受影响的类型检查、组件测试、bundle 完整性检查和浏览器测试通过；bundle 大小警告必须在报告中可见；
- 视觉调整不改变所属领域的接口和业务语义。
