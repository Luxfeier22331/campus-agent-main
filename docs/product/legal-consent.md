# 注册协议产品需求

## 1. 背景

校园问答提供账号注册、登录、聊天记录、个性化记忆、安全验证和第三方模型服务接入。
用户在注册前必须明确知道服务边界、AI 回答限制、个人信息处理方式和第三方服务参与情况。
本文定义注册同意、法律页面和服务端准入必须持续满足的产品要求，不记录实现进度。

## 2. 目标

- 注册前必须显式勾选同意协议。
- 用户可随时访问《用户服务协议》和《隐私政策》。
- 服务端必须拒绝未携带协议确认标记的注册请求。
- 不建设 consent ledger，不记录 consent IP、时间、账号 ID 或用户级 consent version。
- 协议内容准确反映当前产品能力，不承诺未实现功能。

## 3. 非目标

- 不做法律审计系统。
- 不做历史协议版本追踪。
- 不做登录后强制重新确认。
- 不做协议弹窗阅读时长、滚动到底等强交互。
- 不阻塞登录、密码重置或普通问答，只约束注册。

## 4. 用户故事

- 作为新用户，我注册前能看到必须同意服务协议和隐私政策。
- 作为新用户，如果我未勾选协议，系统应阻止注册并说明原因。
- 作为用户，我可以打开协议页面了解服务边界、数据处理和 AI 回答限制。
- 作为系统，直接调用注册接口但未携带协议确认标记的请求必须被拒绝。

## 5. 产品需求

### 5.1 注册页协议确认

在 `/account/register` 的 Better Auth UI 注册表单中展示必填 boolean field：

> 我已阅读并同意《用户服务协议》和《隐私政策》。

要求：

- 默认未勾选。
- 未勾选时阻止注册请求，并显示同一条用户可理解错误。
- 显示错误：`请先阅读并同意用户服务协议和隐私政策。`
- 勾选后注册请求携带服务端可校验的协议确认 header。
- 协议确认不控制 Turnstile 是否展示或执行；Turnstile 属于独立的 auth
  admission hardening。
- 协议链接应可被键盘访问，且不得破坏表单基础可用性。

### 5.2 服务端注册准入

注册请求必须携带协议确认标记，例如：

```text
x-campus-legal-accepted: terms-and-privacy
```

要求：

- 仅 `/api/auth/sign-up/email` 强制校验。
- 缺失或值不正确时拒绝注册。
- 返回可识别错误码：`legal_consent_required`。
- 前端映射为用户可理解错误文案：`请先阅读并同意用户服务协议和隐私政策。`
- 不持久化该标记。

### 5.3 协议页面

用户可访问页面固定为：

- `/legal/terms`
- `/legal/privacy`

页面要求：

- 简洁、可读、移动端友好。
- 顶部展示标题和生效日期。
- 从注册页、登录页、账号页可访问。
- 内容不出现内部架构词，例如 `app-api`、`execution-control`、`provider-config`。
- 可以提及第三方服务类别和代表性服务，例如 Cloudflare Turnstile、AI 模型服务、Sentry、邮件服务。

## 6. 协议内容要求

### 6.1 用户服务协议必须覆盖

- 服务说明：校园问答是辅助性信息整理服务。
- 信息准确性：不替代学校正式文件、官方通知、窗口意见或现场安排。
- 账号责任：用户应使用可接收邮件的邮箱，妥善保管账号。
- 禁止行为：攻击系统、滥用请求、提交违法/侵权/骚扰内容、上传无权处理的他人信息。
- AI 输出边界：回答可能不完整、延迟或存在误解。
- 用户内容：用户对自己提交内容负责。
- 服务变更：服务可能维护、中断或调整。
- 账号限制：滥用或违规可限制账号。
- 联系方式。

### 6.2 隐私政策必须覆盖

- 处理的信息：
  - 邮箱、显示名称、账号 ID、会话状态；
  - 聊天内容、反馈内容、聊天记录；
  - 个性化记忆或偏好摘要；
  - 安全验证结果；
  - 日志、错误信息和基础设备信息。
- 处理目的：
  - 账号服务；
  - 问答和聊天记录；
  - 个性化体验；
  - 安全防护；
  - 故障排查；
  - 服务改进。
- 第三方服务：
  - 安全验证；
  - AI 模型；
  - 错误监控；
  - 邮件服务；
  - 云服务/CDN。
- 用户权利：
  - 查看、更正、删除；
  - 关闭个性化记忆；
  - 删除聊天记录；
  - 注销账号或提交处理请求。
- 保存期限：按功能、安全和运行维护需要保存，不无限期承诺。
- Cookie / local storage：用于登录状态和基础功能。
- 未成年人说明。
- 联系方式。

## 7. 交互与错误状态

- 未勾选协议：表单/客户端 admission 返回错误，不调用 Better Auth 注册 provider。
- 绕过前端直接注册：后端返回 `legal_consent_required`，前端显示同一错误。
- 协议页面加载失败：按普通路由错误处理，不影响已有账号登录。
- Turnstile 未配置：继续使用现有“账号登录暂不可用，请稍后再试。”逻辑。

## 8. 验收标准

- 注册页默认未勾选协议。
- 未勾选时不调用 Better Auth 注册 provider。
- 勾选后注册请求携带 `x-campus-legal-accepted`。
- app-api 对缺少该 header 的 `/sign-up/email` 返回拒绝。
- `/legal/terms` 和 `/legal/privacy` 可直接访问。
- 登录页、注册页、账号页存在协议入口。
- 测试覆盖前端阻止、服务端拒绝、成功注册携带 header、协议页面渲染。
- 不新增 consent 数据表、字段或用户级 consent 记录。
