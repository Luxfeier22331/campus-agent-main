# 界面体验基线

## 文档边界

本文规定仓库内用户界面的共同体验底线，适用于 Campus Web、Ops Web 和仓库自有开发工具。
具体用户旅途和信息内容由所属产品文档维护；组件实现、精确样式值和测试断言由代码维护。

第三方画布、地图、阅读器和领域组件可以保留适合任务的视觉与交互，但其外层任务仍须满足本文的
语言、状态真实性、焦点和可访问性要求。

## 设计方向

本基线借鉴 Apple HIG 的清晰、克制、尊重内容、直接操作、一致性和即时反馈原则，并以校园公共
服务场景的可读性与可达性作为优先级。这里借鉴的是判断界面质量的方法，不复制 Apple 的品牌视觉、
图标、排版或专属平台组件。

- 内容和任务是第一视觉层，装饰、阴影和动效只在帮助理解层级时出现；
- 页面结构保持稳定，导航、控件、状态和反馈在 Campus 与 Ops 之间使用同一语义；
- 交互先给出可预测的按下、聚焦、加载、成功和失败反馈，不能用动画掩盖状态变化；
- 动效、透明度和对比度服从 `prefers-reduced-motion`、辅助技术和文本放大；
- 首期不引入 Liquid Glass。需要层次时使用不透明语义表面、边框和有限阴影，避免把玻璃拟态当作
  产品基线。

## 信息与语言

- 第一屏直接承载当前任务；页面标题描述对象或动作，不用口号、实现名或同义反复解释页面；
- 先展示决定下一步的信息，再渐进披露关联标识、原始字段和技术细节；
- 界面使用直接、具体的中文。正式产品名、字段名和外部平台名保持原值；
- 错误说明发生了什么、影响什么，并在能够恢复时提供就近操作；不把日志、调用链或外部记录描述成
  已经形成的结论；
- 相对时间必须符合人的阅读习惯，完整时间放入详情或提示；不能把投影更新时间描述成运行心跳。

## 信息层级与组件

- 页面区段默认使用标题、留白和分隔线组织，不把每个区段包装成悬浮卡片，也不嵌套卡片；
- Card 只用于独立重复对象、对话框内容或确实需要边界的工具；桌面扫描比较优先使用语义表格；
- Badge 只表达一个对象的主要状态或短分类。同一对象不重复状态 Badge，标题和普通元数据不用 Badge；
- 通知内部领域 Badge 使用稳定的语义色组辅助扫读，分类文字仍是主要标识；门户类型和外链来源使用
  普通元数据与来源图标，不复用领域 Badge 的颜色语义；
- 图标按钮使用约定俗成的图标并提供可访问名称或 Tooltip；文字按钮只承载清楚的命令；
- 路由切换使用导航链接和 `aria-current`。只有同页即时切换的 panel 才使用 Tabs 及其键盘语义；
- 二元设置使用 Checkbox 或 Switch，单选选项使用 Radio，有限选项使用 Select，数值使用对应输入或
  调整控件，不用自制可点击矩形模拟这些控件；
- 导航、按钮、Radio、Tabs 和 Menu 等控件 chrome 不形成文本选区，避免连续点击时出现选中；正文、
  代码和表单输入仍保持可复制；
- 表单字段必须关联 label、说明和错误；错误靠近字段，提交中、成功、失败和并发变化不得混为一种
  反馈。简单搜索表单无需为形式统一引入额外状态框架。

## 状态真实性

- 读取中、成功空数据、部分响应、旧数据、失败、禁用和无权限必须分别呈现；
- 依赖失败只影响所属区域，仍可使用的主要任务继续可用；
- 业务状态必须由所属领域穷尽映射为文案和视觉意图，未知值不得默认为警告或成功；
- 状态同时使用文字和视觉提示，颜色不能成为唯一表达；
- 正常数据新鲜度不在每个条目重复；只有旧缓存、刷新失败或合同明确标记异常时提示。

## 外观与主题

- 共享基础提供跟随系统、浅色和深色三种外观模式；跟随系统时响应操作系统外观变化，手动选择在
  同一浏览器中保持；
- 页面只使用语义颜色（画布、表面、文字、边框、品牌和状态），应用不能把某个浅色十六进制值当作
  跨主题合同；
- 品牌身份、主操作、链接、选中和业务状态使用独立语义。品牌身份色不表示可点击或错误，主操作色
  不用于导航、Tabs、筛选和列表当前项；这些选中状态使用克制的选中表面、文字或边框；
- 实色交互 tint 只用于主要命令和 Checkbox、Switch 等明确控件开态。状态色只表达对应状态，并与
  文案、图标、线型或其他非颜色提示共同使用；
- 实色主操作与所在表面保持清晰边界；启用态可以使用轻微语义边框，禁用态保留中性边界，不能只靠
  接近画布的灰白底色表达不可用状态；
- `Campus` 面向阅读和问答，优先保证阅读宽度与触控目标；`Ops` 面向扫描、比较和操作，优先保证
  表格行高、信息密度与可见焦点；两者只调整密度，不建立第二套颜色或控件语义；
- 主题切换是用户设置，不改变权限、数据新鲜度、请求状态或领域文案；首屏脚本只负责在 hydration
  前应用已选择的外观，不读取业务数据。
- 实际明暗发生变化时使用短促的整页淡入淡出表达状态转换，不逐元素补颜色动画；首次加载、同一
  明暗主题内切换模式和 reduced motion 均立即完成。连续选择以最后一次为准，不能堆叠动画；地图等
  自绘画布在自身 style 就绪前保持背景占位，不能把旧底图与新外层主题同时展示。

## 落地范围

### 产品可用性状态页

`status-web` 是产品可用性页面，不承载班车、食堂营业等校园业务状态。页面 H1 后直接进入两个固定服务行：校园问答
与问答之外的其他服务；不增加中间分组标题或服务计数。每项服务展示当前状态、最近检查时间和过去 30 天时间线。
第一版不展示事件、维护、通知或订阅入口。

- 状态页完全匿名，不展示账号、登录或 session 状态；桌面和移动 header 对齐 Campus 的产品导航顺序：问答、
  文档、通知、校园地图、食堂、同好群、反馈、服务状态。Campus 继续由 `CampusTopNav` 组合导航，状态页使用
  独立原生渲染器，不将 `CampusTopNav` 或产品导航迁入 `packages/ui`；
- Campus `/status` 与状态页 `/go/campus/*` 只通过配置的公开 origin 做固定 `302`、`no-store` 重定向，探测入口
  `STATUS_CAMPUS_ORIGIN` 与用户导航入口分开维护；
- 同一服务的当前状态只在服务行出现一次；正常快照不展示整体状态横幅、跨服务状态计数或全局“最近更新”时间；
  时间线日期结果只在共享提示层中说明；
- 时间线以快照 `generatedAt` 为末日锚点。历史中没有记录的日期显示为中性“无历史数据”空槽，不映射为
  `unknown`；探测明确返回未知时才显示“未知”。日期用参考状态页风格的连续窄竖条轨道表达，条段高约
  `32px`、间隙 `2px`；30 个真实日期均分轨道宽度，移动端铺满卡片内容宽度，桌面轨道上限为 `448px`，
  并在 `320px` 宽度下完整显示；
- 快照超过 `expiresAt` 后需要在服务区域就近提示“监控数据已过期”；
- 刷新失败与服务状态分开表达。已有快照时保留最近结果并提示无法更新；快照过期后当前状态显示为 `unknown`，
  历史时间线仍然保留；首次读取失败保留加载骨架并等待下一次固定间隔读取；异常提示可以显示最近成功更新时间。页面完整时间和
  按日时间线统一使用北京时间 `Asia/Shanghai`；
- 服务列表、异常数据提示和数据区域使用不超过 `8px` 圆角，列表内部用分隔线组织服务行，按钮和提示层等控件同样
  不超过 `8px` 圆角。状态页可以使用极弱的边框阴影组织重复对象，不使用大圆角和装饰性阴影；该规则只约束
  状态页，不迁移现有 Campus/Ops 页面；
- 所有 viewport 使用同一套时间线 DOM 和复合 `role="slider"` 控件，每个服务只有一个 Tab 停靠点；控件提供
  `aria-valuemin="1"`、`aria-valuemax="30"`、当前索引和包含日期/状态的 `aria-valuetext`。左/下方向键选择前一天，
  右/上方向键选择后一天，`Home` 和 `End` 选择首尾日期且首尾不循环；轨道点击、触摸和细指针移动按横坐标选择最近日期。
  30 根竖条仅作为视觉子元素，轨道本身承担焦点和触控目标，不增加横向滚动。日期结果由一个页面级 `role="tooltip"` 提示层展示，
  打开时通过 `aria-describedby` 关联复合控件，Escape、失焦或外部点击关闭；页面在 `320px` 和 `390px` 宽度下不得产生页面级横向滚动；
- 初始状态使用两个与真实服务行结构和尺寸一致的静态骨架，不使用 shimmer；首次读取失败继续保留骨架。禁用 JavaScript
  时隐藏骨架，并在同一服务列表内显示“需要启用 JavaScript 才能读取服务状态。”；
- 时间线不能只依赖颜色：正常使用实心条，受影响使用一道横向空隙，中断使用两道横向空隙，未知使用点线轮廓，
  无历史数据使用虚线轮廓；图例使用相同形状，forced-colors 模式继续提供系统色下的可区分样式；
- 公共页面不展示开发、预发布或生产环境标签；环境字段只用于快照隔离和运行时配置。`generatedAt` 只作为时间线锚点，
  并在过期或读取失败时按需提供最近成功更新时间；探测频率和时区属于运行合同，不在页面底部重复说明。入口映射或
  重定向不创建额外服务行。
- 页面按固定间隔自动读取快照，常态不提供手动刷新按钮；首次读取失败时保留加载骨架并等待下一次固定间隔读取，
  自动读取不抢焦点。常态没有整体摘要，只由唯一隐藏
  `status` 节点播报语义状态变化，不播报 `generatedAt`、相对时间刷新或时间线浏览动作；提示层
  不使用 live region。forced-colors 下必须使用系统色，并用填充、形状、边框线型区分状态，不依赖颜色单一编码。

当前基线扩展覆盖 Campus 首页/问答、文档目录与详情、通知目录与详情、同好群、食堂、校园地图和反馈，以及 Ops
`/overview`、`/requests`、请求详情、食堂维护和 Dining Studio。页面组合沿用同一套主题、焦点、
导航和状态语义；Campus 保留阅读与问答所需的内容宽度，Ops 保留扫描与比较所需的信息密度。

地图和 Dining Studio 是领域界面例外：MapLibre 的底图、浮层、marker 和选中高亮使用 Campus 专属
Token，主题变化会重新加载对应 MapLibre style；tldraw 的画布、工具栏和对话框 portal 使用 Ops 语义
表面，并同步 `colorScheme`。这些适配不改变业务 API、领域数据或编辑合同，也不引入 Liquid Glass。

代表性浏览器验收覆盖 `320px`、`390px`、`1023px`、`1024px` 和 `1440px`，包括页面级重排、深色主题
持久化、移动导航 Escape/焦点回收和 Axe 扫描。Campus 的聚焦 lane 由
`apps/campus-web/e2e.ui-baseline.config.ts`
和 `test:e2e:ui-baseline` 提供；Ops 的三 viewport 套件由 `apps/ops-web/browser.config.ts` 提供。
这些检查描述源码验收范围，不表示某个环境已经部署。

## 响应式与输入

- 产品页面在 `320px` CSS viewport 下能够重排，不能依赖页面级横向滚动；确需横向比较的数据区域
  可以在自身边界内滚动，移动端核心旅途应提供任务导向列表；
- 主要移动操作和图标按钮提供至少 `44px` 触控区域，所有指针目标满足 WCAG 2.2 最低要求；
- 文字允许换行，固定格式控件具有稳定尺寸，动态内容不得遮挡相邻内容；
- 所有交互具有可访问名称、正确状态、可见焦点和逻辑顺序；核心任务可以只用键盘完成；
- Dialog、Sheet、Menu 和 Tabs 使用成熟组件处理焦点、Escape 和键盘导航，关闭后焦点返回合理位置；
- 次级侧栏在桌面端可以收起，但必须提供可见、可键盘访问的切换按钮，不能只依赖边缘 Rail 或快捷键；
- 问答工作区 TopNav 和聊天记录侧栏 Header 使用 `52px` 统一高度；其他产品页面继续使用全局 TopNav
  高度，不能为了问答工作区改变所有页面；
- TopNav 的 `variant` 只定义宽度和定位等布局语义，`density` 独立定义高度；全宽工作区不能隐式切换为
  紧凑高度；
- 聊天记录侧栏在 `1024px` 及以上使用 `260px` 展开态和 `52px` 常驻图标轨道，低于该断点使用
  `260px` 临时 Sheet；切换按钮提供 `aria-expanded` 和准确文案，移动 Sheet 关闭后焦点返回唯一 opener；
- 侧栏 Header、历史滚动区和账号 Footer 分层，只有历史区滚动；桌面展开态和移动端显示完整账号行，
  收起态显示账号图标及 Tooltip，菜单不能被滚动容器裁剪；
- 侧栏收起状态属于界面偏好，可以在桌面端持久化，不改变导航权限、会话数据或请求状态；
- 目标基线为 WCAG 2.2 A/AA，支持文本放大、reduced motion 和辅助技术状态播报。

## 验收

- 页面在常见桌面宽度以及 `320px`、`390px` 下无文本遮挡、页面溢出或不可达操作；
- 加载、空、失败、部分成功、禁用和成功状态与真实数据一致；
- 键盘、焦点恢复、可访问名称和核心任务通过组件测试及代表性浏览器旅途验证；
- 自动化无障碍扫描覆盖代表性状态，不以全页面截图或组件目录代替真实旅途验证。
