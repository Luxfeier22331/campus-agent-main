# 对话附件

## 状态

对话附件是产品目标，当前没有已开放的上传、保存或模型消费合同。本文不把候选数据库、对象
存储、接口或执行步骤描述成现有能力；实现前必须先建立可执行合同和数据所有权。

## 用户目标

- 用户可以在提问时附带截图，请系统解释截图内容；
- 用户可以附带小型文档，请系统总结、提取信息或结合问题回答；
- 用户能在发送前查看、替换或移除附件；
- 历史消息能够显示附件名称、类型、处理状态和安全预览；
- 附件失败不应悄悄退化为忽略附件后的普通回答。

## 产品行为

### 图片

图片用于本轮多模态理解。模型应区分图片中读取的信息和已开放校园工具返回的当前事实；截图
不能替代制度、通知等正式数据来源。

### 文档

文档用于当前会话的有界阅读和总结。用户上传内容不是机构知识库来源，不自动进入 RAG、发布
流程或长期个人记忆。

### 处理状态

界面至少区分待处理、处理中、可用和失败。发送前失败的附件必须阻止带附件请求；发送后处理
失败必须显示明确原因和可重试操作，不能返回看似完整但没有消费附件的答案。

## 边界

- 附件仅属于上传者及其会话，访问必须经过会话权限检查；
- 不允许从文件名、客户端 MIME 或存储地址推断安全性；
- 模型可见内容必须限制类型、大小和解析结果；原始认证材料和内部存储标识不得进入模型；
- 删除会话或附件后，产品读取和后续模型调用必须停止访问相应内容；
- 附件不能成为 official notice、regulation、curriculum 或 official web 的来源事实；
- 不承诺通用网盘、跨会话文件库、协同编辑、任意大文件处理或自动知识库导入。

## 交互要求

- 添加附件使用明确的附件控件，展示支持类型与大小限制；
- 发送、移除、重试和取消在键盘与触控设备上均可操作；
- 长文件名换行或截断时保留可访问名称，不挤压发送按钮；
- 上传与处理进度不能导致输入区跳动、遮挡消息或丢失已输入文本；
- 错误信息说明用户下一步操作，不暴露内部地址、供应商响应或存储标识。

## 验收标准

- 单图、图片加文字、小型文档和不支持类型分别有端到端测试；
- 无权用户不能读取、复用或删除他人附件；
- 失败附件不会被静默忽略，重试不会重复发送消息；
- 历史会话能稳定展示附件状态，删除后不再可访问；
- 图片与文档内容不会自动进入机构知识库或长期记忆；
- 移动端与桌面端均无文本覆盖、不可达操作或页面横向溢出。

## 实现前置

开始实现前必须确定并测试：上传与读取合同、数据生命周期、权限模型、存储所有权、模型输入
限制、删除语义和观测边界。精确字段应写入合同与 schema，不回填到本 PRD。
