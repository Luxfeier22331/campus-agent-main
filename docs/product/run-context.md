# 多轮对话

## 背景

校园问答需要理解“这个”“上一条”“刚才第二点”等连续追问。产品必须让用户在同一会话内自然
延续问题，同时避免旧轮次、失效依据或错误记忆覆盖当前意图。

本文只定义用户可感知的多轮行为。内部上下文装配、记忆和执行边界见
`../architecture/system/agent-framework.md` 与 `../architecture/system/memory-plane.md`。

## 目标

- 当前问题可以结合近期对话、本轮重新准备的依据和当前可用的个人记忆理解；
- 用户可以追问近期回答正文中可识别的对象和规则，不必重复完整背景；
- 系统明确区分当前输入、会话历史、长期记忆和检索依据；
- 上下文过长时优先保留当前问题和最近相关内容，并让裁剪结果可诊断；
- 快速连续发送、取消、超时和较晚完成的旧请求不会覆盖较新的会话状态。

## 用户行为

### 连续追问

用户先询问一项制度，再问“那大一能不能申请”时，系统应结合上一轮主题理解指代。无法可靠
判断时，应请求澄清，不能猜测。

### 追问依据

用户询问“刚才引用的第二条原文”时，只有近期对话正文能够唯一确定被指代对象，系统才据此在本轮
重新检索并形成当前依据。来源只出现在上一轮结构化来源列表、当前依据不存在或用户无权访问时，应
请求用户明确来源或说明无法回答，不能直接复用旧引用或生成虚构引用。

### 跨能力追问

用户可以先查询一个校园事实，再结合制度或培养方案继续提问。上一轮结果只帮助理解本轮问题，
不能替代本轮所需的实时工具调用或知识检索。

### 快速连续发送

同一会话中的请求按各自消息和运行标识处理。较早请求晚完成时，不得覆盖较新请求选中的依据、
会话状态或展示内容。

## 上下文规则

- 用户看到的会话历史必须来自已保存的会话，不能因刷新页面或更换设备而依赖浏览器临时状态；
- 当前消息优先于历史内容；旧轮次不能改变用户本轮明确表达的目标；
- 历史对话和个人记忆必须保持来源可区分；上一轮工具结果与引用依据不进入本轮模型上下文；
- 个人记忆只有在用户启用后参与对话，关闭记忆不影响近期会话追问；
- 依据追问必须重新检索并确认来源、版本和访问范围；最终引用只能来自本轮依据。

## 裁剪

上下文超出模型允许范围时，依次保留当前问题、本轮依据和必要的最近完整对话片段，再保留有已确认值
的会话状态。个人记忆由运行时在功能 active 且状态不是 pending 时按需读取，不预载为隐藏上下文，也不向
用户暴露工具或读取过程。被裁剪内容不得通过其他字段重新注入。当前输入本身超过限制或无法形成有效
上下文时，系统应返回明确错误。

## 非目标

- 允许用户编辑任意会话图或运行时内部状态；
- 把全部历史消息无条件发送给模型；
- 使用独立文本分类器猜测指代；
- 让旧依据绕过本轮检索、权限或终结校验；
- 向用户暴露内部上下文装配、模型窗口或执行协议字段。

## 验收标准

- 制度连续追问、正文可消解的依据追问、跨能力追问和无法消解的指代均有测试；
- 当前问题在模型输入中只出现一次，历史内容不能覆盖当前请求；
- 依据追问会在本轮重新检索，旧引用不得直接复用；
- 裁剪顺序稳定，超限有明确错误，诊断信息不包含被裁剪正文；
- 并发轮次、取消、超时和较晚完成不会破坏较新的会话状态；
- 关闭记忆后仍可使用近期会话上下文，记忆 active 后才参与后续对话并保存新的长期信息。
