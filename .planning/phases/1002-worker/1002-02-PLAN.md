# Plan 1002-02: 收口 staging preflight 与 DB/Access gate

## Objective

把当前分散的 shell env、secret、Worker config、shared DB drift、Access/operator admission 检查收口成一个 canonical staging preflight，确保发布前 fail-close。

## Scope

- `scripts/doctor_env.py`
- `scripts/check_worker_secret_presence.py`
- `scripts/verify-worker-deploy-config.mjs`
- `apps/app-api` staging drift / migration gate
- deploy runbook 与 package scripts

## Tasks

1. 梳理现有 preflight/gate 覆盖面，列出缺口：
   - `STAGING_SUPERVISOR_API_BASE_URL`
   - `STAGING_ACCESS_TEAM_DOMAIN`
   - `STAGING_ACCESS_POLICY_AUD`
   - required Worker secrets
   - built config/service bindings
   - shared DB drift
2. 为 `app-api` 增加与 web surfaces 对齐的 staging config verification。
3. 设计并实现一个 canonical staging preflight 入口，按固定顺序执行 env/secret/config/db checks。
4. 明确 `APP_API_DB` / `APP_API_DB_FRESH` 的 gate 语义，并把 auth-sensitive fresh-lane proof 纳入验证。
5. 明确区分：
   - Access envelope failure
   - operator admission failure
   - shared runtime / bridge failure
6. 更新 deploy scripts 与 runbook，使 canonical preflight 成为 staging publish 前置步骤。

## Verification

- `uv run --all-packages python -m scripts.check_worker_secret_presence --env staging --json`
- `pnpm --dir apps/public-chat-web deploy:verify-config:staging`
- `pnpm --dir apps/protected-panel-web deploy:verify-config:staging`
- `pnpm --dir apps/app-api db:reconcile-shared-drift:staging`
- `pnpm --dir apps/app-api test:worker -- --reporter=verbose test/worker-runtime-cache.test.ts test/auth-and-db.test.ts`

## Acceptance Criteria

- staging publish 前存在单一 canonical preflight，而不是人工拼接命令。
- 缺失 shell input、secret、binding config 或 DB drift 时，deploy 会在 publish 前 fail-close。
- `APP_API_DB_FRESH` 仍被保留并有明确验证，不会被 preflight 收口时误合并回单 lane。
- Access failure 与 operator allowlist failure 在文档和验证里被明确区分。

## Out Of Scope

- Cloudflare dashboard provisioning 自动化
- 手工执行 `db:migrate:staging` 的替代方案
- production deploy gate
