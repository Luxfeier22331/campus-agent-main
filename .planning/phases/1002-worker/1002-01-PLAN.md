# Plan 1002-01: 统一三端 deploy-time release identity

## Objective

移除 `app-api` 与 `public-chat-web` 当前残留的静态 `SENTRY_RELEASE` 债务，统一 `app-api`、`public-chat-web`、`protected-panel-web` 的 staging release identity 生成与注入规则。

## Scope

- `apps/app-api`
- `apps/public-chat-web`
- `apps/protected-panel-web`
- 与 release identity 相关的 worker tests 和 runbook

## Tasks

1. 审计三端当前 release identity 注入方式与命名规则。
2. 为 `app-api` 新增 deploy-time `SENTRY_RELEASE` 注入逻辑，并保留显式 override 能力。
3. 为 `public-chat-web` 新增 deploy-time `SENTRY_RELEASE` 注入逻辑，并与 panel 使用同一命名规则。
4. 从 `app-api` 与 `public-chat-web` 的 `wrangler.toml` staging vars 中移除静态 `SENTRY_RELEASE`。
5. 更新相关 Worker tests，禁止未来再次把静态 staging release 写回 repo config。
6. 更新 deploy/runbook 文档，明确 release identity 属于 deploy-time concern。

## Verification

- `pnpm --dir apps/app-api test:worker -- --reporter=verbose test/worker.test.ts`
- `pnpm --dir apps/public-chat-web test:worker -- --reporter=verbose test/worker.test.ts`
- `pnpm --dir apps/protected-panel-web test:worker -- --reporter=verbose test/worker.test.ts`
- 代码审查确认 `app-api` 与 `public-chat-web` staging config 不再持有静态 `SENTRY_RELEASE`

## Acceptance Criteria

- 三端 staging deploy 都能生成 `<app>@staging-<sha>` 形态的 release identity。
- `app-api` 与 `public-chat-web` 不再把固定 release 名写死在 repo config。
- 测试覆盖 release identity 的 deploy-time 注入逻辑，而不是历史静态值。

## Out Of Scope

- Sentry deploy API 集成
- production release naming
- CI/CD provider-specific automation
