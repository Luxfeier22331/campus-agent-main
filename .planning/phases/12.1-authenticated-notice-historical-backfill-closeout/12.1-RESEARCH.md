These seams already prove the data path. The missing piece is orchestration and reconciliation:

- freeze full input
- generate checkpoints
- rerun full import
- compare expected IDs with registry state
- persist a closeout summary

One boundary detail matters here:

- checkpoints must be cumulative prefix slices of the frozen full bundle
- disjoint shards are unsafe because `authenticated_notice_import.py` delegates document persistence through `scope_refresh=(corpus, collection)`
- this means staged replay is a sequence of progressively larger prefixes, not arbitrary partitions

## Operational Facts We Must Preserve

- zero-byte authenticated-notice artifacts are valid
- repo-local MinIO previously stalled after zero-byte writes on a shared client
- the required fix is already landed: zero-byte writes use a one-shot client
- any closeout runner must preserve that runtime behavior and must not “fix” the issue by changing source-truth semantics

## Risks

- full `6694` replay may be long-running even with the current zero-byte fix
- document scope and raw asset scope do not have identical lifecycle semantics
- document scope is refreshed by authenticated notice import, so unexpected document IDs are a real closeout failure
- raw asset registry retains scope history, so reconciliation must require expected raw coverage but treat unexpected raw IDs as informational unless a stricter operational policy is explicitly added
- because `internal_notice` stays `offline_preparation`, any closeout artifact that implies serving release would be a category error

## Planning Implication

The right implementation is not “another smoke command.” It is:

- a closeout runner that uses the same import boundary
- a persisted input-freeze artifact
- checkpoint summaries plus rerun summary
- registry-based reconciliation keyed by expected notice/raw identities
