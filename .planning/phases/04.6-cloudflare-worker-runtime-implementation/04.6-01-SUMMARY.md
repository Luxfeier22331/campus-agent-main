# Phase 04.6 Plan 01: Worker Runtime Shell Summary

**A standalone Cloudflare Worker runtime shell now exists under `apps/*`, with local Wrangler/Vitest tooling, Route-based config, and a repo-safe workspace shape that does not spill provider concerns into `packages/*`**

## Performance

- **Duration:** Inline session on 2026-03-25
- **Tasks:** 2
- **Files modified:** 10

## Accomplishments

- Added `apps/public-entry-worker` as the public-entry runtime shell with self-contained `npm` tooling and committed lockfile.
- Locked the Worker config to Route-based delivery with `workers_dev = false` and `preview_urls = false`.
- Added the initial Worker runtime source, env template, README, and Vitest harness so downstream behavior work could land on a real shell.
- Added a minimal `pyproject.toml` for the Worker app so the existing root `uv` workspace membership rule for `apps/*` does not break Python verification flows.

## Files Created/Modified

- `apps/public-entry-worker/package.json` - Local Worker scripts and Cloudflare runtime dependencies.
- `apps/public-entry-worker/package-lock.json` - Reproducible Node dependency lockfile for the Worker app.
- `apps/public-entry-worker/pyproject.toml` - Minimal workspace-safe Python metadata so `uv run --all-packages` keeps functioning.
- `apps/public-entry-worker/wrangler.toml` - Route-based Worker config with alternate public entrypoints closed.
- `apps/public-entry-worker/vitest.config.mts` - Worker-runtime test configuration.
- `apps/public-entry-worker/test/worker.test.ts` - Worker shell regressions and runtime-path coverage.

## Decisions Made

- Kept the Worker app self-contained under `apps/public-entry-worker` instead of creating root-level Node workspace files.
- Treated root `uv` workspace membership as a real repo constraint and satisfied it with a minimal app-local `pyproject.toml` rather than weakening the workspace rule.

## Deviations from Plan

None - the shell, config, and workspace compatibility fixes stayed within the plan's intended runtime boundary.

## Issues Encountered

- Initial Cloudflare package versions and Vitest integration assumptions were stale; the app was corrected to the currently installable SDK versions and the current `cloudflareTest(...)` plugin API.
- Wrangler attempted to write logs into a read-only user config directory inside the sandbox, so the app scripts now set `XDG_CONFIG_HOME=./.wrangler-home`.

## User Setup Required

None.
