# Phase 04.6 Plan 03: Trusted Worker Origin Summary

**`apps/supervisor-api` can now run behind the Worker in an explicit trusted-worker mode that rejects missing or invalid origin auth and maps Worker traffic to runtime-owned actor context instead of trusting forwarded user headers**

## Performance

- **Duration:** Inline session on 2026-03-25
- **Tasks:** 1
- **Files modified:** 4

## Accomplishments

- Extended `ApiSettings` with `worker_shared_secret` and `worker_actor_id`.
- Reworked `map_actor_context()` to branch explicitly by auth mode and added constant-time secret validation for `x-worker-origin-auth`.
- Ensured trusted-worker mode returns runtime-owned actor context from settings defaults instead of consuming forwarded `x-actor-*` headers.
- Added focused regressions for trusted-worker success, missing secret rejection, invalid secret rejection, and env parsing.
- Documented Worker-origin env vars in `.env.example`.

## Files Created/Modified

- `apps/supervisor-api/src/campus_supervisor_api/settings.py` - Added Worker-origin config fields and env parsing.
- `apps/supervisor-api/src/campus_supervisor_api/auth.py` - Added explicit `trusted-worker` auth handling with constant-time secret compare.
- `tests/api/test_supervisor_api.py` - Added trusted-worker path regressions and env parsing assertions.
- `.env.example` - Added `API_WORKER_SHARED_SECRET` and `API_WORKER_ACTOR_ID`.

## Decisions Made

- Kept `api.py` unchanged because the transport shell already cleanly delegates auth to `map_actor_context()`.
- Treated Worker-origin identity as runtime-owned context only, leaving final actor/ACL/audit semantics for Phase 5.

## Deviations from Plan

None - the origin-side patch stayed inside settings/auth/tests/env wiring as planned.

## Issues Encountered

- Repository verification must run with `UV_CACHE_DIR=/tmp/uv-cache` in this sandbox because the default `~/.cache/uv` path is not writable.

## User Setup Required

None.

## Next Phase Readiness

- Public answer traffic can now terminate at the Worker and reach `apps/supervisor-api` through an explicit trusted-origin seam.
- Phase 5 can build actor/ACL/audit semantics on top of this runtime-owned origin admission path rather than reopening edge auth design.

- Trusted-worker tests prove success with `x-worker-origin-auth`, `401` on missing/invalid secret, and runtime-owned actor context instead of forwarded `x-actor-*` values.
