# Phase 04.7 Consumer App Boundary Handoff

## Status

This handoff is retained as the accepted 04.7 boundary reference after PR #4 merged the `public-consumer-chat` implementation to `main` on 2026-03-27.

Read it as a phase-local boundary truth, not as an open planning queue.

## What 04.7 Froze

Phase 04.7 把 public consumer chat app 的实现边界收口为一个独立的 `apps/*` 产品前台，而不是对现有 Worker/origin seam 的重写。

本 phase 固定以下 truth：

- public answer path 继续是 `public hostname -> Cloudflare Route -> Cloudflare Worker -> apps/supervisor-api -> packages/supervisor-core -> specialist`
- consumer chat product 作为单独 app 落在 `apps/*`，推荐未来路径为 `apps/public-consumer-chat`
- `apps/public-consumer-chat` 的前台宿主固定采用 `TanStack Start`
- `apps/public-entry-worker` 继续只是公网入口壳，不是 UI host，不是 edge orchestrator
- `apps/supervisor-api` 继续只是 runtime ingress，不长出模板页面或 chat UI
- `packages/*` 不吸收 frontend、auth provider、conversation UI、Cloudflare 入口语义
- app auth 固定采用 `Better Auth`
- primary relational store 固定为 `Supabase Postgres`
- auth / chat 统一放在同一个 `Supabase Postgres` 中，按 schema 分域
- `Qdrant` 继续承担在线 retrieval 主存储
- v1 product MVP 固定为 `authenticated-first`
- v1 browser-to-answer transport 固定按 `same-site` 规划；`cross-origin` 不是当前默认实现

## Recommended App Placement

推荐 repo shape：

```text
apps/
├── public-entry-worker
├── public-consumer-chat
└── supervisor-api
```

其中：

- `apps/public-entry-worker`
  负责 public hostname、Cloudflare Route、outer admission、Worker-to-origin trust
- `apps/public-consumer-chat`
  负责 `/login`、`/chat`、`/chat/:conversationId`、sidebar、chatbox、app-level session UX、conversation ownership UX
- `apps/supervisor-api`
  负责 answer runtime ingress、transport mapping、request correlation、进入 supervisor path

明确禁止：

- 把 consumer app 做成 `apps/public-entry-worker` 的 UI mode
- 把 consumer app 做成 `apps/supervisor-api` 的模板页面
- 不采用裸 `TanStack Router + 外挂后端壳`
- 不把 app auth / conversation API 回灌到 `apps/supervisor-api`
- 让浏览器直接消费 `packages/*`

## Product Shape

v1 public consumer surface 固定为：

`sidebar conversation history + primary chatbox + app-level user session`

最小页面形态：

- left sidebar
  只展示当前用户自己的 history 与 `New chat`
- primary chat panel
  展示当前 conversation 的消息流、回答态、澄清态、错误态
- lightweight top bar
  展示产品名、当前用户、sign out / account entry

明确不是：

- panel
- admin
- workspace
- runtime-unification surface
- specialist/runtime/provider control plane

## Route Map And Required States

### Required Routes

- `/login`
- `/chat`
- `/chat/:conversationId`

### Route Meaning

| Route | Required behavior |
| --- | --- |
| `/login` | 只负责进入 public consumer app，不承担 panel/operator 登录含义 |
| `/chat` | 始终作为新对话起始页；展示 empty state，只有用户发送首条消息后才创建 conversation |
| `/chat/:conversationId` | 展示并继续某条当前用户拥有的对话 |

### Required States

| State | Required product meaning |
| --- | --- |
| `login` | 用户尚未进入 app-level session，只提供继续登录的明确动作 |
| `empty` | 当前 conversation 没有内容，展示 welcome copy、少量示例问题、范围提示 |
| `answer` | 正常展示 user message、assistant answer，以及可选 citations/evidence 区域 |
| `clarification` | assistant 明确要求补充信息，属于正常产品态，不渲染成错误 |
| `error` | 请求失败，显示简短原因、`retry` 入口、`request_id` / correlation hint |
| `history` | sidebar 展示当前用户自己的 conversation list，并允许切换线程 |

## Ownership Split Table

| Concern | Consumer app owns | `apps/public-entry-worker` owns | `apps/supervisor-api` owns | Still deferred to Phase 5 |
| --- | --- | --- | --- | --- |
| UI shell | sidebar, top bar, chatbox, route UX | no UI ownership | no page/template ownership | none |
| session UX | login state, logout UX, session lookup, protected route redirect | outer admission only | may receive trusted runtime context only | final actor semantics |
| conversation ownership | current-user history, thread lookup, server-side ownership enforcement | does not own history truth | does not own app conversation tables | actor, ACL, audit closure |
| answer execution | render answer, clarification, error states | request admission and trusted forwarding | runtime ingress into supervisor path | final retrieval ACL semantics |
| observability | display `request_id` or correlation hint to the user when needed | project trace/runtime metadata | consume request correlation and pass to supervisor | final audit governance |

关键规则：

- Worker-side identity material 不能被当作 canonical app identity
- consumer app user 不等于 `SupervisorRequest.actor`
- retrieval `ACL` 与 audit closure 仍然是 Phase 5，不得在本 handoff 中宣称已完成

## Transport Topology

v1 browser-to-answer transport 固定为 `same-site`。

### v1 Decision

- consumer app 的浏览器请求按 same-site path routing 规划
- `cross-origin` browser calls 不作为 v1 默认路径
- 如果未来需要 `cross-origin`，必须作为单独显式决策处理

### Why Same-Site For v1

- `authenticated-first` 与 cookie/session 语义更简单
- 避免把 Cloudflare Access CORS 复杂度引入第一版产品
- 更容易保持 consumer app session 与 public answer path 的一致 UX

### Topology Rule

```text
browser -> same-site app route / app-owned API seam -> public hostname -> Cloudflare Route -> Worker -> apps/supervisor-api
```

这个 section 的重点是产品调用拓扑，不改变 runtime canonical truth：

- Worker 仍然是唯一 public answer entry
- app 不绕过 Worker 直打 origin
- app 不直连 `packages/*`

## Reference UI Patterns

可以借鉴 `vercel-ai-chatbot` 的 consumer-chat shell 形态，但只借交互骨架，不借模板工程层。

允许借鉴：

- collapsible sidebar
- recency-grouped history，例如 `Today`、`Yesterday`、`Last 7 days`
- centered message column
- sticky composer
- empty-chat greeting
- history loading skeleton
- scroll-to-bottom affordance
- delete-thread / delete-all confirmation

明确不要继承：

- Next.js app/layout/routing structure
- Auth.js session model
- Vercel deployment assumptions
- model selector
- artifacts pane
- attachments
- slash commands
- pyodide 或 code-execution affordances

## App-Level Identity And Conversation Rules

- app-level sign-in / session UX 属于 consumer app line
- app host 固定为 `TanStack Start`，不是 standalone client router
- auth 固定为 `Better Auth`
- primary relational store 固定为 `Supabase Postgres`
- auth / chat 同库分 schema，默认命名为 `auth` 与 `chat`
- `ingestion_registry` 是同库内保留的 canonical registry schema 名称，但不是本 app phase 的主写域
- `Qdrant` 继续承担 online retrieval 主存储；`Postgres` 不承接在线向量检索主路径
- 不采用 `D1 for auth`
- 这组结论是 app-line accepted decision，不是 monorepo-wide framework freeze
- conversation history 只展示当前用户数据
- `/chat/:conversationId` 必须做 server-side ownership check
- conversation title 可以由首句截断或后端生成
- 只需要最小数据模型：`user`、`conversation`、`message`

## Anti-Drift Rules

- 不把 public consumer app 混成 protected internal panel
- 不把 public consumer app 混成 admin surface
- 不引入 runtime-unification 讨论
- 不在 UI 暴露 specialist、runtime、provider、internal orchestration
- 不把 Worker admission 写成 app-layer auth 真相
- 不把 Worker admission 写成 canonical app identity truth
- 不把 `TanStack Start` 退化成 `TanStack Router + 外挂后端壳`
- 不把 `D1 for auth` 写成可接受默认方向
- 不把 app session/conversation 规则写成 `packages/*` contract
- 不把 anonymous-enabled Worker 能力误写成 v1 默认产品模式

## Summary

04.7 把 public consumer chat 的实现边界收口为一个单独的 `apps/public-consumer-chat` 产品前台。后续实现只能在不改写 `public hostname -> Cloudflare Route -> Cloudflare Worker -> apps/supervisor-api` 这条 runtime truth 的前提下，完成 chat-first UI、app-level session、conversation ownership 和 answer rendering。Phase 5 的 actor、ACL、audit 仍然保持 deferred。
