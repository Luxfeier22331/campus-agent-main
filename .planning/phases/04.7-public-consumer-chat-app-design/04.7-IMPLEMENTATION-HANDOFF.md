# Phase 04.7 Implementation Handoff

## Goal

这份 handoff 把 04.7 已冻结的 consumer app 边界转成后续可执行的 build order。它不是 Phase 5 completion，也不重开 Worker / panel / governance 讨论。

固定前提：

- future app path: `apps/public-consumer-chat`
- public answer runtime truth: `public hostname -> Cloudflare Route -> Worker -> apps/supervisor-api`
- app host: `TanStack Start`
- auth: `Better Auth`
- primary relational store: `Supabase Postgres`
- auth/chat 同库分 schema，默认 `auth` + `chat`
- `Qdrant` 继续承担在线 retrieval 主存储
- v1 product posture: `authenticated-first`
- v1 browser calls: `same-site`

## Build Order

1. `App Shell`
2. `Auth/Session`
3. `Conversation Ownership`
4. `Chat Interaction`
5. `Runtime API Seam`

## App Shell

### Required output

- 在 `apps/public-consumer-chat` 建立 `TanStack Start` app-local frontend/runtime shell
- 路由骨架至少包含 `/login`、`/chat`、`/chat/:conversationId`
- 页面骨架固定为 sidebar + top bar + primary chat panel
- 默认采用 responsive 单一 IA，而不是桌面/移动双系统

### Required shell behavior

- left sidebar 可 collapse
- sidebar 包含 `New chat`、history section、current user footer
- main area 使用 centered chat column
- composer 固定在底部 sticky composer
- mobile 通过 drawer/collapse 复用同一套 shell，而不是 fork 新路由

### Explicit non-goals

- 不实现 panel
- 不实现 admin route
- 不实现 workspace/navigation hub
- 不引入 model selector、attachments、artifacts pane

## Auth/Session

### Required output

- app-level login / logout UX
- app-level session retrieval
- protected route behavior for `/chat` and `/chat/:conversationId`
- invalid-session redirect back to `/login`

### Rules

- Worker admission 仍然只是 outer access control，不是 final actor truth
- consumer app 负责用户进入前台后的 session UX
- v1 明确是 `authenticated-first`
- auth 固定采用 `Better Auth`
- 不采用 `D1 for auth`
- 不把 Worker admission 当作 canonical app identity truth
- 不把 app auth / conversation API 回灌到 `apps/supervisor-api`
- 这是 app-line frozen decision，不是 monorepo-wide auth substrate

### Failure behavior

- session 缺失时不展示 history 数据
- session 失效时清理 app-visible user state 并重定向登录
- 不使用 client-only guard 替代服务端 session check

## Conversation Ownership

### Required output

- 最小产品模型：`user`、`conversation`、`message`
- storage entry 固定走 `Supabase Postgres`
- schema 入口固定显式区分 `auth`、`chat`，并保留 `ingestion_registry` 命名约定
- current-user-only history list
- `/chat` 固定为新对话起始页；`New chat` 只返回该起始页，首条消息发送后才创建线程
- thread title strategy
- server-side ownership enforcement

### Minimum model expectations

| Model | Minimum fields |
| --- | --- |
| `conversation` | `id`, `ownerUserId`, `title`, `createdAt`, `updatedAt` |
| `message` | `id`, `conversationId`, `role`, `text`, optional `request_id` / `traceId` |

### Rules

- `/chat/:conversationId` 必须验证当前 session user 是否拥有该 conversation
- history 只返回当前用户数据
- title 可以先用首句截断或后端生成
- `Postgres` 承担 relational truth，不承担 online vector retrieval 主路径
- `Qdrant` 继续承担 online retrieval 主存储
- 不扩展到 shared conversation、folder/tag、long-term memory platform

## Chat Interaction

### Required output

- composer 输入与发送行为
- pending / waiting state
- `answer` rendering
- `clarification` rendering
- `error` rendering with `retry`
- history switching

### Required interaction details

- 空线程显示 greeting 和少量 suggested prompts
- history loading 时显示 skeleton
- 线程较长且用户滚离底部时显示 scroll-to-bottom
- composer 保持 autofocus、local draft persistence、clear send/stop semantics
- destructive actions 例如 delete thread / delete all history 必须二次确认

### State mapping

| Runtime result | UI state |
| --- | --- |
| completed answer | `answer` |
| clarification request | `clarification` |
| request failure / origin failure | `error` |
| no messages yet | `empty` |

### Product rules

- `clarification` 是正常产品态，不得当作异常 toast 一笔带过
- `error` 要暴露 `retry` 入口
- `error` 需要保留 `request_id` 或等价 correlation field 供用户报障
- citations/evidence 区域可以预留，但不是阻塞首版布局的前置条件

## Runtime API Seam

### Required output

- app 内有明确的 answer API adapter
- 请求通过现有 Worker/origin seam 进入 `apps/supervisor-api`
- request/response shape 能映射 prompt、conversation identifiers、`request_id`

### Topology

```text
browser -> same-site app seam -> public hostname -> Cloudflare Route -> Worker -> apps/supervisor-api
```

### v1 topology decision

- v1 browser calls are `same-site`
- `cross-origin` is deferred
- CORS posture for v1 is `same-site only for v1`
- cookie posture for v1 assumes same-site session semantics

### Contract rules

- app 不直接绕过 Worker 调 `apps/supervisor-api`
- app 不直接消费 `packages/*`
- Worker 之后仍然首先进入 `apps/supervisor-api`
- 不采用裸 `TanStack Router + 外挂后端壳`
- `request_id`、trace、correlation metadata 属于 runtime seam，可在 UI 中 surfaced
- `actor`、`ACL`、`audit` 仍不在本 phase 收口

### Minimum request/response mapping

| Direction | Fields |
| --- | --- |
| request | `conversation_id`, prompt/user goal, optional client-generated `request_id` |
| response | answer text or clarification text or error payload, surfaced `request_id` / trace hint |

## Recommended Build Sequence

1. 先建 `apps/public-consumer-chat` 路由壳与 layout，不接真实数据
2. 接上 `Auth/Session`，先完成 `/login` 与受保护路由
3. 再落 `Conversation Ownership` 的最小表和 server-side ownership
4. 接 `Chat Interaction`，完成 empty/answer/clarification/error/history 五类主要产品态
5. 最后稳定 `Runtime API Seam`，把 request/response、`request_id`、retry 语义收口

## Validation Checklist

- [ ] `apps/public-consumer-chat` 作为单独 `apps/*` app 存在
- [ ] `/login`、`/chat`、`/chat/:conversationId` route skeleton 存在
- [ ] shell 包含 collapsible sidebar、top bar、centered chat column、sticky composer
- [ ] `/chat` 和 `/chat/:conversationId` 默认受 session 保护
- [ ] history 只返回当前 session user 的 conversation
- [ ] server-side ownership guard 覆盖 `/chat/:conversationId`
- [ ] `clarification` 与 `error` 在 UI 上被区别渲染
- [ ] `retry` 行为明确可用
- [ ] `request_id` 或等价 correlation hint 会在错误态中 surfaced
- [ ] browser-to-answer 调用保持 `same-site`
- [ ] v1 不要求 `cross-origin` CORS 兼容
- [ ] app 不直接调用 `packages/*`，也不绕过 Worker 直打 `apps/supervisor-api`

## Deferred List

以下内容明确 deferred，不属于本 handoff 完成范围：

- final `actor` propagation
- retrieval `ACL`
- audit closure
- panel / admin design
- runtime unification
- `cross-origin` answer transport
- model selectors
- attachments
- artifacts panes
- shared conversations / team permissions

## Summary

04.7 的 downstream implementation 应按 `App Shell -> Auth/Session -> Conversation Ownership -> Chat Interaction -> Runtime API Seam` 顺序推进。后续实现可以借用 consumer chat 产品的交互骨架，但必须继续把 Worker 当作 public entry shell，把 `apps/supervisor-api` 当作唯一 public runtime ingress，并把 Phase 5 的 actor、ACL、audit 明确留在 deferred 状态。
