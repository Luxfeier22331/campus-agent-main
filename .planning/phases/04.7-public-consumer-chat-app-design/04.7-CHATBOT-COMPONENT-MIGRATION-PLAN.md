## Goal

这份计划记录了按批次把 `apps/public-consumer-chat` 的核心 UI 从“参考 chatbot 的定制实现”推进到“直接适配 chatbot 组件系统”的执行拆分，同时保持 04.7 已冻结的正式方向不变。

本计划默认依赖以下文档：

- [04.7-CONSUMER-APP-BOUNDARY-HANDOFF](./04.7-CONSUMER-APP-BOUNDARY-HANDOFF.md)
- [04.7-IMPLEMENTATION-HANDOFF](./04.7-IMPLEMENTATION-HANDOFF.md)

## Recorded Execution Rules

- 优先直接迁组件结构，不优先保留旧实现
- 一次只收口一个稳定批次，每批必须附带可重复验证
- 每批结束必须跑 `pnpm typecheck`
- 每批结束尽量跑 `pnpm test`
- `pnpm test` 若失败，只接受外部 Supabase/DNS 网络类失败；前端 contract/scaffold/test 不允许退回

## Batch 1: Sidebar Primitive And Shell Unification

### Objective

把 chat shell 的根布局彻底统一到 `SidebarProvider + Sidebar + SidebarInset + SidebarRail` 原语，不再保留旧 sidebar 壳的思维模型。

### Files

- `apps/public-consumer-chat/app/components/ui/sidebar.tsx`
- `apps/public-consumer-chat/app/components/chat/chat-shell.tsx`
- `apps/public-consumer-chat/app/components/chat/app-sidebar.tsx`
- `apps/public-consumer-chat/app/components/chat/chat-header.tsx`
- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 让 `sidebar.tsx` 成为唯一 sidebar primitive 来源
2. 让 `chat-shell.tsx` 只负责 provider + shell composition
3. 让 `app-sidebar.tsx` 继续贴近 reference header/new chat/delete/history/footer 结构
4. 删除只服务旧 sidebar 壳的样式依赖
5. 修正 collapsed / mobile drawer / rail / overlay 行为

### Exit Criteria

- desktop 与 mobile 共用同一套 sidebar primitive
- sidebar 卡顿问题从结构层被消除，而不是仅调动画参数
- shell 代码不再混有旧 `chatbot-sidebar` 单体壳残留

## Batch 2: Message System Migration

### Objective

把消息区从 list 内联渲染改造成 `messages container + message component + thinking state` 结构。

### Files

- `apps/public-consumer-chat/app/components/chat/chat-message-list.tsx`
- `apps/public-consumer-chat/app/components/chat/chat-message.tsx`
- `apps/public-consumer-chat/app/components/chat/chat-greeting.tsx`
- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 让 `chat-message-list.tsx` 对齐 reference `messages.tsx` 的容器职责
2. 让 `chat-message.tsx` 承接单条消息的 role/kind/request_id/retry 呈现
3. 让 `thinking` 成为独立 message-like 表现
4. 让 empty state greeting 与 message container 的叠放方式对齐 reference
5. 保留 04.7 自己的 `clarification` / `error` / `request_id` 业务要求

### Exit Criteria

- list 不再内联大块 message DOM
- answer / clarification / error / pending 结构稳定
- scroll-to-bottom 行为与 reference 接近

## Batch 3: Composer And Empty-State Alignment

### Objective

把新对话页输入区和建议动作区收口到 reference 的交互形态，但保持当前 app 的 conversation creation 规则。

### Files

- `apps/public-consumer-chat/app/components/chat/chat-composer.tsx`
- `apps/public-consumer-chat/app/components/chat/suggested-actions.tsx`
- `apps/public-consumer-chat/app/components/chat/chat-greeting.tsx`
- `apps/public-consumer-chat/app/routes/chat.index.tsx`
- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 对齐 suggested actions 的 wrapper、布局和动效
2. 对齐 composer 的容器结构和 submit affordance
3. 保持 auto-resize、draft persistence、focus、enter 行为
4. 明确 `/chat` 是新对话起始页，首条消息后才创建线程
5. 确保新对话页与 thread 页共享同一 shell

### Exit Criteria

- `/chat` 的用户心智清晰稳定
- 建议问题与 composer 的视觉和交互接近 reference
- 首条消息的线程创建过渡不破坏当前产品规则

## Batch 4: History And User Nav Alignment

### Objective

把 sidebar history 和 user nav 继续拆到接近 reference 的粒度，减少大组件内部条件分支。

### Files

- `apps/public-consumer-chat/app/components/chat/chat-history-list.tsx`
- `apps/public-consumer-chat/app/components/chat/sidebar-user-nav.tsx`
- `apps/public-consumer-chat/app/components/chat/app-sidebar.tsx`
- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 把 history list 进一步拆向 history item 结构
2. 对齐 active / hover / collapsed / skeleton 的层级与样式
3. 对齐 user nav button 与 menu 的 DOM 结构
4. 保持 delete all / sign out 等 destructive action 的确认和位置稳定

### Exit Criteria

- history list 的交互与 reference 更接近
- user nav 在 collapsed / expanded 下都没有错位和抖动
- sidebar footer 行为稳定

## Batch 5: Auth Layout And Preview Migration

### Objective

把 `/login` 从“独立设计的登录页”收口到 reference auth layout 的结构语言。

### Files

- `apps/public-consumer-chat/app/routes/login.tsx`
- `apps/public-consumer-chat/app/components/chat/auth-form.tsx`
- `apps/public-consumer-chat/app/components/chat/submit-button.tsx`
- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 对齐 auth layout 左主列 + 右 preview 区域
2. 让右侧 preview 更像真实 chat shell 缩略图，而不是独立卡片
3. 保留 `Better Auth` 调用路径，但不污染视觉组件结构
4. 保持 `/login` 已登录重定向逻辑不变

### Exit Criteria

- 登录页视觉结构明显接近 reference
- 登录表单与按钮状态结构统一
- auth 交互和外观不再割裂于 chat shell

## Batch 6: Style Convergence And Cleanup

### Objective

消灭“旧壳样式 + 新组件样式并存”的状态，让 CSS 只服务当前组件体系。

### Files

- `apps/public-consumer-chat/app/styles.css`

### Tasks

1. 删除旧 sidebar 壳相关死样式
2. 删除旧 header/message/composer/auth 的残留类
3. 合并 spacing、radius、border、shadow、motion token
4. 确保命名与当前组件树一致

### Exit Criteria

- `styles.css` 不再同时服务两套结构
- 后续 UI 调整不必再判断“旧壳还是新壳”

## Batch 7: Verification And Gap Audit

### Objective

在浏览器中确认迁移后的真实状态，并盘点与 reference chatbot 的剩余差距。

### Commands

```bash
cd apps/public-consumer-chat
pnpm typecheck
pnpm test
pnpm build
pnpm dev
```

如外部条件就绪，再补：

```bash
cd apps/public-consumer-chat
pnpm smoke:live
```

### Manual Checks

1. `/login` 的整体结构是否已明显接近 reference
2. `/chat` 是否稳定停留在新对话页
3. 发送首条消息后是否正确转到 `/chat/:conversationId`
4. sidebar collapse/expand 是否顺滑
5. mobile drawer 是否共用同一 shell
6. history active state / hover / loading skeleton 是否稳定
7. user nav 菜单是否稳定
8. scroll-to-bottom 是否合理出现

### Exit Criteria

- 记录剩余差距
- 差距必须具体到组件/交互，不接受“感觉还差一点”

## External Conditions

以下条件不属于 UI 迁移本身，但会影响完整验证：

- reachable `Supabase Postgres`
- 正确的 `PUBLIC_CONSUMER_CHAT_DATABASE_URL`
- 正确的 `BETTER_AUTH_SECRET`
- reachable `apps/supervisor-api` when `PUBLIC_CHAT_MODE=live`
- 能解析 Supabase session pooler host

## Success Condition

计划完成时，`apps/public-consumer-chat` 应满足：

- 核心组件树已按 reference 组件系统完成适配
- 不再依赖旧 sidebar / old shell 思维模型
- `/login`、`/chat`、`/chat/:conversationId` 的视觉与交互明显接近 reference chatbot
- 当前 app 仍完全遵守 04.7 的正式方向与边界约束
