<domain>
## Phase Boundary

Phase 10.1 is a narrow follow-up after Phase 10.

Its job is not to reopen retrieval or expand crawl scope. Its job is to close the current worktree truth cleanly:

- make the current `muc_public_pages` stable-reference-like scope explicit
- freeze which `inventory_only` documents remain in current truth only for regression/audit
- freeze which current-truth news documents are now a handoff set for a later `fresh_news` surface
- align planning/docs/runbooks so later work no longer treats "current mixed local collection" and "future fresh-news surface" as the same problem

### In Scope

- Repair planning truth drift so Phase 10.1 is explicitly recorded in roadmap/state
- Add or extend machine-checkable repo helpers for the `inventory_only` handoff sets if that improves downstream reuse
- Add repo-tracked docs/runbook references that define the current truth closeout and the future fresh-news handoff boundary
- Update current planning truth so the next official-web workstream is framed as quality improvement within the current fixed scope plus a separate future surface handoff

### Out Of Scope

- Expanding host scope, crawl frontier, or scheduler policy
- Opening `official_web/muc_public_pages` as a default query-enabled collection
- Building the actual `fresh_news` or `news_archive` collection
- Reopening the Phase 10 freshness fail-close contract
- Reclassifying the current `future_fresh_news_surface` pages back into the current release gate

### Success Shape

- The repo has one explicit truth for what the current `muc_public_pages` scope is and is not
- The `8` current-truth news pages now have an explicit handoff boundary for later fresh-news work instead of remaining as vague `inventory_only` leftovers
- Future work can reuse repo-tracked helpers/docs/runbooks without reopening the same current-truth versus fresh-news argument
</domain>

<decisions>
## Implementation Decisions

### Locked by current repo truth
- `official_web/muc_public_pages` remains `offline_preparation` and is not default query-serving truth.
- `release_gate_required` is the only current answer-quality gate subset for the current stable-reference-like scope.
- `retain_inventory_only` stays inside current truth for regression/audit but is not a hidden follow-up gate queue.
- `future_fresh_news_surface` stays in current truth only for regression/local validation and must not be silently promoted back into the current stable-reference gate.

### Locked by Phase 10 closeout
- Freshness-sensitive asks already fail close for the current mixed collection and that contract must remain intact.
- Future fresh-news work depends on explicit publication/fetch metadata and a separate serving surface, not on ad hoc reuse of the current mixed dataset.

### The agent's discretion
- The exact helper/API shape used to expose triage subsets for downstream code/tests
- The exact document/runbook structure used to freeze the fresh-news handoff, as long as it stays repo-tracked and clearly separates current truth from future surface work
</decisions>
