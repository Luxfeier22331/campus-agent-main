## Summary

The user's challenge was valid when raised: the repository alone did not contain real `curriculum_plan` OCR artifacts that proved what curriculum document structure actually looks like after OCR normalization. That changed when a real asset-level provider sample and real document-level `structured.jsonl` samples were added and reviewed. The repo still does not prove a fully frozen curriculum semantic contract across all template variants, but it now does prove the upstream provider-result shape, several cleaning-layer facts, and a sample-backed candidate chunking baseline that was previously speculative.

That means Phase 05.1 still should not freeze the full curriculum chunking semantics yet. It can now safely freeze architecture-level boundaries, ownership, fail-closed expectations, several provider-to-clean normalization rules, and the rule that curriculum chunk semantics stay explicit rather than inheriting handbook defaults implicitly. But exact normalized unit taxonomy across all documents, list/table atomicity below provider-block level, and final token guardrails are still not established phase-wide facts. They remain candidate decisions that require broader structured-sample review than the current sample pack.

The correct update is therefore: use the real provider sample to strengthen curriculum cleaning rules now, but continue to narrow Phase 05.1 to a boundary-and-evidence closure phase until normalized structured outputs are reviewed. If Phase 6 proceeds as if names like `requirement_paragraph` and `requirement_list` are already proven runtime truth, it will still be freezing guesses, not evidence-backed contracts.

**Primary recommendation:** Reframe Phase 05.1 as "freeze what is safe from the real provider sample, require structured-output review before semantic contract freeze," and explicitly downgrade current curriculum unit names to candidate taxonomy only.

### Real provider sample facts now proved

The user provided a real provider artifact for the current derived-bucket path shape:

- `campus-rag-derived/curriculum/sources/pdf/curriculum-plan-2022/2022/<ingest_id>/provider-response.jsonl`

The fetched sample proves the following facts:

- The asset-level `provider-result.jsonl` is not one page per line. It contains `142` JSONL records, each with `5` `layoutParsingResults`, for `710` total page results.
- The provider result is page-layout-first, not curriculum-semantic-first. Each page result contains:
  - `prunedResult.parsing_res_list`
  - provider-generated `markdown.text`
  - layout coordinates / polygons
  - provider block labels such as `text`, `paragraph_title`, `table`, `number`, `figure_title`, `doc_title`, `vision_footnote`, `content`, `image`
- The dominant labels in this real sample are:
  - `text = 2745`
  - `paragraph_title = 1349`
  - `table = 822`
  - `number = 708`
  - `figure_title = 70`
  - `doc_title = 64`
  - `vision_footnote = 29`
  - `content = 4`
- Provider labels are not equivalent to final curriculum semantics:
  - heading-like Chinese section markers appear mostly in `paragraph_title`, but some appear in `text`
  - numbered items appear in both `paragraph_title` and `text`
  - `vision_footnote` includes true remarks and notes, not only ignorable noise
- `table` is already emitted as HTML table content at provider stage and appears heavily across the sample.
- `figure_title` appears adjacent to tables and behaves like table caption text.
- `number` blocks are null-order isolated numerals and align with pagination noise rather than curriculum body semantics.
- `image` and `header_image` blocks in this sample have empty `block_content`; they should not produce text chunks.
- `content` blocks are used for the table-of-contents carryover pages; they should not be mistaken for ordinary body prose.
- `block_order` is available for `text`, `paragraph_title`, `doc_title`, and `content`, but not for `table`, `figure_title`, `number`, `vision_footnote`, `image`, or `footer`. Cleaning logic must therefore preserve original block sequence or spatial adjacency for unordered structural blocks.

   Fact source: runtime profile and roadmap/docs already lock this.

2. Split-manifest logical documents are the pre-chunking boundary.
   Fact source: split-manifest schema and worker tests already enforce one master PDF -> multiple logical documents.

   Fact source: worker tests already prove `provider-result.jsonl`, `structured-full.jsonl`, and per-document `structured.jsonl` are separate outputs.

4. Curriculum chunking must live entirely inside ingestion/data-plane ownership.
   Fact source: repo architecture docs and package guardrails.

   Fact source: current `build_indexable_chunks_from_jsonl(...)` already rejects `curriculum_plan` unless an explicit `chunk_profile` is supplied.

6. Chunk metadata must preserve document provenance and page anchors.
   Safe minimum fields to freeze now: `document_id`, `version_id`, `source_uri`, `anchor.page_start`, `anchor.page_end`, ACL metadata, and split-manifest-derived document identity. These are already consistent with current registries and worker outputs.

7. Phase 05.1 should not decide retrieval collection strategy, supervisor routing, or online serving semantics for curriculum.
   Fact source: roadmap, ADRs, and runtime gating.

8. Provider-result cleaning must operate at `layoutParsingResults` page granularity, not JSONL-line granularity.
   Fact source: the real sample batches 5 page results inside each JSONL line.

9. Provider block labels are normalization hints, not final curriculum semantic units.
   Fact source: the real sample places heading-like and numbered content across both `paragraph_title` and `text`.

10. HTML tables and adjacent figure titles must survive provider-to-clean normalization as first-class structural content.
   Fact source: the real sample emits many curriculum tables as HTML `table` blocks and emits nearby `figure_title` captions.

11. Standalone provider `number` blocks should be treated as pagination noise by default.
   Fact source: the real sample's `number` blocks are isolated numerals with null `block_order` and do not behave like curriculum body content.

12. Provider `vision_footnote` should be preserved as note-like content until downstream normalization decides attachment or chunking.
   Fact source: the real sample includes meaningful notes and remarks in `vision_footnote`; dropping by label would lose content.

13. Empty `image` / `header_image` blocks should not emit text chunks.
   Fact source: these blocks are empty in the real sample and only point to extracted images.

## Cleaning Rules That Should Change Now

The real provider sample is sufficient to tighten the cleaning-layer rules immediately, even though it is still insufficient to freeze final chunk semantics.

1. Update the cleaning contract so the normalizer iterates over each `layoutParsingResults` page entry, not each JSONL line.

2. Treat `prunedResult.parsing_res_list` as the authoritative normalization input.
   Provider `markdown.text` is still useful as a debug artifact, but it is already a transformed view and does not preserve all label-level distinctions.

3. Preserve provider `table` blocks as atomic structural inputs during cleaning.
   Do not flatten them into prose during provider normalization.

4. Merge or associate `figure_title` with the nearest `table` when adjacency is clear.
   This is the real-sample-backed equivalent of the old `campusRag` table-caption preservation rule.

5. Replace any label-only heading logic with label-plus-content heuristics.
   `doc_title` and `paragraph_title` are strong heading candidates, but `text` can still contain heading-like curriculum structure markers.

6. Drop isolated provider `number` blocks from body-text assembly by default.
   Keep page anchor provenance elsewhere if needed, but do not let page numbers become semantic chunk text.

7. Preserve `vision_footnote` as note content rather than dropping it as generic OCR debris.
   Attachment to the nearest table or section can remain a later normalization decision, but silent deletion is no longer justified.

8. Keep `content` blocks separate from normal body prose.
   In this sample they behave like table-of-contents payload, not ordinary curriculum narrative.

## Focused Update: Cleaning Strategy Optimization Only

This update narrows Phase 05.1 to curriculum canonical/source normalization only. It does **not** recommend token budgets or chunk sizing. Those remain deferred until the cleaning contract is frozen and real document-level structured outputs are reviewed.

### Keep As-Is

- Keep `structured-full.jsonl` as the source-of-truth cleaning boundary between provider payload and per-document structured outputs. This already matches the raw-first architecture and the current worker artifact split.
- Keep page-level block preservation in [`curriculum_provider_normalize.py`](../../../packages/ingestion-core/src/campus_ingestion_core/curriculum_provider_normalize.py#L15) through [`curriculum_provider_normalize.py`](../../../packages/ingestion-core/src/campus_ingestion_core/curriculum_provider_normalize.py#L232): `table`, `figure_title`, `vision_footnote`, `content`, `number`, `image`, `footer`, `doc_title`, and `paragraph_title` are preserved as distinct source rows rather than flattened into prose.
- Keep treating provider labels as normalization hints, not final curriculum semantics. The current `text`-can-still-be-heading logic is directionally correct because curriculum headings are visibly mixed across labels in the reviewed artifacts.
- Keep HTML only for actual provider table payloads. The mixed HTML-table vs pipe-table forms in old `campusRag` canonical docs are mostly a legacy presentation inconsistency, not a source-contract requirement.

### Must Optimize Now

1. Freeze caption binding, not caption styling. Old canonical docs show the same semantic role rendered as centered HTML text (`课程清单如下：`) in [国际经济与贸易本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/国际经济与贸易本科人才培养方案.md#L76), plain prose, or bolded pseudo-caption via the legacy formatter in [format_curriculum_plan_docs_clean.py](/home/reptilian/code/campusRag/packages/rag-core/src/campusrag/pipelines/ingest/format_curriculum_plan_docs_clean.py#L208). The breaking issue is not visual inconsistency; it is the lack of a stable `table_caption -> table` association in the normalized source contract.
2. Normalize sibling heading recognition so equivalent section markers produce equivalent structure. The old artifacts show sibling drift such as `## （一） 素质要求` followed by raw prose-only `（二）知识要求` in [中国少数民族语言文学本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/中国少数民族语言文学本科人才培养方案.md#L24) and [中国少数民族语言文学本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/中国少数民族语言文学本科人才培养方案.md#L36). That is consumption-breaking because downstream section recovery becomes hierarchy-dependent on formatting accidents.
3. Add sentence-wrap repair before final source rows are considered canonical prose. The old artifact has a hard line split inside one sentence at [光电科学与工程创新实验班本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/光电科学与工程创新实验班本科人才培养方案.md#L36) and [光电科学与工程创新实验班本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/光电科学与工程创新实验班本科人才培养方案.md#L38). That is not harmless style drift; it changes paragraph truth and can mislead later section/list logic.
4. Bind notes and remarks to their owning structure instead of leaving them as floating paragraphs. The old artifacts show standalone `备注：` blocks separated from the content they qualify in [光电科学与工程创新实验班本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/光电科学与工程创新实验班本科人才培养方案.md#L192). Since the current normalizer already preserves `vision_footnote` as `note`, the missing optimization is attachment semantics, not note retention.
5. Treat table continuation and repeated header rows as structure metadata, not independent narrative rows. Old canonical docs show back-to-back tables for one logical section in [美术学类本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/美术学类本科人才培养方案.md#L130) and [美术学类本科人才培养方案.md](/home/reptilian/code/campusRag/rag-data/canonical/curriculum_plan/docs/美术学类本科人才培养方案.md#L138). If continuation is not explicit in source normalization, later consumers will treat layout spillover as separate semantic units.

### Canonical Contract To Freeze

- Freeze the asset-level source schema around the current row shape in [`curriculum_provider_normalize.py`](../../../packages/ingestion-core/src/campus_ingestion_core/curriculum_provider_normalize.py#L179): `row_type`, `block_role`, `heading_level`, `reading_order`, `bbox`, `text_normalized`, `clean_text`, `html`, `section_hint`, page anchors, and provider provenance remain required fields.
- Freeze that only `row_type="table"` may carry HTML payload. Captions, notes, TOC entries, headings, and paragraphs must expose plain normalized text in `clean_text`, not presentation markup.
- Freeze adjacency/ownership metadata as the next contract addition for cleaning v1: caption-to-table, note-to-owner, and continuation-to-root relationships need explicit fields or deterministic reconstruction rules before any chunk semantics are frozen.
- Freeze that page numbers, empty images, and footers remain preserved at source level for provenance but emit empty `clean_text` and are non-narrative by default.
- Freeze that canonical markdown formatting is non-authoritative. Downstream consumers must depend on structured source rows, not on whether a table is rendered as HTML vs pipe table or whether a caption is centered, bolded, or plain text.

### Risks If Left Unchanged

- Section recovery will remain format-sensitive, so equivalent curriculum sections can diverge into different parents or flat paragraphs depending on OCR punctuation noise rather than document meaning.
- Table captions and notes will continue to float as free text, which makes later retrieval/chunk assembly attribute conditions or remarks to the wrong table or the wrong section.
- Multi-part tables will be over-segmented into separate semantic objects, especially in curriculum sections that spill one logical list across repeated table headers.
- Review effort will keep getting wasted on markdown style cleanup that does not improve ingestion truth, while the actual breaking inconsistencies remain in ownership and attachment semantics.

### Recommended Next Edit Surface

- Primary: [`curriculum_provider_normalize.py`](../../../packages/ingestion-core/src/campus_ingestion_core/curriculum_provider_normalize.py) to add attachment-aware normalization rules while keeping the current source row schema stable.
- Secondary: curriculum-specific tests in [`test_curriculum_provider_normalize.py`](../../../tests/ingestion/test_curriculum_provider_normalize.py) to lock heading parity, sentence-wrap repair, caption attachment, note attachment, and table continuation behavior against real samples.
