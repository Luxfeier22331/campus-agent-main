# Phase 03.2: Source Truth Fan-Out And Attachment Projection - Research

**Researched:** 2026-03-26
**Domain:** Source-truth-first ingestion convergence for handbook-derived downstream projections
**Confidence:** HIGH

Historical note: this research captures the pre-execution problem statement for Phase 03.2. The runtime has since converged onto `handbook_source_projections.py` plus projection-aware replay/cleanup; references below describe the architecture gap as it existed before execution.

## Executive Summary

The repo-local architecture already says the right thing at the raw layer: one raw asset may feed multiple corpora, and raw truth must not be rebound to one collection-specific path. At research time, the implementation was only partially there. `student_handbook` had a canonical raw-first and replayable ingestion path, but downstream `campus_services` outputs were still arriving through a separate bridge lane, and handbook attachments/forms/navigation-like leaves were still represented mostly as cleanup semantics instead of as first-class derived documents.

The planning conclusion is therefore not to add another migration path. It is to converge the existing ingestion system around one stronger invariant:

- consume raw once
- persist canonical source truth once
- declare all downstream projections explicitly
- rebuild from source truth, not from raw re-consumption

This keeps the verified handbook path intact while removing the current architectural debt that would otherwise force future collection work to revisit the same raw source repeatedly.

## Current State Findings

### What is already aligned with the desired design

- `docs/architecture/phase1-ingestion-and-storage-architecture.md` explicitly freezes that raw assets are not organized by corpus because one raw asset may be reused by multiple corpora.
- `docs/architecture/student-handbook-ocr-normalization-strategy.md` already models handbook correctly as `asset-level OCR result -> internal structured source -> multiple logical documents -> document-level units/chunks`.
- `raw_ingestion.py` plus worker runtime rules already persist handbook source-level artifacts (`provider-response.jsonl`, `layout-elements.jsonl`) and document-level artifacts (`canonical.md`, `document-units.jsonl`) from canonical raw provenance.
- `local_rebuild.py` already demonstrates the right rebuild instinct for handbook: replay from persisted provider response instead of re-running OCR/raw onboarding.
- Current handbook cleanup/chunking validation has already established that the source-to-document-to-chunk path is stable enough to stop using chunk cleanup churn as a design blocker.

### What was architecturally wrong before execution

1. **Single-collection consumption bias**
   - Current ingestion orchestration still thinks in terms of one selected `corpus + collection` run.
   - This makes source-truth reuse implicit rather than first-class.

2. **Replay had not yet become projection-aware**
   - Replay was rooted in `student_handbook` source truth, but it had not yet been extended to rebuild all declared downstream projections from that same source.
   - This meant replay was not yet acting as the complete source-truth rebuild boundary for downstream outputs.

3. **`campus_services` still lived on a side lane**
   - The then-existing handbook-derived `campus_services` bridge imported from legacy canonical files and injected handbook-derived documents as migration entries.
   - This created a second ingestion worldview instead of reusing the source-truth-first contract.

4. **Attachments are semantics, not documents**
   - `handbook_cleanup.py` knows appendix/form/navigation-like behavior well enough to influence units and chunking.
   - But those leaves are not yet emitted as stable derived documents with explicit parent/source lineage.

## Risk Assessment

### Main risks

1. **Architectural drift by “just one more migration”**
   - Risk: a new collection is added by duplicating the `campus_services` migration pattern, and the repo ends up with multiple ingestion truths.
   - Mitigation: freeze one projection contract now and require future collection additions to enter through it.

2. **Replay remains non-canonical**
   - Risk: rebuild logic keeps working only for handbook while downstream projections require raw re-consumption or legacy file imports.
   - Mitigation: make “rebuild from source truth” an explicit phase deliverable, not an incidental handbook helper.

3. **Attachment semantics remain trapped inside handbook**
   - Risk: appendix/form/navigation content keeps existing only as handbook cleanup detail, so service-like outputs stay lossy or require one-off extraction code.
   - Mitigation: elevate attachment-bearing or navigation-bearing leaves into explicit derived documents with stable identity and parent linkage.

4. **Boundary leakage into retrieval or supervisor layers**
   - Risk: downstream projections are solved by retrieval-time filtering, collection aliases, or supervisor routing hacks.
   - Mitigation: keep all projection convergence strictly inside ingestion/data-plane code and config.
