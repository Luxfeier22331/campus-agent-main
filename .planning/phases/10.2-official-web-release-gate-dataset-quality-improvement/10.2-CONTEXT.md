# Phase 10.2: Official Web Release Gate Dataset Quality Improvement - Context

**Gathered:** 2026-04-04
**Status:** Ready for execution
**Source:** Derived from Phase 10/10.1 closeout truth, release-gate QC sampling, current official-web cleaning policy, and projection/chunking implementation audit

<domain>
## Phase Boundary

Phase 10.2 is the fixed-scope data-quality follow-up after Phase 10.1.

Its job is not to reopen crawl scope, fresh-news serving, or query enablement. Its job is to make the current `release_gate_required` subset structurally trustworthy:

- repair over-aggregated `article_detail` projection units in the current `11`-document release gate
- keep notice/reference pages answerable from better-shaped units instead of giant merged sections
- add machine-checkable audit truth for this specific failure mode
- verify the repaired shape with replay, sampling, and focused repo tests

### In Scope

- `release_gate_required` only
- `article_detail` source-truth projection and structured-unit batching rules
- official-web chunking audit truth for over-aggregated article sections
- focused retrieval/answer regression checks where notice/reference shaping could regress
- replay/QC closeout for the fixed-scope release candidate

### Out Of Scope

- `retain_inventory_only`
- `future_fresh_news_surface`
- fresh-news implementation or hot-lane design
- crawl expansion, host expansion, scheduler promotion
- default query-serving or runtime-profile changes

### Root Cause

Current QC sampling shows the main blocker is not release plumbing.

The blocker is that `official_web_projection._build_projection_units()` keeps buffering `article_detail` text whenever `unit_type == section_text` and `section_path` stays the same. This collapses long multi-paragraph sections into a single unit for pages such as:

- `学校概况`
- `学校简介`
- `本科培养`
- `研究生培养`
- `博士后`
- `校长强世功接受“统战新语”专访 解读民族团结进步促进法`

This is partially masked later because official-web chunking can split oversized text by line budget, but that still leaves the structured-unit layer too coarse and shifts quality pressure onto retrieval shaping and answer compression.

### Success Shape

- multi-paragraph article sections stop collapsing into one giant `section_text` unit by default
- notice-style pages still keep local `topic/time/location` evidence grouped well enough for current retrieval/answer heuristics
- chunking audit can explicitly name this failure mode instead of only surfacing downstream symptoms
- fixed-scope replay and tests show the repaired shape is stable for the current release gate
</domain>

<decisions>
## Implementation Decisions

### Locked by current repo truth

- Only `release_gate_required` participates in the current answer-quality gate.
- `retain_inventory_only` and `future_fresh_news_surface` remain explicit non-gate boundaries.
- Phase 10 freshness fail-close behavior stays untouched.

### Locked by current cleaning/chunking policy

- `article_detail` chunk intent is “one section or 1-3 continuous paragraphs under one section path”, not “entire page section merged forever”.
- Chunk quality must not depend on silently treating giant merged article units as acceptable truth.

### The agent's discretion

- the exact buffering / flush heuristics used for `article_detail`
- the exact audit issue code and examples shape
- the minimal doc refresh needed to record the repaired release-gate truth
</decisions>
