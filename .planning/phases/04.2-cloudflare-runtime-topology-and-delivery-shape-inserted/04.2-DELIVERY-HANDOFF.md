# Phase 04.2 Delivery Handoff

## What Plan 01 Froze

Plan 01 通过 `docs/architecture/cloudflare-runtime-topology.md` 冻结了以下 topology truth：

- public entry 继续 front `apps/supervisor-api`
- protected panel 继续作为 separate future `apps/` runtime origin
- public/protected surface 即使未来共享 hosting substrate，也不能共享 exposure model、runtime boundary 或 rollback unit
- topology 和 delivery ownership 到 `apps/*` 为止，不能下沉进 `packages/*`

## Delivery Ownership Table

| Concern | Cloudflare owns | Repo-owned runtime owns | Explicitly deferred |
| --- | --- | --- | --- |
| hostname exposure | public/protected hostname and edge visibility | n/a | final implementation details |
| secrets/config | edge-side protection/config outside runtime origin | runtime-origin environment/config loading | concrete secret store and rollout mechanism |
| origin route | edge route selection to the correct origin | request handling after origin selection | public-entry integration details for 04.3 |
| health/readiness seam | edge-to-origin reachability gate | runtime-level health/readiness contract | concrete health endpoints and probes |
| rollback unit | surface-to-origin route rollback at edge | origin-side rollback boundary per app shell | exact deployment workflow and tooling |

## Planning Rules For 04.3 And 04.4

### 04.3 must preserve

- public entry still fronts `apps/supervisor-api`
- forwarding/integration work remains runtime-scoped
- edge integration details do not introduce provider types into `packages/*`

### 04.4 must preserve

- protected panel remains a separate future origin under `apps/`
- panel runtime shell consumes runtime APIs only
- panel runtime shape does not become `apps/supervisor-api` hidden admin mode

## Explicit Deferred List

The following remain deferred after 04.2:

- Cloudflare config implementation
- header/trace forwarding specifics
- cache/timeout/streaming edge behavior
- concrete secret manager or deployment mechanism
- panel UI/routes/pages and panel business workflows
- `SupervisorRequest.actor`
- retrieval ACL
- audit / trace closure

## Minimal Checklist For Later Planning

- [ ] topology stays anchored on `apps/*`
- [ ] public entry continues to front `apps/supervisor-api`
- [ ] protected panel stays a separate future origin
- [ ] health/readiness is defined as a runtime seam, not a package concern
- [ ] rollback can happen by surface/origin boundary
- [ ] no delivery concern is pushed into `packages/*`
- [ ] no 04.3/04.4 artifact consumes Phase 5 actor/ACL/audit scope

## Summary

04.2 已经把 Cloudflare 到 repo runtime 的 topology 和 delivery ownership 收口完成。后续 04.3 应只补 public entry edge integration contract，04.4 应只补 protected panel runtime shell 形态；两者都不应重新讨论 public/protected surface 是否应该共享 origin，也不应把 runtime delivery concern 下沉进 `packages/*`。
