## Target Workflow

```text
transport schedule baseline
-> notice change set
-> grounding verdict / evidence bundle
-> supervisor finalization
```

The workflow stays admitted only when each step is backed by bounded repo-owned artifacts:

- `schedule_baseline`: produced from the current transport schedule read model.
- `notice_change_set`: produced from admitted notice consumption projection/read model and current
  transport operational notice truth, not raw notices at query time.
- `evidence_bundle` / `grounding_verdict`: produced from bounded artifacts and source refs when
  the answer needs cross-source grounding.
- final answer: generated by supervisor finalization, with artifact usage visible in workflow
  trace.
