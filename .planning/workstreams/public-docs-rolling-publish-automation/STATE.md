## Current Slice

- Phase 6 is implemented locally and the workstream is complete.
- Scope is release orchestration for `apps/public-docs`, not docs shell /
  reader UI.
- Prod schedule target is Shanghai time `00:00 / 06:00 / 12:00 / 18:00`,
  executed by the controlled runner at UTC cron `7 4,10,16,22 * * *`.
- Ingest side owns manifest generation and publication.
- Deployment automation consumes current manifest pointer and immutable
  manifest assets; it does not scan object storage to decide public subset.
- Deploy execution belongs in CI / controlled runner / operator machine, not in
  Worker runtime.
- Changed manifest now gates ordered build, build-output smoke, deploy config
  verify and Wrangler deploy through an injectable command runner.
- Failed candidates can be retried only when the current manifest digest still
  matches and no newer deployed release superseded the failure.
- Rollback uses Cloudflare Worker version id and appends `rolled_back` ledger
  records without mutating old records.
- Optional deploy-hook nudger is only an immediate trigger. It validates
  `surface=public_docs`, environment and optional shared secret, ignores payload
  release truth, and then either runs the existing forced pipeline with
  `trigger=hook` or dispatches a Cloudflare Deploy Hook URL.
- Production acceptance evidence is generated by an injectable local harness and
  covers 11 scenarios without real Cloudflare or object store side effects.
- Production rolling publish now has a GitHub Actions controlled runner with
  explicit enable/dry-run gates, persisted object-store release ledger and
  uploaded evidence artifacts.
