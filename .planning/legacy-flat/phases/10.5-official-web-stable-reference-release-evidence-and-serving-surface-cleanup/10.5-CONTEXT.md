## Implementation Decisions

### Locked by current architecture
- `muc_public_pages` remains the mixed bridge; it still needs stable-reference-like retrieval/answer behavior until the later split phases finish.
- `stable_reference` remains `offline_preparation`; physical release evidence does not imply query-open or alias publish.
- The correct abstraction point is serving-surface semantics, not literal collection-name branching inside retrieval or specialist logic.

### Locked by current worktree truth
- Real bootstrap replay output already exists at `/tmp/official-web-qc-20260401-batch-d-clean-subset-projection-stable-reference-v1`.
- Real scope-specific import already produced 9 routed `stable_reference` documents.
- Real registry-backed release already exists as `official_web_stable_reference__r20260404_204033`.

### The agent's discretion
- Whether the new helper should prefer runtime-profile `serving_surface` or collection-name fallback when tests construct synthetic profiles
- How much eval code to generalize now without reopening mixed release-gate fixtures
</decisions>
