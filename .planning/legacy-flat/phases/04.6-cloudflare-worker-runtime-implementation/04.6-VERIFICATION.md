# Phase 04.6 Verification

## Goal

Implement the Route-based Cloudflare Worker public-entry runtime shell in front of `apps/supervisor-api`, preserving the frozen entry modes, trusted-origin seam, and alternate-entry closure without absorbing Phase 5 actor, ACL, or audit scope.

## Must-Haves

- A dedicated Worker runtime shell exists under `apps/*` and uses Route-based config with `workers_dev = false` and `preview_urls = false`.
- The Worker enforces exactly `authenticated-only` and `anonymous-enabled`, fails closed on missing auth/config, and forwards only to `ORIGIN_BASE_URL` with `x-worker-origin-auth`.
- `apps/supervisor-api` supports an explicit `trusted-worker` mode that rejects missing or invalid origin auth and keeps actor context runtime-owned.
- The implementation stays within `apps/*` and `.env`/tests without leaking Cloudflare semantics into `packages/*`.
