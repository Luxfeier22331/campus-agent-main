# Plan 1003-01: 冻结新闻面 opening policy 与 runtime-profile criteria

## Objective

把 `official_web/fresh_news` 与 `official_web/news_archive` 的 opening policy、runtime-profile 条件和默认关闭姿态写成 machine-checkable serving contract。

## Scope

- `docs/architecture/official-web-serving-and-news-retrieval-strategy.md`
- `docs/architecture/official-web-architecture.md`
- runtime profile / config docs
- `official_web` 独立 worktree 的 policy handoff

## Tasks

1. 固定 `stable_reference`、`fresh_news`、`news_archive` 三个 surface 的默认 consumer posture。
2. 明确 `fresh_news` opening 的硬门槛：
   - `article_detail` 主证据
   - 时间元数据覆盖
   - duplicate collapse
   - freshness gate
3. 明确 `news_archive` 只服务显式历史查询 / operator / 分析 / 评测。
4. 把“seed baseline 不等于 runtime opening approval”写入 policy truth。
5. 确认这些规则只进入独立 official-web worktree 的前向执行面，不在当前分支直接开 query surface。

## Verification

- docs review against `1003-RESEARCH.md`
- runtime-profile/config review against current `offline_preparation` truth
- terminology review for `stable_reference` / `fresh_news` / `news_archive`

## Acceptance Criteria

- repo 级 policy 明确禁止把 news surfaces 混回默认 `stable_reference`。
- `fresh_news` opening criteria 可供后续 config/eval 直接消费。
- `news_archive` 非默认消费姿态被写死，不再作为模糊的“以后也许可答”集合。

## Out Of Scope

- 直接开放 `fresh_news` / `news_archive`
- browser/live search provider 选型
- crawl 扩面
