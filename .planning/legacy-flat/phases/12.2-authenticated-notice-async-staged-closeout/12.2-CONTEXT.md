# Phase 12.2 Context: Authenticated Notice Async Staged Closeout

**Gathered:** 2026-04-04
**Status:** Planning and research
**Source:** Phase 12/12.1 docs, existing closeout runner, authenticated notice architecture docs, current `run-14` execution data

## Phase Intent
Phase 12.2 rearchitects authenticated notice historical closeout into an *async staged data-plane pipeline*: fixed input => async shard executors => staging tables + artifacts => single promoter that commits canonical `campus_notices/internal_notice`. This replaces the cumulative checkpoint rerun model with deterministic promotion.

## Execution Boundaries
- `apps/authenticated-notice-collector` stays out of registry/chunk ownership.
- `apps/ingestion-worker` runs orchestrator CLI + run-state commands.
- `packages/ingestion-core` owns planner, async executor, promoter, verification, staging schema, and object-store keys.
- Only one promoter ever writes to canonical `campus_notices/internal_notice`; shards never mutate the final document scope.

## Observability Goals
- `closeout_runs`, `closeout_shards`, `closeout_milestones`, and staging tables provide durable state.
- Async heartbeats + milestone summaries live in `campus_notices/operations/authenticated-notice-closeout/{run_id}`.
