# Phase 12.1: Authenticated Notice Historical Backfill Closeout - Context

**Gathered:** 2026-04-04
**Status:** Planning and implementation started; historical replay is proven through `240`, while the full `6694` backfill and closeout evidence remain open
**Source:** Distilled from authenticated-notice architecture docs, Phase 12 closeout docs, current worker/import code, and the historical export artifacts under `/home/reptilian/code/rag-data/muc-notice-collector/runtime/exports`

<domain>
## Phase Boundary

Phase `12.1` exists to close the historical authenticated-notice content set as a data-plane execution stream.

This phase is about:

- freezing the full historical input set that should be treated as the current closeout target
- providing a repo-owned orchestration path for staged backfill, full replay, rerun, and reconciliation
- producing stable closeout evidence for `campus_notices/internal_notice`

This phase does **not** reopen:

- live portal re-access
- scheduled/incremental collector runs
- authenticated-notice control-plane ownership on `app-api`
- query-serving promotion for `internal_notice`
- collector-side registry/chunk/index ownership

</domain>

<decisions>
## Locked Architecture Posture

- `authenticated_notice_portal` remains a dedicated `source_channel`, not an `official_web` subtype.
- `notice` remains the canonical source unit.
- historical closeout still writes only to `capture/ -> provider/ -> source-truth/ -> document import` seams.
- `campus_notices/internal_notice` remains `restricted + offline_preparation` through this phase.
- object storage semantics remain `S3-compatible object storage` even when repo-local MinIO is the operational substrate.

## Current Execution Truth

- Phase 12 already proved bounded replay through:
  - `2` notices
  - `10` notices
  - `50` notices
  - `240` notices
- `run-2` historical bundle is the currently verified bounded replay substrate:
  - bundle: `/home/reptilian/code/rag-data/muc-notice-collector/runtime/exports/notices-bundle-20260403-run-2.json`
  - manifest: `/home/reptilian/code/rag-data/muc-notice-collector/runtime/exports/export-manifest-20260403-run-2.json`
  - count: `240`
- `run-14` is the current full historical backfill substrate:
  - bundle: `/home/reptilian/code/rag-data/muc-notice-collector/runtime/exports/notices-bundle-20260403-run-14.json`
  - manifest: `/home/reptilian/code/rag-data/muc-notice-collector/runtime/exports/export-manifest-20260403-run-14.json`
  - count: `6694`
- replay no longer stalls on repo-local MinIO zero-byte writes because `S3ObjectStoreWriter` isolates zero-byte payloads to a one-shot client.
- staged replay for this phase must use cumulative prefix slices only; disjoint shards are unsafe because authenticated notice import refreshes the whole document scope.

## Current Gaps

- the repo does not yet have a dedicated closeout runner for authenticated-notice historical backfill
- full-bundle execution, rerun, and reconciliation are still manual/operator-driven rather than repo-owned
- there is no single repo-owned closeout artifact that freezes:
  - input bundle/manifest
  - checkpoint summaries
  - rerun evidence
  - registry reconciliation results
- `6694` full backfill remains deferred in docs because the repo has not yet produced that final closeout evidence package

## Explicitly Rejected Directions

- do not treat historical bundle closeout as permission to open query-serving
- do not treat export JSON, SQLite, or local path layout as canonical long-term truth
- do not move collector responsibilities into `apps/ingestion-worker`
- do not make this phase depend on current live portal access

</decisions>

<workstreams>
## Proposed Workstreams

### Workstream 1: Freeze the full historical input set

- record the exact bundle/manifest pair that defines the current closeout target
- derive and persist the expected notice count and checkpoint sizes
- prevent later execution from silently drifting to a different export

### Workstream 2: Add a repo-owned closeout runner

- orchestrate staged replay checkpoints and final rerun from one CLI
- persist per-checkpoint summaries and a final closeout summary
- make closeout resumable rather than relying on ad hoc shell history

### Workstream 3: Add reconciliation and closeout evidence

- compare expected notice IDs and raw asset IDs against registry state
- keep document reconciliation strict while treating raw asset scope history as coverage-only
- surface missing document/source-truth evidence explicitly
- produce a closeout artifact set that future operators can trust

</workstreams>
