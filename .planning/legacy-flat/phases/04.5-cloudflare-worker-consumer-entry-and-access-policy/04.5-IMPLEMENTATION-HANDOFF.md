# Phase 04.5 Implementation Handoff

## What Plan 01 Froze

Plan 01 通过 `docs/architecture/cloudflare-worker-consumer-entry-access-policy.md` 冻结了以下 04.5 truth：

- public answer hostname 的唯一 public consumer entry code path 是 `public hostname -> Cloudflare Route -> Cloudflare Worker -> trusted origin/apps/supervisor-api`
- Worker 入口只允许两种模式：`authenticated-only` 与 `anonymous-enabled`
- 匿名能力由 explicit Worker flag 控制，例如 `WORKER_ALLOW_ANONYMOUS`
- `Cf-Access-Jwt-Assertion` 只用于 Worker-side Access JWT validation，不等于应用层 actor semantics
- Worker-to-origin trust 通过 runtime secret/header contract 维持，例如 `X-Worker-Origin-Auth`
- `workers_dev = false` 与 `preview_urls = false` 是 alternate public entry closure 规则
- 04.5 不完成 `SupervisorRequest.actor`、retrieval ACL、audit closure 或 Worker package implementation

## Implementation Rules Table

| Concern | Frozen rule | Still deferred |
| --- | --- | --- |
| public entry shape | `public hostname -> Route -> Worker -> trusted origin/apps/supervisor-api` | concrete hostname/zone wiring and route pattern |
| entry mode | exactly `authenticated-only` or `anonymous-enabled` via `WORKER_ALLOW_ANONYMOUS` | final auth-provider choice and product auth UX |
| Access auth | `authenticated-only` mode validates `Cf-Access-Jwt-Assertion` in Worker | exact JWK/AUD wiring and vendor SDK detail |
| anonymous mode | anonymous is an explicit Worker runtime policy, not Access `Bypass` | later product copy and anonymous quota/rate behavior |
| origin trust | Worker forwards only with trusted `X-Worker-Origin-Auth` material | exact secret rotation and private-network topology |
| runtime context | Worker may project request-id/trace/runtime mode facts only | final `SupervisorRequest.actor` mapping |
| alternate public entry | `workers_dev = false` and `preview_urls = false` unless separately protected later | any future exception process |
| governance scope | Phase 5 still owns actor, ACL, and audit closure | Phase 5 implementation |

## Rules That Must Survive Implementation

- public entry 继续只 front `apps/supervisor-api`
- Worker continues to act as public consumer-entry shell, not as edge orchestrator
- Worker/projected identity must not be treated as final `SupervisorRequest.actor`
- no Worker concern is pushed into `packages/*`
- no implementation note may claim to finish retrieval ACL or audit closure
- anonymous mode must remain explicit and reviewable, not hidden behind infrastructure loopholes
- direct origin exposure must remain disallowed

## Fail-Closed Matrix

| Condition | Required behavior |
| --- | --- |
| `authenticated-only` selected but Access/JWT config missing | Worker returns 401/403 and does not forward |
| `Cf-Access-Jwt-Assertion` missing or invalid | Worker returns 401/403 and does not forward |
| `WORKER_ALLOW_ANONYMOUS` unset while anonymous mode required | Worker returns 403 and does not forward |
| contradictory mode flags or ambiguous policy state | Worker returns 403 and does not forward |
| Worker origin secret missing | Worker returns 503/403 and does not forward |
| origin request missing `X-Worker-Origin-Auth` | origin returns 401/403 and does not fabricate fallback identity |
| origin is reachable without trusted Worker path | deployment is considered invalid and must be corrected before public rollout |

## Explicit Deferred List

- `SupervisorRequest.actor`

## Summary

04.5 把 Worker public consumer-entry 和 access-policy seam 收口完成。后续真实实现只能围绕 `public hostname -> Route -> Worker -> trusted origin/apps/supervisor-api` 这条 runtime path 落地，继续保持 fail-closed，并且不得把边缘身份、匿名开关或 origin trust 误写成 `packages/*` contract 或 Phase 5 已完成事项。
