# Plan 16-02: 扩展双渠道 compare 与 adjudication 证据

## Objective

把现有 sidecar compare lane 从“生成两份输出”升级成“能支撑路由决策的 adjudication evidence”。

## Tasks

1. 扩展 compare output schema，记录：
   - provider hard failure
   - empty output
   - baseline/candidate availability
   - structure/noise-oriented summary
2. 定义 compare trigger：
   - 资产类型不确定
   - 已知 provider failure family
   - tranche validation sampling
   - 高价值复杂表格/长 PDF
3. 冻结 winner-selection 规则，禁止仅以 `plain_text_length` 做 canonical winner。
4. 补 operator-facing compare evidence 文档与 sample review 模板，确保后续 tranche decision 可回放。

## Verification

- focused tests for compare worker CLI and compare core output
- sample compare reruns on repeated-failure PDF and repeated-false-negative table image
- review of compare output against current assessment notes

## Acceptance Criteria

- compare lane 能区分“provider 挂了”“provider 成功但空输出”“provider 成功但结构差”
- route decision 所需的 adjudication 信息可被稳定重复消费
- compare lane 仍是 sidecar / routing evidence，不会直接写成 downstream canonical truth
