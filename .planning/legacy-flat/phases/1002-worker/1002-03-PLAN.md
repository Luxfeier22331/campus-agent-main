# Plan 1002-03: 固定 release-scoped post-deploy evidence

## Objective

把 staging 发布后的 smoke / observability 验收从“能用就行”收口为 release-scoped evidence contract，确保每次 deploy 都可追溯。

## Scope

- `docs/runbooks/worker-observability-smoke-runbook.md`
- artifact template / evidence directory convention
- `public-chat-web -> app-api` trace
- `protected-panel-web -> app-api` trace
- `app-api` runtime event evidence

## Tasks

1. 固定 release-scoped artifact 目录命名与最小文件集合。
2. 明确每次 deploy 后必须保留的 evidence：
   - chat trace
   - panel trace
   - app-api runtime event
   - release / environment / timestamp
3. 固定 canonical smoke identity 与 operator identity 使用规则。
4. 把 release identity 写入 observability smoke artifact contract。
5. 更新 runbook 与模板，明确 `/readyz=200` 不是 closeout。
6. 为后续回归提供 artifact checklist，避免 evidence-only 项再次散落成 backlog 噪音。

## Verification

- runbook/doc review against `docs/architecture/runtime-delivery-and-release-hardening-architecture.md`
- 现有 observability 查询脚本可生成与 release identity 对齐的 artifact
- staging smoke checklist review

## Acceptance Criteria

- 发布完成的定义包含真实 trace / runtime event evidence，而不是只有 deploy success。
- evidence artifact 以 `timestamp + environment + release` 收口。
- smoke identity 与 operator identity 的使用规则在 runbook 中稳定可复用。

## Out Of Scope

- 浏览器截图内容标准化
- 具体 staging 人工操作窗口安排
- production evidence retention policy
