# Phase 04.3: Public Entry Edge Integration Contract - Context

**Gathered:** 2026-03-25
**Status:** Ready for planning
**Source:** Derived from the inserted roadmap phase, Phase 04.1/04.2 architecture outputs, and current planning/state constraints

<domain>
## Phase Boundary

Phase 04.3 freezes the runtime-facing integration contract between Cloudflare public entry and `apps/supervisor-api`.

The scope is to make the public-entry contract explicit for:

- request forwarding expectations
- request-id / trace propagation expectations
- cache, timeout, body-size, and streaming boundary expectations
- health/readiness behavior at the public runtime seam

This phase does not implement Cloudflare configuration or application behavior. It exists to make the edge-to-runtime contract explicit while the mainline query path remains blocked.

</domain>

<decisions>
## Implementation Decisions

### Locked by roadmap and prior phases
- Public entry still fronts `apps/supervisor-api`.
- Public entry remains runtime-scoped, not package-scoped.
- Edge/provider-specific concerns must stop at `apps/*` and must not leak into `packages/*`.
- Health/readiness is a runtime seam, not a package concern.
- Phase 5 still owns `SupervisorRequest.actor`, retrieval ACL, and audit closure.

### Locked phase intent for 04.3
- The public entry contract must define what Cloudflare may forward, preserve, or constrain before the request reaches `apps/supervisor-api`.
- The contract must state what the runtime origin can assume about request IDs, traces, timeout budgets, cache expectations, body-size expectations, and streaming behavior.
- The contract must remain provider-aware at the edge while avoiding provider types in core packages.

### Explicit non-goals
- Do not implement Cloudflare rules, workers, routes, or config.
- Do not define app-layer auth, actor propagation, retrieval ACL, or audit sink behavior.
- Do not change `packages/contracts`, `packages/supervisor-core`, `packages/rag-specialist`, or retrieval/data-plane packages.
- Do not define panel runtime shell behavior; that belongs to 04.4.

### The agent's Discretion
- Exact decomposition into one canonical contract doc plus one concise implementation/handoff note, or similar small artifact set.
- Exact naming for request-id, trace context, timeout budget, and streaming boundary, as long as the terminology stays at the runtime boundary.

</decisions>

<specifics>
## Specific Ideas

- Treat 04.3 as the public-entry equivalent of an ingress contract note, not an implementation phase.
- Make request-forwarding and runtime assumptions explicit enough that later implementation does not need to guess about headers, trace propagation, body limits, timeout budget, cache semantics, or streaming behavior.
- Keep all contract language pinned to `Cloudflare public entry -> apps/supervisor-api` and stop before package semantics.

</specifics>
