# Phase 04.1 to Phase 5 Handoff

## What Phase 04.1 Froze

### Plan 01

`docs/architecture/cloudflare-public-entry-boundary.md` 冻结了 public entry boundary：

- Cloudflare 位于 `apps/supervisor-api` 之前，负责 edge/control boundary。
- public entry 与 protected internal panel 采用 two-surface split。
- Cloudflare 不拥有 supervisor routing、specialist delegation 或 retrieval semantics。

### Plan 02

`docs/architecture/product-runtime-architecture.md` 冻结了 protected internal panel boundary：

- panel 非公网，non-public by default，default-deny / fail-closed。
- panel 后续如果实现，位于 `apps/`，不是 `apps/supervisor-api` 的隐藏模式。
- panel 只能通过 runtime APIs 交互，不能绕过 supervisor-facing boundary，也不能直连 `packages/*`。

## Explicit Deferred List

以下内容在 04.1 明确 deferred，不在本 phase 内解决：

- 将外层访问身份映射进 `SupervisorRequest.actor`
- retrieval-time ACL filtering
- audit / trace expansion、记录归属与下游投影
- panel-side business workflows、写操作、审批或 HITL
- 具体 runtime/framework choice
- 任何修改 `apps/supervisor-api` 之外 public entry shape 的实现工作
- 任何 `packages/*` contract、retrieval 或 specialist 语义变更

## Responsibility Matrix

| Concern | Frozen in 04.1 | Still owned by Phase 5 or later |
| --- | --- | --- |
| Public entry hostname and edge protection | Cloudflare fronts `apps/supervisor-api` | n/a |
| Protected internal panel hostname and outer protection | Cloudflare-protected separate surface | n/a |
| Cloudflare access identity | Outer access identity only | Does not replace app-level `SupervisorRequest.actor` |
| `SupervisorRequest.actor` | deferred | Phase 5 |
| Retrieval ACL | deferred | Phase 5 |
| Audit / trace ownership | deferred | Phase 5 |
| Panel business semantics | deferred | Later panel implementation under `apps/` |
| runtime/framework decision | deferred | Later implementation phase |
| `packages/*` boundary changes | not authorized | Out of scope for 04.1 |

## Separation Rules That Must Survive

- public entry 必须继续位于 `apps/supervisor-api` 之前，而不是把 Cloudflare 变成 edge orchestrator。
- protected internal panel 必须继续属于 `apps/` runtime boundary。
- Cloudflare protection 不能被解释为已经满足 authorization、ACL 或 audit closure。
- `apps/` 负责 runtime/framework integration；`packages/*` 继续保持能力边界。

## Minimal Implementation Checklist For Phase 5

- [ ] public entry 继续 front `apps/supervisor-api`
- [ ] panel work stays under `apps/`
- [ ] `SupervisorRequest.actor` mapping is explicit and typed
- [ ] retrieval ACL semantics are enforced before evidence return
- [ ] audit / trace fields cover route, actor, status, and cited/evidence identifiers
- [ ] Cloudflare protection is treated as upstream access control, not as app-level authorization completion
- [ ] no implementation change reopens `packages/*` boundaries without a new accepted design decision

## Design Constraints For Later Work

后续实现必须继续尊重：

- Plan 01 与 Plan 02 是 boundary freeze，不是 provider-specific implementation script。
- `apps/supervisor-api` 与任何未来 panel app 都只是 runtime/framework shell。
- 04.1 没有授权把 Cloudflare、panel access provider、ACL rule engine 或 audit sink 类型泄漏到 `packages/contracts`。

## Summary

Phase 04.1 已经把 Cloudflare public entry 和 protected internal panel 的边界冻结完成；Phase 5 应只补 application-layer actor、ACL 和 audit closure，不应重新讨论 public entry 应不应该绕开 `apps/supervisor-api`，也不应把 panel 做成 `packages/*` 的直连入口。
