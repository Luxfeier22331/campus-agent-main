# 决策笔记工作流

先读 [笔记 README](../../notes/README.md) 的分类、格式和归档规则；本 Skill 负责操作顺序，
规则和命令示例由 README 维护，不把范围扩展到当前任务之外。

1. 按模块名、行为和关键词搜索活动笔记：
   `rg --hidden --glob '!.agents/notes/archived/**' '关键词' .agents/notes/`。
   `.rgignore` 默认排除归档；追查历史时显式搜索 `.agents/notes/archived/`，不据此更新归档。
   已有 owner 优先就地更新；部分取代保留有效范围并互链，理由翻转才新建笔记并关联旧决策。
2. 新想法写 proposed，实施后随代码转 implemented；被否决的提案转 rejected 并说明原因。
   从 [模板目录](../../notes/templates/) 选择对应模板，填写真实理由与备选，不留空节或占位符。
   提案写清可观察的验收标准和风险；实施后按实际结果改写决策与后果，保留必要验证及覆盖缺口。
   拒绝时保留原提案与备选，只追加否决理由；具体章节要求由 README 维护。
3. 按 README 的未来指导价值规则处理旧篇：有指导价值则保持活动；完全合并须先转移独有内容
   并修复入站链接；低指导价值的 implemented 历史才归档。不能仅因被取代就归档或删除。
   归档保留原状态和正文，已有归档不再编辑；不批量清理迁移笔记。
4. 遇到真实故障时按[复盘入口](../../../docs/postmortem/README.md)判断是否需要事故复盘。
   故障经过与漏检原因放复盘，长期选择及其理由留在决策笔记，两者互链。
5. 运行 `pnpm docs:check`；需要观察引用时显式运行 `pnpm docs:notes:anchors`。
   informational 不等于缺陷；只有实际读者需要决策理由时才补 owner 链接。

纯排版、错别字、依赖补丁、不改变行为的机械重命名和单模块内自明的小修复豁免。
