# Agent Note: 通知标签体系重设计与分类边界

Status: proposed

## 背景

现有分类体系（v1，15 类）存在结构性问题：`unclassified` 是无意义负空间（132 条混合条目）；`campus_news` 是负向兜底（27.7% 残差，吸收已完成业务事件）；类别间 42x 粒度失衡；跨域重叠（科研+采购 411 条、国际+竞赛 32 条）。旧的 Jev 决策模型方案（14 类决策选项、`unclassified` 低置信标记、39 条规则揉进 criteria）全部作废，决策成本高于重新设计；作废的是分类口径，Jev 模型本身仍用于新体系的试标（第 6 节）。

本提案重设标签体系，并把外部分流出去。取代 [通知分类协议收敛到单一 owner](../../implemented/architecture/2026-10-20-notice-classifier-protocol-owner.md) 中"后续：Jev 决策模型接入"一段描述的分类语义（14 类选项、低置信 unclassified、39 条规则揉进 criteria）；该协议 owner 收敛本身仍有效。

## 提案

### 1. 分类边界：内部分类，外部不分类

分类只服务于站内可操作的通知（读者能在站内完成报名/查结果/参与）。据此分层：

- **内部通知**（学校门户，3375 条）：分类为 category + status，双字段一次调用输出。
- **外部通知**（微信 3221 / 政府采购网 438 / 校内子站 525）：不分类，只显示来源。

支撑事实：外部通知在库中无正文（`notices_external_content_check` 强制 `is_external` 时 content 为 NULL），只有标题 + URL；详情页与图片接口早已 `NOT is_external` 硬排除，产品上外部本就是"点出去看"。为无站内消费方的外链打标是纯成本。

先前"外部野鸡小比赛 → news"的规则（基于外部也分类的前提）随本边界自动失效，不再需要定义野鸡与否的边界。

### 2. 双字段：category + status（正交，一次调用输出两个字段）

**category = 读者能做什么**（15 类，全正向定义）：

- 可参与：procurement / competition / lecture_forum / training / application / recruitment / international
- 可查：selection_result / examination
- 需知：service_info / teaching_schedule / activity / news
- 需办理：**affairs**（注册、报送、录入、审核、认定、信息修改、离校手续等具体事务）
- 组织内部：governance（党务、党建、纪检、团务和单位内部行政工作）

`affairs` 是本次新增的第 14 类。v1 里这类通知散在 teaching_affairs（620）、student_affairs（231）、research_affairs（154）；v2 拆散后被迫塞进 governance 和 service_info，正是这两个类边界长期打架的根因。语料中事务办理类约 208 条，与 application 重叠仅 1 条、与设施类重叠 2 条，边界干净。`service_info` 因此收敛为纯设施与服务状态（开放关闭、停水停电、门诊、开放时间、服务指南），读者只需要知道、不需要办事。

`teaching_schedule` 是 0.2.0 新增的第 15 类，收教学日程与开课安排：校历、课表、本（预）科与研究生课程安排和排课、做好新学期教学工作、网络教学平台与微专业开课、教学周安排、节假日课程调整、停止开课、上下课时间。读者同样只需要知道，但这是师生会主动查看的教学日程，不是基础设施；此前课程调整挂在 service_info，排课与新学期教学工作的部署挂在 governance，前者让 service_info 不再只是设施，后者把学生会主动看的内容混进党务与单位行政。语料中共 50 条，全部由车道 5 规则判定。

**status = 事件所处阶段**（3 值，与 category 正交，不反向改类）：

- upcoming：未发生或进行中，可报名/参与
- completed：已发生，有结果或回顾
- static：持续有效，无时间性

### 3. 时间修正策略：A + C

需求：用户要知道哪些还没发生、哪些已结束。同一事件会出现"报名通知"（upcoming）与"获奖名单"（completed）两条。

- **A（主）**：status 严格由标题语义决定，保持可审计、与"分类只依据标题"一致。
- **C（补）**：展示层对"发布很久仍标 upcoming"的条目给时间软信号降噪，不改标签。生产接入暂不实现（第 7 节）。
- **B 不引入**：事件串接 + 回溯修改未来允许，但本次不做——校园语料"第X届"年度活动极多，名称匹配误伤面大。

### 4. 流合同：外部整体进"校园动态"

现状两个流靠 category 值路由：通知 = `category <> 'campus_news'`，校园动态 = `category = 'campus_news'`。外部不分类后 `NULL <> 'campus_news'` 不成立，须显式改写：

- **通知** = `NOT is_external AND category <> 'news'` → 纯内部业务通知。
- **校园动态** = `category = 'news' OR is_external` → 内部新闻 + 全部外部外链。

外部在分类维度统一为"无类别"，任何分类筛选不命中外部。这与"不显示分类只显示来源"是同一个决定的两面。

### 5. 判定规则形态（替换 39 条关键词规则）

先按 `notice_type`（来源门户栏目）分流，再分别产出标签。`notice_type` 表达的是形式（通知/公示/报道），不是主题，因此不直接映射 category；但标题里信号足够强的条目，关键词加形式先验已能稳定给出两个字段，这部分走规则，其余走模型。规则可以随语料扩展和更新，只要读者视角下合理。

| 车道 | 范围 | 内部条数 | 规则产出 | 转模型 |
| --- | --- | ---: | ---: | ---: |
| 0 | 留学（跨栏目，最先匹配） | 155 | 155 | 0 |
| 1 | 公示公告 | 433 | 430 | 3 |
| 2 | 学术信息 | 80 | 72 | 8 |
| 3 | 活动报道 | 380 | 380 | 0 |
| 4 | 就业信息 | 117 | 116 | 1 |
| 5 | 教学通知、办公通知、学工通知、科研通知 | 2210 | 1486 | 724 |
| 合计 | | 3375 | 2639 | 736 |

条数为留学先行扣除后的各车道余量。车道 1–3 是双模型（gemini / deepseek）分歧最集中的部分：0.1.0 前 300 条的 32 条分歧里有 12 条落在这里，其中 news↔governance 的 7 条全部是活动报道，规则化解决的是准确性。车道 4–5 的规则子集在 0.1.0 样本里双模型几乎一致（45 条中 42 条），规则化主要省调用；例外是设施服务的 status，模型在 upcoming 与 static 间摇摆，由规则定死。

匹配顺序：先车道 0，未命中再按 notice_type 进车道 1–5；车道内按表格顺序，命中即停。关键词按子串匹配，已知误命中用排除词处理（先从标题中剔除排除词再匹配），之后发现新的误命中再补。

通用 status 规则（下文写「按 status 规则」处适用）：含 成功举办/圆满/回顾/顺利 → completed；其余 → upcoming，包括只写活动名称、无时态词的标题，沿用 0.1.0「裸举办默认 upcoming」。

#### 车道 0：留学（跨栏目）

| 条件 | category / status |
| --- | --- |
| 含 留学/访学/交换生/公派/合作奖学金/互换奖学金/留学基金/留基委/Mitacs/国（境）外/境外…项目/赴港澳/赴台/国际组织后备人才/项目宣讲/研学交流/日内瓦/里昂第三大学/国际招生/国际研究生奖学金/澳门高校/赴澳门/联合国，或以「【…宣讲会】」开头 | international |

分布：教学通知 131、活动报道 7、公示公告 5、就业信息 2、办公通知 1。内容是访学选拔与报名、项目宣讲会、公派遴选、候选人与录取名单、资助公示、行前培训、留学咨询。「项目宣讲」补上不带访学字样的境外项目宣讲会（牛津、剑桥、LSE、贝尔法斯特、港理工本升硕）；「研学交流」「日内瓦」补上赴境外研学和联合国总部实地交流的回顾报道；「里昂第三大学」补上标题只写校名的交换项目选拔；「联合国」补上留基委联合国机构宣讲咨询活动的推荐报名与参加报道，与国际组织后备人才同属 international。以「【…宣讲会】」开头的标题全部是国际合作处发布的境外院校项目宣讲（语料 20 条，其余 19 条已被访学、项目宣讲等词命中），补上标题只写校名和主题的 MIT AI+X 项目宣讲。「澳门高校」「赴澳门」补上向澳门高校推荐奖学金硕士研究生、赴澳门城市大学读硕士的通知与拟推荐人选公示，赴港澳台高校读学位与留学同属 international。「国际招生」「国际研究生奖学金」补上读博面试交流会和留基委国际研究生奖学金信息说明会（境外院校来招生、介绍奖学金），双模型试标中两者被判为 examination、lecture_forum 与 international 不一。词表碰不到的相近条目不进本车道：教师「因公临时出国（境）计划」报送、「海外学者系列讲座」、「涉外法治与国际组织」微专业。

留学项目从宣讲、报名、遴选、名单到行前，整个生命周期都归 international，读者按"这是留学的事"查找。因此本车道压过结果公示 → selection_result、行前培训 → training、宣讲会 → lecture_forum。竞赛名单仍归 selection_result：竞赛名单是独立的结果公告，留学名单是项目流程的一环。

排除词：志愿军。

竞赛只认「赛/杯」，不再用 喜报/喜讯/佳绩/获奖/荣获/载誉：这些词同样出现在社会组织评估等级、期刊专栏入选、人才称号、深造率等没有竞赛机制的荣誉报道里，按已定的竞赛收窄口径归 news；真正的比赛喜报标题都带「赛」或「杯」。单字「赛」同时收回电子商务三创赛「选拔赛终审答辩排名赛」这类不含 大赛/比赛/竞赛 的赛程报道。

「来校/来我校」放在培训与实践之前：研修班学员来校参访、实践团来校座谈是接待来访，不是本校组织的培训或实践。「研讨班」是专题培训班，不是学术研讨会。就业指导中心的活动回顾（求职沙龙、简历指导、选岗指导、秋招拍摄）按车道 4 的口径归 recruitment，不按沙龙形式归 lecture_forum。

党建优先：同时命中党建词与业务主题词的标题（约 27 条，如「双带头人教师党支部书记培训班」「党建引领…系列讲座成功举办」）归 news。读者把党建与行政工作的报道一律视为宣传材料，按"是谁办的"压过"办了什么"。党建词表刻意不用单字「党」「团」，避免误命中 出访团、代表团、团结、调研团。

#### 模型车道

模型处理车道 5 转出的部分（办公 300、教学 213、学工 176、科研 35），加上车道 1、2、4 转出的 12 条，共 736 条；`notice_type` 随标题一起传给模型作为形式先验。剩下的主体是标题没有动作词的「关于…的通知」「关于开展…工作的通知」，以及跨多个动作词、需要语义判断主次的标题。

判定文本三层：

1. 每类**正向定义**（读者能做什么 + 典型信号）。
2. **边界裁决**：competition↔selection_result、application↔international、lecture_forum↔activity、training↔lecture_forum、governance↔activity、competition↔activity、activity↔news、governance↔service_info、teaching_schedule 与 service_info / governance / affairs 三组，以及 affairs 与 governance / application / service_info / examination / selection_result / competition 六组。
3. **防泄漏护栏**，核心一条：有竞赛身份且表达流程/结果——哪怕回顾、哪怕邀请赛——归 competition，不归 news。这消灭了 v1 试跑里 competition→news 的泄漏。

governance 与 affairs 的判别：主题是党务、党建、纪检、团务即归 governance，即使标题含「报送」「填报」；其余需要完成具体事务（表单、系统、材料、审核、录入）归 affairs。

模型车道的补充裁决：

- governance 只收需要执行的组织工作（会议通知、部署、检查、党建团务的具体工作）；党建、统战、行政工作办完之后的报道归 news。
- 留学项目的宣讲、报名、遴选、名单、行前全部归 international，与车道 0 一致。
- 面试统一归 examination，除非标题主体是报名流程。
- 就业指导类（职业咨询、求职指导、考公选调分享）归 recruitment；考研、语言、考证课程与培训归 training。
- recruitment 不含津贴；岗位津贴确认归 affairs。
- 简报、纪要、总结类标题即使 notice_type 是通知类，无可执行动作即归 news。
- 标题含 名单/公示/结果/录取 等结果词时，不论 notice_type，status 为 completed。
- static 只留给长期有效的规则与指南（办法、规定、制度、细则、指南、须知、办事流程）；「开放时间」「放假安排」从 static 信号词中删除，有时段的服务调整归 upcoming。

判定文本中公示公告、学术信息、活动报道、就业信息四种形式的先验随分流删除，这四种 notice_type 只在规则转出时才进模型。

### 6. 已确认决策点

- status 时间修正采用 A+C；B 未来允许，本次不引入。C 不随生产接入实现，之后再定怎么处理。
- 外部整体进校园动态。
- 竞赛收窄到"有完整竞赛机制"（报名→选拔→赛制→初赛决赛→评审→排名→奖项）；试跑后若仍泄漏到 news，继续收窄定义。
- 判定规则版本 0.1.1：在 0.1.0 上引入 notice_type 分流（第 5 节）。版本号只在规则确定后升级，小步改动升末位。
- 判定规则版本 0.2.0：类别增删升中位版本，0.2.0 新增 teaching_schedule。之后每次改规则（车道词表或判定文本口径）升末位（0.2.1、0.2.2……），台账 judge 列记录实际版本。0.1.1 的判定文本在第二到第四批之间原地改过几次口径，未升版本，其台账整体视为一个旧版本。
- 规则车道：党建优先归 news；采购类按是否已有结果拆 completed / upcoming；公示公告和学术信息无主题信号的条目转模型，不设兜底类。
- 模型车道传入 notice_type。
- 双模型试标改用 Jev 与 deepseek（原 gemini 与 deepseek）：生产协议已接入 Jev（`typesafe.systemone`），试标结论可直接用于生产切换；Jev 是判别式模型，与生成式的 deepseek 判断方式不同，同错概率更低，且给出逐选项概率；gemini 在 0.1.0 试标中 300 条耗时 1576 秒，是 deepseek 的 8 倍。
- 关键词误命中加排除词，不放弃规则化。
- 分类规则可按语料动态更新与扩展，判据是读者视角下合理；既有规则不因先定而固化。
- 留学跨栏目最先匹配，整个项目生命周期（含名单、资助公示、行前培训）归 international。
- 就业信息按主题拆：就业指导归 recruitment，考研、语言、考证课程归 training。
- 通知类四栏切高精度子集走规则：门户在这四栏下没有子栏目，按标题动作词切子集（第 5 节车道 5 表）。
- 「申报」按读者拆分：个人申报项目、基金、奖项归 application；单位预算、财政专项、办学条件、集中采购、修缮费等归 governance；补贴、奖励、补助的申请与领取归 affairs。
- 课程调整、停止开课、上下课时间归 teaching_schedule；选课、退补选、重修、补修归 affairs。
- service_info 只放基础设施与服务状态；教学日程与开课安排单独成类 teaching_schedule，不并入 service_info（师生主动查看的教学日程不是设施），也不留在 governance（发给教学单位的排课部署学生也会主动看）。
- 监考员选聘归 recruitment：有劳务的临时岗位，与助教岗位选聘同一口径。
- 在职教职工的专业技术职称及岗位评聘、科级等干部岗位聘任归 application，与干部挂职、选聘一致；recruitment 只收面向学生和求职者的岗位。
- examination 的「考核」只指学业与技能考核；研究生三助岗位考核、干部与辅导员考核、团组织述职评议考核是单位对人员的管理，归 governance。
- 发给用人单位的学期勤工助学工作通知（岗位申请、报酬填报、上岗时间）归 affairs；面向学生的勤工助学岗位招聘仍归 recruitment。
- 赴港澳台高校攻读学位、澳门高校奖学金硕士研究生推荐归 international，车道 0 补「澳门高校」「赴澳门」。
- 单届赛事或项目的实施方案、指南有时效，status 为 upcoming；学校公布的学科竞赛名录是学生主动查的多年有效名录，归 competition / static；各单位报送竞赛计划名录仍归 governance。
- 项目、成果入选某会议或展示的速报没有供读者查的名单，归 news；工会或部门联合商家的上门服务、团购优惠、图采会归 activity。
- 境外院校或其项目负责人介绍本校可报名的访学、交流项目的宣讲会归 international，即使以讲座形式呈现。
- 标题写「活动」但设有报名、比赛、择优推荐、选拔赛的演讲、读书演讲归 competition。
- 要求各单位排查隐患、调整活动的极端天气安全工作部署归 governance；面向师生的天气预警、后勤服务调整仍归 service_info。
- 发给各单位的信息报送管理、预算批复与细化预算上报、部门人员与科室分工调整告知归 governance；已完成的人员分工调整只告知对接人，status 为 static。
- 个人填答的调查问卷（含校友追踪调查）、个税汇算清缴及其咨询、教学工作奖励与工作量的核定申报归 affairs；核定、批复同时要求期限内提交材料的，status 为 upcoming。车道 5 个人事务办理补「个税」「汇算清缴」。
- 设施、服务运行情况的回顾报道归 news / completed。

**暂缓上线（2026-10-23）。** 第一次发布的代码与评测已在本分支完成，但 status 的语义要按第 8 节重新设计；

### 8. status 重设计

**问题。** status 只看标题、在分类时定下、之后不变，却同时承担两件事：这条通知要读者做什么，以及现在
是否还有效。后者标题给不出，前者被压成了三个值：

- 不随时间变化。本地 2326 条 upcoming 中只有 36 条发布于 14 天内、249 条于 60 天内；前端若做「只看待进行」，
  用户看到的约 98% 已过期。
- upcoming 占 69%，混着几类对读者意义不同的通知：要办事、有截止（报名、申报、提交、领取，按标题动词粗估约
  800 条）；去参加或会发生（讲座、考试、活动、停水、封楼，约 720 条）；其余约 800 条里又有只需知道的安排与
  提醒（班车调整、放假安排、防诈骗）、学生不必关心的工作部署（安全稳定、主体责任检查），以及实为长期规则的
  细则。
- 已知分歧都出在这里：有声自习室争的是时效（试运行一学期还是长期开放），信息报送争的是性质（工作部署还是
  长期制度），「加强防范网络诈骗」标为待进行但读者无事可做。
- 曾提出加 `none`：它与 static 的边界需要重新定义，又容易变回被删掉的 `unclassified`，且只解决其中一类。

**方向（用户已认可）。** 拆成两个字段：

1. **读者动作（intent）**，分类时只看标题，与 category 正交：category 回答「什么主题」，intent 回答「要我做
   什么」。草案五值：

   | 值 | 判据 | 例 |
   | --- | --- | --- |
   | `action` 需办理 | 读者要在期限内完成一件事：报名、申报、提交、填报、领取、选课、缴费、应聘、投标 | 奖学金申报、选课通知、招标公告 |
   | `event` 可参加 | 一件在某时间发生、读者可以或需要到场的事：讲座、考试、比赛、活动、培训、会议 | 学术讲座、四六级考试安排 |
   | `notice` 需知悉 | 读者只需知道的安排、变化与提醒，有时段但无须办事 | 停水停电、班车调整、放假安排、防诈骗提醒 |
   | `result` 看结果 | 已经产生的结果或已发生的事：名单、公示、成绩、中标、报道、回顾 | 拟录取名单、活动报道 |
   | `reference` 长期参考 | 没有时间窗口、长期有效的规则、指南与服务 | 管理办法、办事流程、长期开放的设施 |

   取代现在的三值：completed 基本对应 result，static 对应 reference，upcoming 拆为 action、event、notice。
   学生不必关心的工作部署是否单列，在判据审定时决定；倾向归 notice，由展示层按 governance 降权，不另设值。
2. **时效（validity）**：原拟由日期计算（正文抽取截止或举办日期，抽不到按 intent 给默认有效期）。
   **2026-10-23 用户决定先不做**：正文选对日期难（多步时间安排、落款日期、回顾已发生日期），而发布时间
   已能近似时效：本地 event 约 95% 在发布后 14 天内举办，action 79% 的截止在发布后 30 天内。读者侧用
   intent 加 `released_at` 窗口组合入口，窗口是前端配置、不进标签与数据库。

**前端用法草图（待产品确认）。** 近期待办（action，发布 30 天内）；近期活动（event，发布 14 天内）；近期
安排（notice，发布 14 天内，governance 降权）；办事指南（reference，按 category 浏览与搜索）；结果与动态
（result，按 category 归档）。入口用「近期待办」而不是「可报名」：标签不保证仍在期限内。category 筛选在各入口内通用。

**实施顺序。**

1. 审定 intent 五值与判据，以及前端入口；时效的抽取范围、所在阶段与兜底期限。
2. intent 进判定文本（升中版本）。由现有标准答案的 category 与 status 机械映射可先得到约 85%（2866 / 3375）：
   completed → result、static → reference、application / affairs / recruitment / procurement 的 upcoming
   → action、讲座 / 考试 / 培训 / 活动的 upcoming → event、teaching_schedule / service_info 的 upcoming →
   notice；类别内仍有混杂（如考试报名应为 action、招聘讲座应为 event），映射只作初稿。competition、
   governance、international 的 upcoming（509 条）需要判定。车道规则同批改为直接给 intent，模型车道两模型
   重新试标，标准答案的 status 列换成 intent，`classify:eval` 同步。
3. 合同、迁移与 Model Config 验证列表一次性改为 intent，第一次发布随之上线。
4. 时效不做（见上）；读者侧与流合同在第二次发布切换。

**已定（2026-10-23，用户确认）。**

- 不设第六值：学生不必关心的工作部署归 notice，展示层按 governance 降权。
- 动作优先：事件与办事并存的标题（考试报名、比赛报名、讲座报名）归 action，错过报名就无法参加；
  考试安排、比赛通知本身不要求办事时归 event。
- 默认有效期与正文时效抽取：随时效一起不做（见上文第 2 项）。

**intent 判据（进判定文本前的草案）。** 判定只看标题，与 category 独立，按顺序取第一个成立的：

1. result：标题陈述已产生的结果或已发生的事（名单、公示、成绩、录取、中标、喜报、报道、回顾、简报），
   沿用现 completed 判据。
2. reference：长期有效、没有时间窗口的规则、指南与服务，沿用现 static 判据（含 0.2.29 长期开放的服务与
   设施）。
3. action：读者要在期限内完成一件事，标题含报名、申报、申请、提交、报送、填报、领取、征集、选课、缴费、
   应聘、招聘、选聘、推荐、遴选、注册、办理、确认、预约、核对、认定、报销、投标等办事动作，或主体是
   读者可申请的项目、可投标的采购、可应聘的岗位。
4. event：一件在某时间发生、读者可以或需要到场的事：讲座、论坛、宣讲、考试、测试、面试、比赛、活动、
   培训、演练、会议。
5. notice：其余只需知道的安排、变化与提醒：教学安排、设施与服务、放假、班车、封楼、安全提醒、工作部署。

**初稿映射。** `jobs/notice-classifier/eval/experiments/2026-10-23-status-intent/intent-draft.tsv` 由现有
标准答案的 category、status 与标题机械生成，逐条记录依据：result 982、action 1186、event 755、notice 387、
reference 65。upcoming 先看标题办事动词，再按类别（teaching_schedule、service_info → notice）与事件词，
最后按类别兜底；international 的「启动选派、访学项目」按读者申请归 action。抽查可见类别内混杂按预期拆开：
招聘类的讲座预告归 event，竞赛类的「报名截止时间变更」归 action。初稿只作试标起点，intent 进判定文本
（升 0.3.0）后由两模型重新试标、按分歧调规则，结果替换标准答案的 status 列。

**0.3.0 实施（2026-10-23）。** intent 取代 status，一次改到合同、迁移、Model Config 验证、分类 Job 与评测：

- `campus-contracts` 删 `NOTICE_LABEL_STATUSES`，加 `NOTICE_LABEL_INTENTS` 与中文名；迁移
  `20261022143323_notice_label_columns` 尚未发布，直接把 `label_status` 改为 `label_intent`（本地库回退该
  迁移后重放）；Model Config 验证列表改名 `noticeClassificationIntents`。

**0.3.x 试标与评测（2026-10-23）。** 模型车道每批 50 条、两种后端各跑一次，分歧与判错改车道规则或判定

**决策模型后端去 Jev 化（2026-10-23）。** Nace 的 Drex 与 Jev 接口兼容（`POST /v1/systemone`，Bearer 鉴权，
同样的 choice 问题与答案结构，只计输入 token），用它替换 Jev。小规模试跑用 0.3.21 的问题：drex-v2.0 在
10 条上 7 / 10，drex-max 同 10 条 10 / 10，再抽 50 条两模型一致的标准答案 50 / 50；drex-max 每条约 1.4 万
输入 token、约 1 秒。存储名 `notice_classification_jev` 改为 `notice_classification_decision`，provider 接受
`nace` 与 `typesafe`，接口仍是 `typesafe.systemone`（接口格式名，与 `openai.chat_completions` 服务 deepseek
同理）；Ops Web 后端名 `jev` 改为 `decision` 并可选服务商，评测 `--backend decision`，本地 seed 读
`NOTICE_CLASSIFICATION_DECISION_*`（provider 默认 `nace`、模型默认 `drex-max`）。迁移
`20261022135401_notice_classification_backends` 未发布，直接改名。drex-max 是固定版本，不随 `drex-latest`
移动。之后 r10 起的重判与标准答案的 `dual_model` 改由 drex-max 与 deepseek 产生。

**决策模型判据按标题拼装（0.3.34 至 0.3.41）。** drex-max 没有提示缓存、按输入计费，0.3.33 每次发出完整的
两个 choice 问题（3.2 万字），其中易混裁决按点名类别复制就占 1.95 万字；deepseek 的系统提示几乎全部命中缓存。
决策模型的问题因此按标题与栏目拼装，LLM 系统提示始终按原顺序拼回全文：

- 类别定义与易混裁决的特例条款带 `title_signal`，标题命中才发；互为对照的条款挂同一组信号，一起发或一起省；
  并列清单只发命中的项。信号是对标题的宽匹配，漏发的代价是该条可能判错，由评测暴露后补信号词。
- 易混裁决只在 category 问题的 instructions 里发一次，不复制到点名的类别下；栏目说明只发本栏目的一条；
  输入说明讲的是规则筛选与栏目分布，不发给决策模型。
- 宽口径裁决的主句复述两边的类别定义，并入定义后只留带信号的特例句。affairs 与 application 的对照例外，
  每次都发：拆开后两边定义各自读，「认定」与「评定」字面相近，缺了「主动争取」对「按既定流程」的并列对照
  就会判错，而这组对照适用于两类的大部分标题，设信号会漏掉。
- intent 判据每次发全文，不按标题裁剪：五个值互为对照，判别依据分散在各条特例句里，标题不命中时只剩各自
  第一句，模型失去区分依据；逐版回放中裁剪类别定义不影响判对，裁剪 intent 会。
- 之后不再为省输入改判定文本，改动只看判对率。

**裁剪后的判错交给车道规则（0.3.42 起）。** 按标题拼装后，少数标题落在几条易混裁决的交界上，同一条通知在
相邻版本之间时对时错；决策模型对同一输入的输出确定，按提交取出旧版本 `model.ts` 与 `notice-judge.json`
回放即可复现。再补判定文本只是把交界挪到别处，所以标题信号明确的收进车道规则：规则用 `--backend rules`
验证、不调用模型，标准答案里被新规则给出同一标签的 `dual_model` 行改记 `rule_lane`。补信号或改文本仍用于
没有明确标题信号的判错。

## 未采用方案

- **事件串接 + 回溯修改（B）**：被 A+C 取代。未来在已有时间修正能力后再评估；本次引入会为"第X届"年度活动名称匹配引入不可控误伤。
- **外部独立第三流（外链 tab）**：语义最干净，但多一个 tab 与导航，而外部 76% 是微信。与"外部进校园动态"相比收益不匹配。
- **外部按来源细分再分类（采购网→采购等）**：只是把 `is_external` 换成 `source_domain`，复杂度上升而外部仍无站内消费方；政府采购网 438 条虽然格式规范，但仍是外链。
- **预设一致性与质量指标**：还没有结果先定阈值无依据，先出结果再考虑怎么用指标。
- **notice_type 直接映射 category**（活动报道→news、公示公告→selection_result、学术信息→lecture_forum）：活动报道 388 条里有讲座回顾约 60、竞赛喜报约 30、培训约 25，整体映射会把它们吞进 news；学术信息有成果报道，公示公告有采购。形式只能作 status 先验和车道入口，category 仍要看标题主题。
- **notice_type 只作先验传给模型、不分流**：模型在这三种形式上的分歧最集中，且规则已能稳定判定，继续交给模型只是付调用成本换分歧。
- **规则车道无信号条目设兜底类**（公示公告其余→selection_result、学术信息其余→lecture_forum）：抽查发现兜底会把推免工作通知、招生简介、成果报道错分，转模型更准。
- **就业信息整栏归 recruitment**：考研、语言、考证课程的主题是技能与应试，不是就业；整栏归 recruitment 会让 recruitment 吸收培训。
- **留学名单按形式归 selection_result**：会把留学项目的生命周期拆到两个类，读者按主题查找留学时漏掉名单与资助公示。
- **开放时间、放假安排归 static**：语料中这类标题全部是有时段的调整，没有常设规则；归 static 正是 0.1.0 中 service_info upcoming↔static 分歧的来源。
- **活动报道业务主题优先于党建**（党建培训班→training）：读者不区分党建报道的形式，统一视为宣传材料。
- **每次都发全部易混裁决**：0.3.41 的 4 条判错在发全部裁决时都判对，是最直接的修法；但每条多出约 1.5 万字
  输入，决策模型按输入计费，成本回到裁剪前，而信号明确的标题交给车道规则不花模型调用。
- **易混裁决复制到点名的每个类别下**：每个选项的判据自成一体，是试标脚本的原始放法；但每条通知平均多发约
  0.56k 字重复文本，移到 instructions 后每条收到的裁决集合不变。
- **intent 判据按标题裁剪**：0.3.35 至 0.3.40 采用，每条通知省约 4k 字；但它让 intent 在互为对照的值之间
  失去依据，回放显示这几版的 intent 判错由此产生。
- **affairs 与 application 的裁决按标题信号发送**：与其他宽口径裁决一致、省每次都发的固定文本；但这组对照
  适用于两类的大部分标题（奖助学金评定、微专业招生、岗位评聘、领取、学位授予），信号无法收窄而不漏发。

## 可观察结果

- 双模型（Jev / deepseek-v4-flash）对模型车道的试标一致性与分歧分布；分歧条目回看语料调规则，不调阈值。Jev 每条给出各选项概率，两模型一致但 Jev 置信度低的条目一并抽查。
- 内部/外部在列表流的实际分流行为符合第 4 节路由。
- 外部通知不再渲染分类徽章，只显示来源。

## 风险

- 外部整体进校园动态后，438 条政府采购公告落在动态页，动态页出现外链采购公告的语义噪声；接受，通知页收益（干净内部业务列表）更大。
- status 长期不回溯（A），"报名通知"在比赛结束后仍显示 upcoming；由 C 的时间软信号降噪，标签本身保持标题语义、可审计。
- 竞赛边界仍可能有泄漏到 news 的个案；按已确认决策继续收窄定义处理，直到分歧收敛。
- 规则车道没有双模型分歧可看，关键词子串匹配的误命中只能靠抽查发现；发现后补排除词。
- 党建优先会让「入党积极分子培训班」这类报道归 news 而不是 training；这是有意取舍。
- 「主题压过形式」目前按类别逐条决定（留学名单归 international、竞赛名单归 selection_result），不是全局原则；新增类似例外时需逐条论证。
- 条数基于 2024-07-01 起的 3375 条内部通知；语料扩展后，词表需在新语料上复核误命中。
