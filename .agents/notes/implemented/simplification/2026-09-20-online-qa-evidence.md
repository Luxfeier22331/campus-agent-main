# Agent Note: 在线问答保留可用材料

Status: implemented

## 背景

访学多事实查询的前两次检索重复返回正文，却因累计十条结果上限阻止第三次查费用。
全问题重排与每条通知只保留一块会削弱针对性检索；按页面合并预览会把不同编号展示成同一段正文。

## 决策

本次检索的 `search_goal` 用于排序，旧调用仍可使用用户目标。按 `result_ref` 排除本轮已返回片段，
保留同一通知的互补章节。取消十条累计结果和二十项证据的静默限制，仍保留每次返回数量、字符及请求资源预算。
模型输入统一去重资料，历史上下文可裁剪，但已取得的必要材料不因历史字符预算被拒绝。
暂时性工具失败不禁用后续调用；模型轮次和工具调用预算耗尽时复用已有恢复合成路径。
来源卡按页面及段落区分，Docs 编号链接匹配时忽略阅读器追加的 `hl` 高亮参数，保留版本与章节匹配。
耗时诊断读取失败不阻断正文，用户取消仍生效。Campus Search 阶段诊断改为旁路写入，避免诊断数据库延迟消耗检索截止时间。
索引绑定锁只覆盖 run metadata 绑定，不覆盖实际检索；检索失败保留 validation、index、embedding、retrieval、rerank 或 selection 阶段，生成稳定的阶段错误码。
回答完成后的 memory append 使用独立 workflow，提交和状态查询沿用同一 operation ID，并将单次远端观察窗口统一为 300 秒，避免短超时触发重复提交。

## 未采用方案

单纯提高累计结果上限改动更少，但重复结果仍会占满新上限，互补章节及预览错误也不会消失。
无条件重试整条问题可能改善偶发失败，却重复产生答案和费用；这里保留模型选择后续调用及已有合成流程。
不增加代码级整条问题重试、第二套诊断队列或新的 fallback；不修改统一模型网关和计费用量合同。

## 后果

多事实问题可以继续补查新资料，来源编号可以超过十，产品和 Ops 消费相同合同。
去重只针对同一证据片段，不代表不同片段互相矛盾时可以省略判断。请求 deadline 与调用预算继续限定成本。
回归覆盖针对性排序、互补章节、跨调用排除、超过十的引用、预算恢复、诊断失败、阶段错误归因、并发索引绑定和 memory append 长观察窗口；部署前仍需完成真实 Qdrant 冷热查询对照。
