# Agent Note: Biome 告警清理保留既有执行合同

Status: implemented

## 背景

仓库 lint 可以在存在 warning 时通过，运行时、测试和样式中因此仍有非空断言、显式 `any`
和选择器优先级顺序告警。用户要求全部修复，并同步 Biome 配置 schema 与已安装工具版本。

## 决策

- 有确定生产者的值通过准确返回类型和元组表达：模型配置返回必需字段，数据库 drain 表定义
  使用固定三元组，Temporal 测试解构固定的 Worker 列表。
- 保留执行所需的必填假设。无法由局部类型推导的阶段、回放和工具结果使用显式断言；测试
  先断言夹具、路由和 schema 存在，再继续验证。OCR 复用原有数据库可用性检查。
- Kubernetes 测试和 Worker 制品脚本只声明实际读取的资源字段，消除 `any`，不引入另一套
  通用资源验证框架。Temporal drain 依赖缩小为实际使用的 workflow 列举接口。
- CSS 调整规则顺序，保持选择器、声明和媒体查询范围；配置 schema 对齐现有 Biome 依赖。

## 未采用方案

- 批量替换为可选链可以快速消除非空断言，但会让必填数据缺失后继续执行，改变原有合同。
- 关闭规则或增加忽略注释可以减少代码改动，但没有完成用户要求的告警修复。
- 将 warning 全部升级为 CI 错误可以阻止后续积累，但这是另一项门禁策略调整，本次仅使用
  严格命令验证清理结果，保留现有 lint 入口。

## 后果

类型和测试直接表达已存在的前提，内部数据缺失时能在使用位置失败。正常执行路径和 CSS
声明保持原有语义；仍需用各包类型检查、运行时测试、Temporal 集成测试和合同生成检查
确认改动，lint 清零本身不证明业务行为正确。
