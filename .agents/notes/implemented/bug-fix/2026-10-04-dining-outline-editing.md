# Agent Note: 食堂路径节点编辑与外轮廓保护

Status: implemented

## 背景

需求方维护海淀食堂地图时要求解除外轮廓的编辑保护，并将第三食堂的轮廓作为第一食堂的初始形状。
Ops Web 已有路径节点拖动、增删、缩放和草稿保存能力，但属性面板与形状能力对外轮廓单独禁用，
使内容维护人员无法在前端校准实际建筑外形。该限制属于编辑器，并非许可证或数据库权限。

需求方继续维护分隔线时发现无法设置节点。编辑器采用低层 `TldrawEditor`，未注册高层组件默认
提供的 overlay utils，因此已有节点拖动处理没有对应的画布手柄。属性面板只展示坐标，添加节点
则沿尾段向外延长；端点到达画布边界时还会被夹成重复点，无法可靠绘制折线。

## 决策

由 Ops Web 的 Dining 编辑器复用现有路径属性面板和缩放处理，所有地图的外轮廓按手工锁定状态
决定能否编辑，不增加食堂 ID 白名单或新的编辑模式。节点仍由现有 adapter 转换为
`layout.outline.points`，通过既有草稿保存和 revision 冲突检查持久化。

编辑器显式注册 tldraw 默认 overlay utils，恢复节点手柄、选区与缩放等既有工具需要的交互层，
继续使用现有形状和工具白名单。分隔线、结构与外轮廓共用逐节点 X/Y 输入；坐标使用画布绝对值，
Enter 或失焦提交，Escape 取消，越界值限制到画布并显示实际采用值。插点取指定线段中点，保留
原有路径；顶部添加节点作用于末段，闭合路径作用于闭合边，不再向画布外延长。开放路径至少保留
两个节点，闭合路径至少三个。修改沿用原有撤销与 adapter，不改变领域格式或增加数据库接口。

每张地图必须保留唯一外轮廓，因此仍禁止删除、剪切和复制外轮廓，也不将它纳入批量对齐或分布。
节点最少保留三个，画布边界、自相交和非零面积继续由 Dining 领域校验负责。具体用户行为见
[Dining 产品文档](../../../../docs/product/dining.md#当前内容维护)。

第一食堂采用第三食堂轮廓是需求方指定的一次性内容调整，只复制当前已保存的外轮廓并同步
bootstrap JSON，沿用第一食堂的稳定 ID 和内部元素；不新增跨地图复制接口，也不自动发布。

## 未采用方案

- 保持轮廓只读并持续代改 JSON，能够维持已有保护，但会阻断需求方直接在前端校准地图。
- 只对指定食堂 ID 解锁，能缩小当前可编辑集合，但其他食堂沿用同一几何合同，没有独立权限边界，
  不应把一次性数据名称固化为编辑器策略。
- 允许删除或复制外轮廓可完全复用通用绘图行为，但会破坏每张地图唯一轮廓的现有合同。
- 只补坐标输入可以绕开手柄缺失，但画布上的已有拖动和缩放仍不可用，必须同时修复交互层注册。

## 后果

内容维护人员可以继续校准占位地图和照片描绘的轮廓；手工锁定、撤销、未保存保护及发布流程仍由
现有编辑器负责。非法几何会阻止保存，解锁不绕过领域校验。若未来需要多建筑或多外轮廓，须先
重新评估领域合同，不能通过解除删除和复制保护实现。
