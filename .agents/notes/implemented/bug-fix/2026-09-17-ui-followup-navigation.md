# Agent Note: UI 复验后的筛选导航与展示收敛

Status: implemented

## 背景

PR #510 部署后的 MCP 复验确认：缺失用户身份时仍展示完整 ID，概览趋势没有下钻入口，
班车历史后退后 URL 与标签不同步，通知筛选刷新后丢失；Campus 班车日期仍混用斜杠和未补零格式。
这些是 #480、#485、#486、#492 的剩余问题，消费者分别为运维人员和查看班车的学生。

Issue #568 的本地复现还确认：从首页侧栏选择历史会话只切换运行时，URL 仍为 `/`；打开回答来源再后退
会进入空白新对话。已有 `/c/$conversationId` 能在直接访问和刷新后恢复会话，缺口在侧栏入口。

## 决策

- 用户身份缺失时复用 Ops 现有 `formatId`，完整 ID 留在 title 或原详情链接中，不改变用户标识或查询。
- 概览两张趋势图使用可聚焦链接进入实际查询区间的请求列表，失败请求另带 FAILED 筛选；
  不把图上估算的时间点或 p95 数值拼成后端不支持的查询条件。
- 班车服务类型、通知的状态、分类、关键词和页码以路由搜索参数为准；输入中的关键词仍是草稿，
  搜索后才进入 URL。通知继续使用现有草稿离开保护，已确认的页内导航不再次弹出路由保护。
- 历史会话侧栏使用持久化的 conversationId 导航至 `/c/$conversationId`，由已有 QAShell 路由输入
  驱动运行时切换；保留原 Trigger 的键盘行为，但阻止其同时直接切换已保存会话。桌面与移动侧栏
  共用此入口，移动选择仍关闭抽屉。新对话继续重置运行时并返回 `/`，不改变首次发送时的 URL 规则。
- Campus 日期时间保留 `YYYY-MM-DD HH:mm:ss`，仅日期使用 `YYYY-MM-DD`；日期选择保留星期提示，
  不为只有日期的通知关联或有效期补造时间。
- 用户确认 #483 改为四页统一的七项时间选择，默认今日，日期范围最多90天。共享合同统一北京时间、
  周一周界与半开区间；App API 会话查询补上原先未执行的 window 解析，Ops 统计、趋势、列表与计数补齐上界。
- 概览下钻使用响应中的精确起止时间，缓存回退保留原范围与生成时间。自选区间使缓存键由有限枚举
  变为任意区间，因此由概览服务清理五分钟过期条目并限制64条；将来查询模式变化时重评容量。
- #465 将班次与乘车点放在说明前，适用日期和星期不再依赖关联通知存在；后端已返回这些事实，
  不扩大交通接口。#468 仅缓存命中时连续展示，未命中使用骨架屏；相邻日期只在悬停、聚焦或触摸时预取，
  复用单日查询键与月历缓存。预取由交通页面拥有，停止操作即不再扩展请求范围。

## 未采用方案

- 用 effect 把 URL 反复复制为另一份已应用筛选：可保留旧组件状态结构，但会继续产生两个权威来源，
  因此已应用筛选直接读取路由，只有未提交输入保留本地状态。
- 订阅所有运行时 threadId 变化以同步地址：可以覆盖列表切换，但也会在新对话初始化时导航，扩大
  本次修复的生命周期影响；历史项直接复用现有路由即可恢复来源返回和浏览器前进、后退。
- 把图表包成点击 div：容易添加鼠标事件，但会丢失链接语义和键盘操作；采用普通链接。
- 恢复固定浏览器 smoke 命令：可重复模拟页面旅途，但与已确认的资源和验证边界冲突；
  使用现有定向组件测试覆盖路由与显示合同，浏览器复验继续按需通过 MCP 执行。

## 后果

筛选地址可以直接打开和在历史记录中恢复，编辑草稿仍由原页面保护。变更不涉及服务端写入合同、
身份解析 API 或新的持久化状态；时间查询读取合同同步更新。源码验证不代表当前部署已经包含本批修复。

时间查询上限与缓存策略按本次确认的90天范围维护；若实际长区间查询超过现有预算，再根据执行计划定位。

会话导航回归复用现有组件与浏览器测试入口，覆盖桌面和移动端的历史选择、刷新、来源返回、两会话
之间的前进后退和新建会话；测试使用合成会话及通知响应，不代表已修改线上记录或部署。
