# Agent Note: Campus Web hash 清理与运行态故障修复

Status: implemented

## 背景

Issue #547 的 watchdog 超时只清理浏览器状态，未请求取消服务端运行；#552 的单个坏锚点使整张食堂地图降级。
Issue #455 在真实文档语料中仍可复现：“转专业”的目标《本科生专业调整实施办法》排第 6，
“专业调整”则排第 1。构建路径还保留同进程重复摘要检查与无人调用的旧同步入口。

## 决策

- watchdog 超时复用现有取消流程，保留 requestId；取消受理不当成取消完成，继续等待服务端终态。
  取消失败沿用原有失败提示与用户主动停止等待入口，计时器不自动触发后者。
  状态接口确认终态、规范消息刷新结束后，仅释放仍属于该次运行的操作，终止旧流和恢复循环。
- 食堂 SVG 由 App API 在对象读取边界校验摘要，浏览器不再重复计算，缓存键使用内容寻址 URL。
  浏览器保留同源路径与可执行内容检查；未绑定、标签或几何异常的锚点单独移除，其他窗口继续可选，
  坏窗口仍可通过搜索查看。整体 SVG 解析失败或可执行内容仍使地图降级。
- 文档构建只保留 `compileDocsSource` 后物化已验证对象的路径。删除无人调用的分步同步/检查入口、
  `expectedCurrentDigest` 参数、生成对象碰撞自检和物化时重复比较摘要；跨边界对象摘要检查保留。
  地图 normalize 删除起始重复验证，保留最终发布验证；已有同名文件直接比较字节，不重算两次 hash。
  内容寻址 URL、文档来源发布身份和乐观并发写入的 ETag 条件保留。
- 搜索继续由 FlexSearch 负责召回，完整多词匹配先于部分匹配。每组结果中标题包含查询优先，
  再优先去除章节编号后与查询完全相同的章节，组内保持原生顺序，不引入同义词或文档特判。

本篇部分取代[退役冗余 hash 计算](../simplification/2026-09-29-retire-redundant-hashes.md)
中暂留 Campus Web 客户端 digest 校验的选择，其他领域保留项仍有效；同时部分取代
[清理文档检索自维护排序器](../simplification/2026-09-24-flexsearch-native-docs-index.md)
中完全接受原生排序的选择，其 Document/Resolver、构建导出与 Worker 导入设计继续有效。

## 未采用方案

- 保留浏览器摘要复核：可以检测字节漂移，但同源 App API 已完成该检查，没有独立信任边界。
- 仅调整 FlexSearch 字段权重：改动更小，但真实失败在同一章节字段内部，不能解决主题聚焦问题。
- 恢复旧的完整应用层评分器：能表达更多排序因素，但当前只需要标题/精确章节优先，其他权重没有新增依据。
- 超时立刻释放前端：能马上允许重试，却遗留后台运行；继续由既有取消流程处理受理、终态与失败。
- 任意锚点异常使整图失败：保证图与投影完全一致，但会隐藏全部可用窗口，不符合局部失败的产品需求。

## 后果

Playwright MCP 在本分支服务验证：真实超时取消请求最终进入 `phase: canceled`，页面显示取消终态；
食堂 SVG 返回 200，注入一个未绑定锚点后仍有 4 个可用窗口，选中窗口能查看详情，未触发整图降级。
超时验收临时缩短浏览器计时并暂缓流进度，最终源码仍为 180 秒。

本地文档只有 2 篇，搜索浏览器验收通过临时响应转发加载 staging 的 184 篇文档、2337 个检索条目，
在本分支页面和 Worker 中运行修复后的排序。“转专业”首项为目标文档的“第二章 转专业”，
“专业调整”仍首项为同一文档，点击章节保留锚点与高亮参数。未向 staging 发布改动。
回归覆盖对象损坏拒绝、编译失败保留旧产物、局部锚点失败、搜索顺序、取消与恢复竞态。
