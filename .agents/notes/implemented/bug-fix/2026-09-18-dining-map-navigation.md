# Agent Note: 食堂地图阅读、手势与往返导航

Status: implemented

## 背景

手机端放大到上限后窗口名称仍过小、普通滚轮被地图截获、拖动误选窗口，以及窗口定位入口不一致、
本人列表往返丢失视图、关闭投稿详情增加历史回环。筛选跨楼层时也缺少零匹配提示。

## 决策

- 默认保留完整楼层总览，标签使用 16 个 SVG 单位，最大缩放根据实际画布计算，达到可阅读的屏幕字号。
  继续由现有缩放库计算手势和边界，SVG 按目标尺寸渲染，仅平移使用 CSS transform。
- 普通滚轮滚动页面，Ctrl + 滚轮及捏合缩放地图。总览时单指滚动页面，放大后单指拖动地图。
  位移达到 8 CSS 像素、多指或取消手势均抑制该手势的点击，独立点击和键盘选择仍有效。
- 禁用地图双击缩放，部分取代[Campus Web Apple HIG 对齐](../feature/2026-09-17-campus-web-apple-hig-alignment.md)
  中双击缩放和始终 `touch-none` 的条目；该笔记的其余共享 UI 决定仍有效。
- Dining 页面拥有地图与搜索选择后的定位：移动端详情标题及楼层信息不可见时才滚动，尊重减少动态效果。
  浏览器历史恢复不触发主动定位。
- URL 继续保存食堂、楼层、窗口和菜单项；页面内存保存当前地图视图、搜索词和滚动位置，服务本人列表往返。
  不跨刷新持久化，主动切换楼层恢复总览。若以后本人列表不再卸载地图，重新评估这段视图恢复代码。
- 投稿详情内部打开后关闭返回来源历史项；直接链接或新建投稿后的详情关闭替换当前 URL。
  使用 Router 导航，保留[投稿交互修复](2026-09-17-dining-submission-interactions.md)的退出保护所有权。
- 楼层切换保留搜索词，以当前楼层零匹配提示解释不可选状态，复用清除搜索入口。

## 未采用方案

- 保留 200% 上限仅调整字体渲染：改动较小，但已测得手机端有效字号不足 7px，不能满足阅读需求。
- 手机详情改为底部弹层：便于快速查看，但用户已选择保留页面内详情，本次统一现有入口和滚动行为。
- 全局滚动恢复或持久化地图视图：能覆盖跨页面与刷新，但当前需求仅为 Dining 内部往返，由页面内存承接。
- 关闭详情统一 push 或无条件 back：前者制造历史回环，后者会让直接打开分享链接的用户退出 Dining。

## 后果

地图渲染和手势策略只影响 Dining；服务端接口、地图资产校验、数据库与部署配置保持原合同。
组件和 Router 回归验证状态与历史，浏览器人工验收负责真实布局、清晰度和手势；不增加自动 smoke workflow。
