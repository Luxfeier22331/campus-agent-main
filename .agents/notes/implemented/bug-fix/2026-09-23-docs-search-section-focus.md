# Agent Note: 中文文档搜索的章节聚焦排序

Status: implemented

本笔记中的应用层章节聚焦排序已由[清理文档检索自维护排序器](../simplification/2026-09-24-flexsearch-native-docs-index.md)取代；本篇保留 Issue #455 的复现证据和历史取舍。

## 背景

Issue #455 在真实 Campus Docs 语料中复现：查询“转专业”时，《本科生专业调整实施办法》排在第 6，
而查询“专业调整”时同一文档排在第 1。现有搜索没有同义词扩展；FlexSearch 只负责召回，应用层比较器
再按标题、章节、字段覆盖和 FlexSearch rank 排序。

问题来自章节命中分相同后的兜底顺序：`第二章 转专业` 与 `第三节 转专业与转学` 都包含完整查询，
但没有表示前者更聚焦当前办理主题，最终由索引 rank 决定文档顺序。

## 决策

当时在现有比较器中增加通用的章节短语聚焦度：当章节标题包含完整查询短语时，查询短语占章节标题的比例
越高，排序越靠前。该规则现在随自定义比较器一起删除；当前搜索接受 FlexSearch Document/Resolver 的原生排序。

排序优先级保持为：精确文档标题、全词覆盖、精确章节、覆盖词数、字段分、章节短语聚焦度、FlexSearch
rank 和稳定标题/锚点顺序。章节聚焦度只在标题和字段相关性相同时打破平局。

## 未采用方案

- **为“转专业”添加“专业调整”同义词**：当前合同明确搜索不添加别名；这会改变召回范围并引入词表维护责任。
- **为目标文档增加硬编码权重或白名单**：无法泛化到其他办理主题，也会让数据内容承担排序策略。
- **更换搜索引擎或引入远端 reranker**：当前缺陷发生在已召回结果的本地排序，增加服务和索引复杂度没有依据。

## 后果

真实索引中“转专业”的目标文档排到第 1，“专业调整”仍保持第 1；章节展开、固定链接、锚点和高亮合同不变。
对 184 篇文档、2337 个检索条目抽取 489 个标题、章节和多词查询后，完整标题命中和完整章节命中均未被压后，
重复执行的结果顺序稳定。把同一索引条目反转的实验显示，语义分接近时 FlexSearch rank 仍会受输入顺序影响；当前
发布构建按 `docId:anchor` 稳定生成索引，因此这不是本次数据中的线上漂移，但以后若需要更强的重排稳定性，应替换
这个输入顺序相关的兜底，而不是继续增加文档特判。未来若出现跨文档语义意图无法由章节和标题表达，应基于新的真实
失败单独评估，不能把同义词或模型重排作为默认补偿。
