# Agent Note: ADR-0082 Hindsight 记忆生命周期

Status: implemented

## 背景

个人记忆同时包含原始事实、派生观察和用户管理操作。产品侧的手工内容投影与来源删除路径会
形成第二个内容所有者；完整清除仍需要用户生命周期、generation fence 和在途排空。

## 决策

保持 Hindsight 作为内容和派生记忆的唯一 owner。产品数据库只拥有用户生命周期与待执行命令，
不维护手工条目的独立键值镜像。管理页直接展示当前用户 bank 的事实、经历、派生观察及其支持事实。

- 使用原生事实编辑、invalidated 停用和 valid 恢复。停用不是物理删除；派生观察只读。
- 聊天删除/裁剪与记忆独立，不捕获删除来源，不发出来源删除命令。
- 暂停关闭后续召回和追加但保留管理；完整清除排空旧代次后删除整个 bank，完成后保持关闭。
- 按用户顺序处理命令；普通编辑不使整库不可用，命令序号不约束聊天调用。
- 完成回调唤醒下一条命令，定时派发互相隔离。普通修改有界失败并允许用户重试。
- 追加是回答后的独立工作。attempt 失败不等于整个追加失败；Ops 观察已存在的工作状态到终态。
- Hindsight 模型/端点独立于聊天模型，不把记忆查询改写成联网搜索。

### 生命周期边界

每条已接受用户消息使用可重复派生的来源文档标识，支持写入重试；这不构成删除聊天后清除该来源的承诺。
正文、来源、归档和派生关系由 Hindsight 管理。产品只在完整清除及账号注销中承诺删除长期记忆。

本地和 staging 旧个人记忆允许硬切，不新增历史格式兼容、旧条目转换或历史聊天重导入。
保留用户账号、聊天记录、机构知识、共享对象存储和通用 Temporal 数据。
原生 memory UUID 可以作为用户管理目标；bank、租约与供应商操作标识不作为浏览器授权凭证。

## 未采用方案

- **在产品数据库维护手工条目镜像**：便于产品侧直接查询，却产生 Hindsight 之外的第二个内容所有者。
- **聊天删除联动来源批次清理**：可将聊天与记忆一并删除，但本次选择把二者生命周期分离；
  长期记忆删除只在完整清除和账号注销中承诺。
- **轮询 consolidation 或接收 webhook 建立调度器**：可跟踪供应商内部进度，但当前消费者只需要
  原生命令和完整清除的在途排空，不需要第二套记忆调度。

## 后果

删除原先的手工内容投影、单条物理删除与来源批次清理；保留确实服务于完整清除的 generation fence
和在途排空。不接收 Hindsight webhook、不轮询其内部 consolidation，不建设第二套记忆调度器。

具体 API、状态和失败行为由 [记忆接口](../../../../docs/contracts/app-api/memory.md) 与
[记忆架构](../../../../docs/architecture/system/memory-plane.md) 维护。
