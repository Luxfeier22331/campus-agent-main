# Agent Note: Agent 输入输出

Status: implemented

## 背景

模型输入输出曾被当作一份不断增长的 system prompt。这样会把运行策略、工具开放、
不可信正文、输出结构和终态判断混在一起，使模型文案承担本应由代码执行的边界。

## 决策

### 代码拥有运行边界

- 代码拥有认证、策略、能力开放、数据范围、执行预算、终止条件、schema 校验、证据校验
  和最终投影。
- developer instructions 只保留跨工具、长期稳定的不变量；不得替代这些代码边界。
- 运行时把 deadline、turn、输出和上下文限制作为 typed input 传递，不让模型运行时从
  隐式环境变量或宽松默认值推断。

### 输入按信任边界装配

- 角色指令、允许的工具、typed task packet 和输出合同属于受信任控制数据。
- 用户正文、历史会话、检索内容、记忆和工具返回值始终作为明确标注的不可信数据。
- 不可信正文不得拼入 developer instructions，也不得以指令语气覆盖运行时边界。

### 工具使用可执行 schema，最终回答使用文本

- 模型可见工具通过 function/tool schema 描述用途、参数和副作用；跨工具规则才进入
  developer instructions。
- 直接回答和最终合成的正文都以文本交付；Solve 的计划、步骤总结与 Replan 则使用各自的结构化
  operation 合同，由后续 Agent Workflow 决策及运行合同维护。早期“仅原生文本”的范围不排除这些内部结果。
- evidence-backed 回答使用有界正文引用；Finalization 从本轮真实成功工具结果中确定性派生来源，
  不得再调用模型补齐或改写答案。

### 不完整输出必须失败关闭

- provider failure、incomplete、空回答、工具合同错误和运行时错误都产生明确失败结果；步骤输出格式
  失败不抹去已验证证据，后续合成能否继续由持久运行合同决定。
- 追问、资料不足和范围说明是普通回答正文；消费端不得为它们再造模型 outcome。
- JSON、streaming 和持久化投影必须保留同一回答正文与运行状态。

具体 packet 字段、终态枚举和错误码由 executable contract 与所属运行时
文档维护，本笔记 不复制动态清单。

## 未采用方案

- **单一大型 system prompt**：无法可靠执行认证、工具开放和 schema 校验。
- **自定义模型终态对象**：把回答语义和运行状态耦合，并要求每个消费者重复解释。
- **消费端修补模型输出**：会掩盖 provider 和合同失败。

## 后果

- prompt 变更不能放宽代码拥有的能力、数据或证据边界。
- 新 Agent 路径复用对应 operation 输出和证据合同；改变语义时由新的决策笔记说明。
- prompt registry、管理后台或托管模板不是可靠性的前置条件；出现真实治理需求后再决策。
