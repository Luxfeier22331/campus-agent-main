# Agent Note: ADR-0087 内部门户通知来源合同

Status: implemented

## 背景

早期通知采集只请求类型 `5`，并在对象路径和每条来源对象中重复保存站点、类型名称和组织名称。
通知消费不按采集批次顺序执行，集群 source bucket 也没有需要迁移的历史通知对象。

## 决策

- 通知选择器确定采集范围，全局列表只提供跨类型增量顺序，不能用通知 ID 数值推断时间；
- 通知 ID 是对象身份，类型和组织 ID 属于对象字段，名称映射集中维护，不在路径和每条对象重复；
- 外链使用明确标记和来源 URL 表达，采集器不请求外部正文或建立外链抓取状态；
- 同步状态只保存增量与历史覆盖边界，已有合法对象不重复请求，不维护内容版本或 `captures/` 批次；
- 分类只确定唯一内部领域，不表示领域消费、对外发布或用户阅读完成，也不写回来源对象。

## 未采用方案

- **在路径和每条来源对象中重复站点、类型与组织名称**：对象单独读取较直观，但重复维护可变名称。
- **按批次或通知 ID 数值推断采集顺序**：便于枚举任务，却不能表达跨类型的真实时间边界。

## 后果

本篇保留通知来源身份、外链不抓正文以及采集不等于发布的边界。后续规范化存储由
[ADR-0088](./2026-08-14-adr-0088-normalized-notice-storage.md)定义；
[ADR-0094](./2026-08-25-adr-0094-notice-maintenance-state.md)进一步让采集登记数据库库存、分类写回
通知行并显式发布，也维护当前同步区间合同。因此“采集只写来源对象”的历史范围已被扩展，不能
据此跳过数据库登记；来源对象仍不被分类结果改写。
