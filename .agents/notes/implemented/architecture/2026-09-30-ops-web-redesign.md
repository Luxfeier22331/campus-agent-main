# Agent Note: Ops Web 工作台布局重构

Status: implemented

## 背景

Ops Web 页面已经覆盖运行观测、内容维护、账号管理和运营配置，但共享壳层仍以固定侧栏、单一页面标题和分散表单为主。实际使用中需要更快扫描列表、保持筛选上下文，并在桌面与移动端切换详情。

## 决策

沿用现有品牌颜色、字体和明暗主题，重做共享工作台壳层、页面标题区、筛选区和高频列表的层级。导航按运维任务分组，页面内容使用更宽的可用区域和一致的节奏；保留现有路由、URL 筛选、API、返回路径和确认行为。会话详情按问答轮次组织，趋势图在跨日期窗口显示日期，避免时间轴歧义。共享筛选、队列检查器和专用编辑器按各页面真实任务组织，桌面与移动端使用同一语义结构。

所有普通选择字段（筛选、模型发现、编辑表单、任务周期和动态业务选项）通过 Ops 内的 `FilterSelect` 组合共享控件：桌面使用共享非模态 `Select` 的触发框、选项菜单及键盘焦点管理，移动端使用共享 `NativeSelect` 调用系统选择器。选项、禁用条件和业务状态仍由页面负责，空值继续保留原来的“不限定”或“请选择”含义；数字周期在页面转换，表单提交保留原参数和 required 语义。具名字段提交真实值，不提交菜单内部的空值标记。移除 Ops 全局 `base-select` 覆盖，控件外观交回共享组件。筛选字段统一使用 `Field` 关联标签；诊断页自定义日期在下一行展开，反馈页使用明确的列宽，避免内容挤压其他控件。请求筛选移除阻断网格布局的额外时间容器，使自定义日期展开后运行范围字段仍保持原行对齐。

普通按钮、链接式操作和群排序手柄复用 `Button`，保留原事件、禁用状态和拖拽绑定；折叠区统一为 `Disclosure` / `DisclosureSummary`，页面继续管理 open/onToggle。输入与选择字段由 `Field` 关联标签、帮助和错误信息，复选行使用 `Checkbox` 与 `Label`。状态、空列表、错误、骨架和 OCR / 检索候选普通表格复用现有共享基础组件，页面只保留业务内容与布局。

通知队列整行选择、交通线路卡片和日历日期、tldraw 图层与画布对话框保持专用交互。Ops DataTable 继续拥有业务列表行为；Markdown / 通知正文表格、动态图片 DOM 适配和趋势图的读屏表格保留原所有权。可编辑的 datalist 和原生日期输入也保留。筛选布局在页面内使用网格与换行，自定义日期占下一行，不增加带状态的 FilterBar。

邮箱筛选改为草稿与已应用条件分离，查询读取和错误只替换结果区，创建授权表单保持挂载。投稿列表把筛选、游标和游标历史交给现有路由参数，详情的返回链接恢复同一查询。时间预设仍立即应用，自定义日期确认后应用，不改变已有时间合同。

菜单和评价使用同一套响应式列表与动作渲染，避免隐藏视图通过 Portal 同时打开第二个弹窗。用户和账号操作记录在窄屏保留身份、状态与业务字段；DataTable 将 stickyRight 条件先合并再计算类名，修复布尔值绕过 sticky 样式的问题。OCR 保留连续阅读并增加页码定位，重跑和索引回滚复用已有 ConfirmDialog，提交失败仍留在原确认框，待处理时阻止重复提交和关闭。回滚文案与服务端暂停 Schedule、提交索引回滚任务的实际行为一致。

概览在手机端先展示当前问题，图表使用明确链接；通知问题入口靠近队列，交通编辑器显示所选线路、来源与日期范围，模型配置分为生成、检索、分类、OCR，门户使用一个页面主标题和两个业务区段。保持群目录已有键盘排序、地图编辑器的草稿与发布分层，不增设路由或统一表格转卡片框架。实际验收后移除定时任务页的三个旧通知兼容任务及其 API，通知调度只保留统一流水线；OCR 与门户凭据检查按实际后端能力保持只读，退役理由见[统一流水线决策](2026-09-20-notice-pipeline-unification.md)。

真实后端的有数据验收发现：食堂菜单在手机上每行约 257px，长评价接近一屏，举报表格重复展开当前与举报时正文，且 768px 下左右固定列只给中间内容留下约 110px。菜单因此改为按窗口分组的单一紧凑列表，菜品标识与更新时间移入编辑详情；同一窗口的排序仍使用既有全量顺序接口。评价使用同一套摘要列表与既有全文编辑详情，窗口名称复用地图查询，不再在主列表反复展示内部标识。投稿列表在较宽桌面使用表格，平板和手机使用紧凑列表；详情前置当前内容，将举报、编辑历史、作者与处理信息放入共享标签页，默认展示举报。

举报列表仅承载目标摘要、举报理由与处理状态；完整正文、举报人和历史快照放入共享 Sheet，正文独立滚动，处理动作固定在底部。内容版本变化或历史不可回放时默认展开举报时内容，其余按需展开。投稿自身与其评价的举报仍分别处理，确认框继续使用现有版本与处理接口；选中记录按目标类型与举报标识共同定位，并随查询刷新，不复制另一份服务端记录。保留公开、隐藏、删除、到期与清理状态的原有行为。

逐项操作验收进一步发现：举报跳到投稿后丢失原筛选与选中项，状态切换时旧查询结果进入新标签，连续阅读必须关闭并重新打开。举报页因此沿用投稿列表的 URL 状态方式，保存目标、状态、投稿筛选、游标历史和当前举报；投稿返回链接恢复整个举报队列上下文。共享举报抽屉增加本页上一条、下一条，切换记录重置正文滚动和历史展开状态，关闭后聚焦当前记录，记录处理后移除则聚焦队列。举报与评价跨筛选查询不再复用上次结果，读取中保留筛选表单，仅结果区域显示加载状态。

共享组件复核后，Ops 在应用根样式统一文字按钮与输入框的 8px 圆角及 44px 常规控件高度，Portal 弹窗因此与页面保持一致；Campus 保留默认胶囊按钮。共享 Button 以颜色提供按压反馈，取消整体缩放，避免整行举报入口随点击收缩。表单原生与自绘选择框共用内部基础样式及独立控件表面，只读输入也保留完整焦点环；菜单项统一 8px 圆角，已选值同时以背景、文字和勾选标识表达。Tabs 与 ToggleGroup 的分段表现统一，保留各自的键盘语义。

Ops 按实际用途迁移按钮层级：创建、保存和显式搜索突出，刷新、分页、详情、排序与列表轻操作减少描边；普通命令与取消使用中性填充。举报的保留与隐藏使用同级触发按钮，不预设审核结论，确认框继续表达已选操作的后果。模型密钥显示按钮与输入框对齐，用户和邮箱列表的小按钮改用共享响应式尺寸。

真实页面复现桌面选择框展开后整页无法滚动，关闭才恢复；根因是原 Radix Select 固定启用滚动锁。共享 Select 因此改用 Base UI 并固定 `modal={false}`，输入和选项视觉保持共享样式，长选项列表独立滚动。页面传入值与显示标签，不扫描子节点生成隐式选项数据。菜单挂载到最近的 Dialog / Sheet 内，并通过 Radix DismissableLayer 参与既有层级，避免焦点被外层弹窗拉回、Esc 同时关闭两层；背景弹窗锁仍归弹窗所有。OCR 页码跳转继续通过关闭焦点回调定位正文。

问答运营主导航收敛为问答概览、历史会话、回答反馈。运行记录保留二级入口和原 URL，执行详情以结果、执行过程、检索与引用标签组织，异常摘要始终可见。概览优先展示同时间范围的关注请求，使用完整查询总数而非预览条数；无数据、数据不可用、请求失败和等待用户保持独立语义。

会话摘要改为从最新 dispatch 关联该轮问题与回答，解决新问题错误搭配上一轮答案；反馈数量使用与列表相同的时间和请求条件，但忽略 vote 与 cursor，使三个评价入口保持可比较。API 形状与数据库结构不变。会话高级筛选折叠，语义标为“最新一轮状态”，会话及运行记录复用既有游标历史。反馈详情宽桌面分栏、窄屏全宽 Sheet，选中项保留在 URL，本页连续阅读重置正文滚动并恢复关闭焦点。

返回链接改用路由导航，列表查询和消息定位继续随 URL 传递，路由滚动恢复按页面查询保存阅读位置。反馈选中项不改变列表滚动标识，详情滚动容器按反馈标识区分。评价切换采用共享单选 ToggleGroup；恢复焦点不会自动提交评价筛选。时间控件显示请求开始、会话活动或反馈更新时间；反馈保留默认全部时间。

历史会话复核发现桌面首条记录位于约 412px，筛选容器与查询说明占用较多高度，标题、最新问题和回答缺少明确区分。列表改为紧凑工具栏，手机搜索与时间占两行，桌面共用一行；高级条件与精确查询时间在下方展开，自定义日期独占后续行。清除条件移至筛选旁，整行使用原生路由链接，正文限制摘要行数，宽桌面将最新状态、活动时间和用户集中于右侧，窄屏顺序排列。会话详情使用居中的限宽阅读区，问题以浅色底区分，来源、反馈与运行入口仍随对应回答或轮次展示，会话信息移至正文之前折叠。

历史会话进一步改为队列与阅读区工作台：1280px 及以上保留 21rem 宽队列，两区独立滚动；窄屏单栏切换。列表复用摘要接口，选中会话由既有详情查询读取，`conversationId` 和 `messageId` 进入列表 URL，时间与分页参数保持原含义。上一条、下一条仅在当前页选择，独立详情仍可由运行、反馈或阅读区进入。轮次导航复用共享选择器，首末轮按钮与选择完成后聚焦正文；从执行详情带消息定位返回时，容器不抢占目标消息焦点。未指定消息的移动端阅读先聚焦阅读区，返回队列聚焦原会话。

用户定位会话是常用入口，因此把筛选从窄队列移到整个工作台顶部。常驻用户、会话内容和最近活动时间，状态、反馈与失败条件在下一行展开，应用后的条件可逐项移除。用户名称和邮箱按不区分大小写的字面片段匹配，完整用户 ID 精确匹配；App API 复用已有用户关联，在分页前与内容、时间等条件取交集。`ownerQuery` 进入合同、路由和查询缓存键，已有 `ownerId` 精确过滤保留。移动端列表头合并结果统计与刷新，阅读时隐藏筛选，返回后恢复；不引入额外用户选择弹窗或新查询端点。

Ops issue 收尾发现来源卡片已使用配置的 Campus origin，而正文 Markdown 仍原样输出相对通知链接。正文渲染现在读取本条回答已有的归一化来源动作，按通知或文档路径及锚点匹配目标；三个回答阅读入口统一传入来源，不修改数据库正文或新增公共配置接口。匹配不到可用动作时保留文字，外部绝对链接保持原地址。任务状态读取失败显示具体任务名称，原始 Kubernetes / Temporal 错误收进技术信息，避免响应头和 JSON 挤占布局。

任务与内容阅读继续按当前操作提供摘要。通知流水线的 Schedule 包装执行仅在没有启动实际 child 时单列，
已启动 child 的包装执行由 child 代表，关系使用 Temporal 的实际执行信息；跳过或启动失败不能因去重丢失。
Kubernetes 任务只表达 Job 执行结果，不把进程成功等同于每个业务对象成功。通知任务中心和定时任务复用阶段
摘要投影，保留每阶段的结果与已有计数，Temporal 失败不再使用 Kubernetes controller 标签。
运行中的活动按 Temporal 的真实状态区分等待执行、执行中和取消／暂停；阶段名称、尝试次数、
本次开始时间、尝试上限、下次尝试时间、最近状态上报、处理步骤与区间直接可读，缺失上报不推断为零进度或正常运行。
心跳代表活动存活状态，不代表处理数量发生变化，因此页面称“状态上报”；已运行时间与结束耗时独立展示。
调度开关与当前运行并列，暂停后仍在执行不会遮蔽调度状态。运行未结束时显示结果待完成，
历史结果保留采集、分类、发布、索引、清理的各自结果；原始 JSON 仅作为折叠的技术信息。
运行中和异常终止的阶段结果从已有 Temporal History 中的活动完成、失败与超时事件投影，
再合并 Describe 的当前活动与心跳；通知维护与定时任务共用这一投影。这样后续分类或索引失败不会
抹掉已完成的采集结果，超时后的最后进度也不会继续显示为执行中。成功结束的流水线继续使用最终业务摘要。
历史已记录活动完成时，以完成事件为准，避免较早的 Describe 快照把终态覆盖为运行中。
进度条仅表达已知分母的当前步骤进度；扫描列表不等于采集写入成功，也不代表整条流水线的完成比例。
等待执行单独显示等待时间，重试期间注明进度来自上次尝试；本轮耗时包含排队，不能标成实际采集时长。
失败展示 SDK 或 Temporal 的原因链，以保留应用错误，而非只显示通用 Workflow 失败。
这些字段来自已有 Describe、History 和结果接口，不新建进度持久化、故障判定或重试机制。

评价和账号准入的已应用查询、游标及返回历史由 URL 保存；输入草稿独立于已应用查询。
用户详情允许从账号准入和投稿详情返回原位置，投稿窗口复用现有地图目录名称，不读取或改造画布。
同好群搜索只过滤显示，编辑和删除仍提交完整目录；过滤期间关闭拖拽排序，避免把子集当作完整顺序。
班车历史时间段默认折叠，直接定位历史时间段时展开。会话队列通过现有 Markdown 解析器显示可读摘要，
链接仅保留文本，完整回答不改写。

## 未采用方案

会话继续采用整页跳转能够复用独立详情，但频繁扫描不同会话需要反复返回，因此桌面使用嵌入阅读；手机宽度不足以同时呈现两栏，保留单栏切换。

不引入新的视觉品牌或独立设计系统；这会增加主题维护成本并改变现有产品识别。也不把所有内容包进卡片，因为密集表格和编辑器需要连续的内容流。

原生选择器能够直接保留平台交互，但继续叠加 Ops 专属 picker CSS 无法与现有共享菜单保持一致，因此桌面复用已有 `Select`，移动端保留系统选择器。组合组件留在 Ops，不扩展共享包的业务接口。

直接缩小表格字体和固定列宽可以减少少量高度，但无法解决手机全文重复与平板正文被挤压，因此这四页采用按任务组织的列表、标签页和详情抽屉，而不继续增加固定列或共享表格适配规则。

缩淡所有边框能减少视觉重量，但输入框与选择框仍需满足既有 3:1 边界对比度，因此保留控件边界并减少辅助按钮的描边。没有为 FilterSelect 新增尚无差异行为依据的 size/appearance 接口；页面继续拥有字段宽度与排列。

不通过全局覆盖 body overflow 或删除滚动锁样式解决选择框问题，这会绕过事件拦截并破坏弹窗背景锁。也不维护 Radix Select 私有实现补丁；当前共享选择器是唯一需要非模态能力的 owner，替换其底层组件即可，其他 Radix 组件和 tldraw 专用选择器保持原所有权。

## 后果

- 所有 Ops 路由继续使用现有 API、URL 参数和返回导航；共享壳层仅调整呈现和信息层级。
- 桌面导航、移动抽屉、跳过链接和主题切换继续使用原有可访问语义。
- 23 个路由在浅色 320px、390px、768px、1024px、1440px 和深色 390px、1440px 下生成了 161 份截图；对应 DOM 检查均无页面级横向溢出，且每页主内容恰有一个 h1。通知队列在桌面选中后进入队列与检查器分栏，移动端保持抽屉。
- 多日趋势的横轴按北京时间日期区分；会话详情保留消息定位、来源展开和运行详情链接。
