# Agent Note: Temporal 执行面

Status: implemented

## 背景

在线回答必须能跨浏览器断线继续执行，支持取消和超时，并产生持久且产品安全的投影，不能让
PostgreSQL 记录或一次 HTTP 请求充当调度器。

模型运行时还需要一致的模型与工具循环；Temporal 拥有持久执行，不能复制 operation 内的语义工具选择。

## 决策

Temporal 是在线工作流引擎。PostgreSQL 只保存有界 run/event/step/result 投影以及投递命令和
幂等 receipt，不保存 workflow history 或队列状态副本。

早期设计用稳定阶段包裹一次完整 SDK run；后续 [Agent Workflow 决策](./2026-07-29-agent-knowledge-tools.md)
引入 Solve、Execute Step、Replan 和 Synthesize operation。旧 Activity 粒度和 execution-control
编排所有权已由[Agent 编排与 Memory 独立服务](./2026-10-10-agent-orchestration-memory-services.md)
部分取代：agent-runtime 的 TypeScript Workflow 拥有执行顺序，单次模型请求和外部工具调用分别是
Activity；agent-control 拥有准入、命令与查询、有界投影和终态写入。Search 内部 embedding/rerank
不展开为 Runtime Activity。本文的 Temporal 与 PostgreSQL 边界继续有效。
精确阶段、worker 池与终态校验见持久运行架构。

创建 run 与启动命令必须在 agent-control 的同一事务提交，由 reconciler 幂等启动固定
Workflow ID；同步 HTTP 返回不是“Temporal 一定已启动”的证据。取消由 app-api 校验归属后调用
agent-control，由 agent-control 持久化并投递；app-api 不复制取消命令或维护本地 outbox。

原始执行输入由 app-api 以精确文本和 hash 拥有。Temporal 输入/history 与 agent-control
投影只保存 ref/hash 和有界标识，不能复制 prompt、会话或认证正文。

单次模型 Activity 通过 Control 的持久 turn receipt 取得首次执行权；结果不确定时阻断，已完成时
恢复保存结果。operation 完成载荷单独用于修复投影，不再创建 operation 级模型 receipt。
Activity 重试不是供应商调用重试，具体策略由运行架构维护。

取消和超时必须从 Temporal 传播到 Agent Activity 和进行中的内部或供应商调用。取消后的终态
写入使用 `CancellationScope.nonCancellable`，避免 cancellation 跳过持久 closeout。app-api 产品终态
和 fingerprint 裁决跨系统竞争；run 已终态后，较晚完成不得覆盖它。

## 未采用方案

- **PostgreSQL queue**：会重复 workflow 重试、timer、heartbeat 和取消语义。
- **每个工具或语义能力一个 activity**：早期担心拆散 SDK 循环并产生多个语义所有者，因此未采用。
  该粒度决定现已被取代；模型请求和外部工具 Activity 仍由单一 Runtime owner 编排。
- **同步 HTTP 生命周期**：浏览器连接不能拥有回答运行。

## 后果

- 浏览器订阅持久状态和临时回答增量；正文 delta 不写入持久事件，最终答案单独持久化。
- API 接受只证明产品请求和稳定运行输入已持久化；只有 agent-control 确认同一 run 后才发送
  `request.accepted`，不把命令投递伪装成 queue 状态。
- Control API、Runtime Worker、Memory API/Worker 的部署职责由
  [Agent 编排与 Memory 独立服务](./2026-10-10-agent-orchestration-memory-services.md)维护。
- operation 内的 SDK turn 预算与外层计划、重规划预算分开，具体预算由运行合同维护。
- 工具 Activity 的调用结果投影为诊断轨迹；Control 不复制 Runtime Workflow 的执行图。
- 合同、身份与运行一致性错误保持失败；普通来源失败保留已有材料，按当前工作流条件继续或综合，
  不把来源失败等同于整轮失败，也不因合法追问或资料不足说明没有 evidence 而拒绝终态。
- 在线索引知识不提供实时公网搜索回退。
