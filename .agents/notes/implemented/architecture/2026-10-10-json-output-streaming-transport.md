# Agent Note: 模型调用兼容性、工具循环与流式接收

Status: implemented

## 背景

Agent 编排迁移到 Temporal 后，真实模型调用暴露了应用传输选择、供应商输出格式及混合工具兼容性
相互叠加的问题。用户要求保留校内搜索、个人记忆和 hosted web search，并停止供应商端的完整
Schema 约束；修复必须让模型调用、工具结果回传和最终回答完整执行。

| 问题 | 已确认的边界 | 对实现的影响 |
| --- | --- | --- |
| 模型名称与协议混淆 | Model Config 决定接口协议，模型名不决定协议 | 切换供应商不隐含切换 adapter |
| 展示决定模型传输 | Temporal 缓冲展示曾走非流式，所用通道存在非流式请求失败 | 模型传输与增量发布解耦 |
| 完整输出 Schema 不兼容 | 所用通道拒绝完整输出 Schema 与工具的组合 | 保留本地合同，移除供应商输出 Schema |
| JSON MIME 触发异常 | 成功结果回传后仍重复调用，搜索只返回用量；移除后恢复 | 移除 JSON MIME |
| 混合工具被拒绝 | 已携带服务端工具调用开关，仍收到要求启用的错误 | 核对实际请求，不能仅依赖错误文案 |
| 来源元数据不完整 | 部分响应只有搜索查询与入口，后续响应也能返回完整 grounding | 不把缺少引用等同于没有搜索，也不宣称供应商永远不提供来源 |
| TLS 与连接异常 | 请求格式修复与连接是否成功是不同层面的问题 | 不把移除 Schema、切换流式或地址族参数当作 TLS 修复 |

重复调用的对照使用同一份已成功的记忆结果，保留函数名、调用 ID、完整模型 Content 和 thought
signature；模型随后生成新的调用，并在检索词中使用已返回事实。它不是 Temporal 重放，也不是
工具结果未送达。仅移除 JSON MIME 后，模型能够正常返回符合合同的 JSON；切换为 AUTO 或展开结果
包装没有解决同一触发条件。这里确认的是当前通道的可复现触发条件，不推断供应商内部实现，
也不将其推广成所有 Gemini 模型的协议限制。

## 决策

Gemini 原生协议对结构化 operation 只通过提示词约定 JSON，不发送 JSON MIME 或输出 Schema；
OpenAI 兼容协议使用 JSON object 模式；
两条路径都保留本地 outputSchema，
将相同合同作为指令提供给模型，返回后解析 JSON 并由 workflow-runtime 执行严格校验。
不删除函数工具参数 Schema，不放宽计划互斥、字段、长度及步骤校验。最终合成继续使用普通文本。
旧 Runner 与 Temporal 单次 model turn 复用请求设置，避免两个入口发送不同输出格式。

Responses 的所有阶段始终使用流式接收；Gemini Temporal 单次调用也始终使用流式接收，
没有回答增量消费者时只是不发布增量，而是在 Runtime 内收集完整响应后返回。
回答展示、取消、截止时间与工具执行预算继续由既有 owner 控制，不用模拟增量或自动重试改变行为。
该选择部分取代[回答双流式模型消费协议](./2026-09-28-answer-transport-stream-buffered.md)中
将 buffered 展示映射为非流式模型请求的规则；原有缓冲投影及 Gemini 原生协议的流式选择继续保留。

模型名称与接口协议分别配置，切换网关不隐含切换协议；Gemini 原生请求保留三个工具及
`includeServerSideToolInvocations`、`VALIDATED`，不为兼容网关删工具或添加未经验证的字段别名。
模型 Activity 复用既有错误分类与日志字段，保留状态码、诊断详情和调用标识，避免只保存通用错误码
而失去故障原因。Worker 与 HTTP 服务统一既有地址族连接尝试参数，不把它当作 TLS 超时修复。

## 未采用方案

供应商执行完整 Schema 能提前约束输出，但当前通道与混合工具组合不兼容，不能作为应用运行前提。
仅保留 JSON MIME 看似能保证 JSON 语法，但仍会触发重复函数调用与搜索空响应，因此一并移除。
减少工具会牺牲用户明确要求的能力，且仅保留托管搜索时仍能复现 JSON MIME 下的空响应。
切换函数调用模式或展开工具结果包装没有解决重复调用，继续保留既有工具协议。
增加重试或重复调用拦截只能限制成本，不能修复正常工具结果后的回答生成，不作为本次修复。
只去掉 Schema 而不描述合同会让计划与重规划缺少字段依据；合同仍由代码生成并供模型参考。
只把回答展示开关改为 stream 改动更小，但不会覆盖重规划及缓冲恢复，且把传输要求强加给产品展示。

## 后果

Gemini 的 JSON 形式及业务合同均由应用校验，不能依赖供应商强制输出；非法 JSON 和非法结构保持
model_output_invalid 语义，不自动修补或重试。TLS 故障独立于本次格式与流式协议调整。
取消输出 Schema 也不代表网关一定支持内建搜索与函数工具混用；原生字段正确序列化后仍拒绝请求的
情况需要由供应商处理，应用不自动换协议或降级工具。模型版本、协议、端点或上游路由变化时，
之前的通道兼容性结论不能直接移用。
恢复 Gemini 的模型侧流式接收只还原拆分前的传输语义，不能掩盖网关对工具组合的独立限制。
协议测试覆盖实际 SDK 序列化、无回调的四类阶段、工具结果回传与本地拒绝非法结果。
模拟响应能证明请求构造和本地解析，却不能证明供应商接受完整工具组合；Model Config 的基础验证
也不能替代完整 Agent 会话。判断修复是否有效，需要区分模型正常结束、工具预算耗尽后的恢复合成
和最终产品终态，不能只看 HTTP 200 或最终有答案。
托管搜索是否返回来源引用取决于供应商的 grounding 字段；只有查询或搜索入口时保留
metadata_only 语义，不把正文中的链接伪装为带 grounding 支持的证据。
