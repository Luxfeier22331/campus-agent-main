# Agent Note: 文档声明与生成发布

Status: implemented

## 背景

文档数量增长但变更频率低，正文、课程图和图片已经保存在对象存储。过去人工维护完整
`campus_docs_source.v4`，业务元数据与派生的 key、摘要、字节数混在同一文件；普通 PutObject 加回读
不能防止并发发布覆盖。用户确认 Git 只保留轻量声明，继续使用固定生成键，不引入 Docs 数据库。

## 决策

- Campus Web 拥有 Git YAML 声明、声明编译器和来源发布器，contracts 提供共用关系与版本校验。
- 正文与附件保留在 RustFS；发布器从真实对象计算既有 v4 合同的摘要与大小，人只编辑元数据和对象 key。
- 保留固定 `campus-docs/source.json` 给静态构建、Docs builder 和本地同步读取；同一份 canonical 字节
  另外保存为内容寻址 release 副本，用于重复发布和恢复。副本不是默认版本指针。
- 来源发布编译一次并保留已读取对象字节和 reader；提取、分段质量门禁只在来源发布边界执行。
  静态构建和本地 Docs closure 复用同一编译结果，Docs index publisher 消费已发布 reader 而不重复
  质量门禁；各消费边界只做所需的身份、布局、课程图或引用关系校验。
  静态构建直接消费编译结果，不再把原始对象另存到无人读取的 `input/objects`；
  保留来源清单、公开资产、路由目录、页面和既有内容就绪元数据。
- 发布开始时捕获 ETag，验证全部版本后条件创建副本、条件更新固定键，冲突返回失败，不自动重试覆盖。
- 复用现有候选流水线，来源发布使用既有写身份，后续静态构建使用只读身份；PR 只检查离线声明。
- 自动化止于来源和 Campus Web 候选。Docs RAG 显式触发，Notice、统一 serving 指针与版本语义不变。
- 元数据含长 ID、中文和冒号，文件布局沿用公开路由 slug 与版本 slug；不修改业务 ID 和公开 URL。

本决策补充[原生阅读器](../feature/2026-08-01-native-reader.md)的来源编辑与发布部分，静态阅读的
数据库独立性、稳定链接和历史版本仍沿用该决定。

## 未采用方案

- **Git 保存全部正文和附件**：能集中审查内容，但不适合现有生成 reader、图片和历史二进制资料。
- **数据库作为 Docs 编辑源**：可提供后台查询和并发编辑；当前低频维护没有这些需求，用户选择 Git 声明。
- **消费者全部显式传递不可变 release 摘要**：可以固定每次输入，但要同时改变静态构建、RAG 与同步入口。
  用户选择保留生成的固定键，接受两条构建链分别更新，不需要强一致切换。

## 后果

新增机制限于真实来源发布者和现有消费者：不可变副本保存可恢复输入，ETag 条件更新替换旧覆盖流程；
发布成功后的固定键不再做无增益回读；不可变副本发生抢占时仍读取已存在字节比较冲突。
质量门禁与下游结构校验分层，避免同一 reader 在每条消费链重复执行相同提取和分段检查。
不增加通用 artifact 服务、数据库状态或文档运行时 API。若来源维护改为独立 CMS，再重新评估编辑源和
发布 owner；现有消费者全部改为显式不可变输入时再移除固定键。

迁移保留原始对象 key，声明导出再生成应与既有 canonical manifest 等价。旧 `--source-file` 入口保留
一个发布周期作迁移恢复；所有消费者切换到不可变输入后删除旧入口。
保留的 release 及引用对象受现有人工清理边界保护，不增加自动清理器。

操作、字段和失败处理分别由[维护手册](../../../../docs/runbooks/ingestion/campus-docs.md)、
[阅读器数据](../../../../docs/data/document-reader.md)和[交付合同](../../../../docs/contracts/document-reader-delivery.md)维护。
