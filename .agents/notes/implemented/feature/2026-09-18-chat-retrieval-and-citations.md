# Agent Note: 检索状态与正文来源预览

Status: implemented

## 背景

校内工具已经实际检索，但浏览器只能看到生成阶段；正文数字链接也未绑定当前消息的来源数据，
相邻引用显示为连续数字，无法查看来源标题。对应 #341、#518、#495、#519。

## 决策

- 复用 operation SSE、execution-control 持久事件和 App API 回放。Runtime 从实际工具生命周期产生
  校内检索状态，Executor 流仅交付状态与终态，不向学生展示步骤摘要。
- 同类并行调用在 operation 内归并；队列、候选来源和最终 grounding 不充当开始信号。诊断仍独立，
  不把查询参数或工具 ID 投影到浏览器。
- 保留已校验 Markdown 和 source_items 合同。前端以当前消息完整来源映射渲染独立角标和 Popover，
  复用来源卡标题、摘要、favicon 与打开入口；不可用来源不提供悬空交互，历史消息不迁移。

## 未采用方案

- 以工具可用或最终来源推断检索开始，能少改接口，但会显示未发生的搜索，无法满足真实状态要求。
- 把正文迁移为另一种引用格式可简化新 renderer，但已有 Markdown 与来源编号足以支持预览，
  本轮没有迁移历史数据的必要。
- 浏览器另行抓取标题或引入永久 smoke 命令，会重复后端来源解析职责并增加运行成本。

## 后果

- 事件与交互由定向 Runtime、Go、App API 和组件测试验证；实际浏览器验证按需使用本地服务。
- 网页搜索由模型内部处理，不产生产品检索状态；只展示实际 campus_search 调用的状态，grounding 继续承载来源引用。
- 来源相关性与置信度不在本次范围；原站解析继续由既有 Gemini 来源解析器负责。
