# Agent Note: 检索状态与正文来源预览

Status: implemented

## 背景

校内工具已经实际检索，但浏览器只能看到生成阶段；正文数字链接也未绑定当前消息的来源数据，
相邻引用显示为连续数字，无法查看来源标题。对应 #341、#518、#495、#519。

## 决策

引用语法由 Goldmark CommonMark/GFM AST 决定，只在原始文本片段内识别数字分组。
这修复了手写扫描把相邻裸编号误认作参考链接的问题；有真实定义的参考链接仍是链接。
不渲染或重新序列化整段正文，继续使用原始字节位置替换；Go 与前端共享 Markdown 用例。

- 复用 operation SSE、execution-control 持久事件和 App API 回放。Runtime 从实际工具生命周期产生
  校内检索状态，Executor 流仅交付状态与终态，不向学生展示步骤摘要。
- 同类并行调用在 operation 内归并；队列、候选来源和最终 grounding 不充当开始信号。诊断仍独立，
  不把查询参数或工具 ID 投影到浏览器。
- 保留已校验 Markdown 和 source_items 合同。前端以当前消息完整来源映射渲染独立角标和 Popover，
  复用来源卡标题、摘要、favicon 与打开入口；不可用来源不提供悬空交互，历史消息不迁移。
- 对话内“查看通知”打开居中 Dialog，保持当前路由与对话挂载；从引用 Popover 打开时先收起 Popover，
  关闭后焦点回到引用编号，来源卡入口则回到原按钮。支持 Esc、关闭按钮与遮罩关闭。
- Dialog 与完整通知页共用正文、元数据、附件及既有 HTML 处理，沿用通知查询键与缓存，打开时才读取。
  桌面宽度不超过 840px、高度不超过 85dvh，移动端保留边距、高度不超过 90dvh；正文独立滚动，
  标题和底部操作固定。保留完整通知页及信息门户的新标签入口。

## 未采用方案

- 以工具可用或最终来源推断检索开始，能少改接口，但会显示未发生的搜索，无法满足真实状态要求。
- 把正文迁移为另一种引用格式可简化新 renderer，但已有 Markdown 与来源编号足以支持预览，
  本轮没有迁移历史数据的必要。
- 点击通知直接离开对话便于复用整页，但打断核对依据与继续追问；侧边阅读面板未被用户采用，选择居中 Dialog。
- 浏览器另行抓取标题或引入永久 smoke 命令，会重复后端来源解析职责并增加运行成本。

## 后果

- 事件与交互由定向 Runtime、Go、App API 和组件测试验证；实际浏览器验证按需使用本地服务。
- 网页搜索由模型内部处理，不产生产品检索状态；只展示实际 campus_search 调用的状态，grounding 继续承载来源引用。
- 来源相关性与置信度不在本次范围；原站解析继续由既有 Gemini 来源解析器负责。

2026-09-30 通知预览验证：组件回归覆盖按需加载、缓存复用、正文/图片/表格/附件、失败重试和引用焦点恢复，
原通知详情页回归通过。Playwright MCP 在当前 worktree 验证真实通知、URL/输入草稿保持、Esc/遮罩关闭、
引用弹层切换与移动端布局；小高度窗口中 PageDown 只滚动正文，标题保持固定。
真实回答在 Dialog 保持打开时完成；完整通知页可在新标签访问，关闭预览后对话滚动位置保持。
