# Agent Note: 食堂页面布局、视觉、搜索与移动端详情

Status: implemented

## 背景

食堂地图选中窗口只把填充改为接近窗口底色的选中灰，桌面和手机都难以分辨当前窗口；窗口详情切换和
楼层切换没有过渡，内容替换不易察觉。手机端平面图按总览缩放后窗口标签只有数像素，学生只能先捏合放大，
不满足[界面体验基线](../../../../docs/product/ui.md)对移动端任务导向列表的要求；定位到详情后地图离开视口，
换窗口需要手动滚回。食堂切换的长名称和缩放提示在窄宽度下折行，详情区边距和分隔线也不一致。

后续按学生找吃的、看菜单和走到窗口的任务复查：平面图渲染器把结构、分区和地标写成固定浅色，深色外观下
出现大面积白块，浅色下无标签的结构格又与窗口相似；窗口搜索只覆盖当前食堂，想吃某类菜时必须先猜食堂；
正式菜单为空时只有一句空状态；更新时间以秒级时间戳展示；每次进入都回到
第一个食堂，另一校区学生需要重复切换；桌面总览下窗口标签约 11 屏幕像素。

再次按页面整体复查：地图卡片内依次叠放楼层与搜索工具栏、缩放条和更新时间行，1440×900 下更新时间已在
首屏之外；全校搜索仍放在楼层级的卡片里；食堂分段与楼层分段分处两个容器；详情只是带左分隔线的一列。
本地 45 个窗口的正式菜单与用户投稿全部为空，每个详情都并列两个空状态。手机端详情在地图下方，选择窗口
后地图离开视口，只能靠“回到地图”补救；校园地图页已采用地图优先、控件浮在地图上的形式。

## 决策

- 选中窗口改用 `--campus-selected-foreground` 的 4px 描边、选中表面填充和加粗标签。悬停与焦点保持较浅的
  选中边框，且不覆盖已选中窗口；颜色经 Dining 专属 Token 映射，深浅主题共用规则，不使用主操作色。
- SVG 过渡改用共享的 `--motion-duration-fast` 与 `--motion-easing-standard`。Dining 页面接入现有
  `CampusMotionProvider`：详情按窗口使用 `stateSwap` 淡入，平面图按楼层淡入。减少动态效果时由 Provider
  去除位移，只保留透明度，与 Campus 其他页面一致。
- 页面改为地图优先：标题下方是食堂下拉和全校搜索，与地图同列；楼层分段浮在地图左上角，缩放控件与
  手势提示浮在底部。平面图高度按宽度等比计算后上下各加 4rem 画布留白，浮动控件只压在留白上；最大缩放
  仍取宽高中更紧的一边，留白不改变计算结果。平面图不可用时楼层分段回到降级列表顶部。
- 食堂切换在所有宽度统一为按校区分组的下拉，九个食堂不再占用整行分段。
- 食堂下拉、全校搜索与“我的投稿/返回食堂地图”按钮改为填充式控件：无边框，用 `bg-surface-muted`
  填充区分于页面背景，hover 加深为 `bg-surface-hover`，聚焦/展开浮起为 `bg-surface-raised`。食堂下拉
  需用 `enabled:hover:` 与 `data-[popup-open]:enabled:hover:` 覆盖 `SelectTrigger` 自带的高特异性
  `enabled:hover:border-ring`。搜索框聚焦不加 ring：填充式控件的白底浮起已是焦点指示，再叠校园全局
  灰色焦点环（`--campus-focus-ring`）会像残留描边，键盘聚焦时白底变化仍可见，无障碍不受影响。
  全局 `controlClass` 的描边样式与表单页输入框不受影响；楼层分段本就是填充式，三控件视觉统一。
- 桌面详情是右侧独立卡片，吸顶并在卡片内滚动。小于 1024px 时，同一节点变为固定在底部的非模态面板，最多
  占 55dvh，可收起为标题行或关闭；关闭清除 URL 中的窗口，焦点回到对应 SVG 窗口。选择窗口时若平面图被
  面板遮挡或离开视口，把地图滚到顶部，取代“回到地图”和滚向详情的定位。
- 小于 1024px 时，在平面图下方显示“本层窗口”列表，复用平面图降级时的同一个窗口列表组件，以及相同的选择、
  搜索过滤和定位规则。平面图不可用时只显示降级列表，不重复渲染。
- 楼层分段选项不折行；手机端缩放提示按状态显示“双指缩放”或“单指拖动地图”，不再固定两行说明。
- 详情区去掉单独的横向内边距，与投稿区左对齐，分隔线统一为 `border-border/70`；未选窗口的空状态改为
  左对齐的图标和说明。
- 平面图配色由 Campus 在交互样式中覆盖渲染器的固定颜色：该样式追加在资源自带样式之后，同等选择器下
  生效，结构、分区、地标、区域、轮廓和入口映射到随外观切换的 `--dining-svg-*` Token。结构格在浅色下
  接近画布、分隔线变细，窗口保持唯一的高对比可选块。渲染器保留固定颜色作为原始资源与 Ops 的回退，
  已发布资源无需重新生成。
- 窗口搜索覆盖整份已读取地图，结果按“校区 · 食堂”分组且当前食堂优先，选择后复用既有定位；不新增接口。
- 正式菜单为空时不显示菜单分区，投稿区说明暂无正式菜单；两者都为空时合并为“还没有菜单和用户投稿”一个
  空状态，只保留投稿区原有的“投稿”按钮。投稿区复用详情已缓存的菜单查询判断，不增加请求；菜单项价格
  右对齐。
- 手机端搜索时，本层无匹配的“本层窗口”列表与工具栏提示一致，引导从搜索结果选择其他楼层或清除搜索。
  搜索结果弹层宽度跟随输入框，不再贴靠视口边缘。
- 深色外观下窗口填充提高一档、选中填充使用按下态，使窗口与同为深色的地标、结构格区分。
- 地图更新时间按上海日历显示今天、昨天、月日或完整日期，完整时间进入 `title`，文案标明是地图版本时间。
- 浏览器 `localStorage` 只记住上次主动选择的食堂（切换食堂或选择其他食堂的搜索结果）。URL 指定的食堂
  始终优先，记录的食堂已不存在时回到第一个食堂；楼层、窗口和缩放仍不持久化。
- 窗口标签以 16 个 SVG 单位为下限，按窗口框在 22、20、18 中选择能完整显示名称且行数不多于 16 单位
  布局的最大字号，部分取代[食堂地图阅读、手势与往返导航](../bug-fix/2026-09-18-dining-map-navigation.md)
  中“标签使用 16 个 SVG 单位”的条目；最大缩放仍按该笔记计算。

## 未采用方案

- 手机端默认放大地图或增大 SVG 标签字号：不新增控件即可改善可读性，但会破坏完整楼层总览和
  [食堂地图阅读、手势与往返导航](../bug-fix/2026-09-18-dining-map-navigation.md)确定的字号与缩放计算，
  也无法解决一次看全窗口的问题。
- 窗口列表在桌面端也显示：入口更统一，但桌面地图标签可读，侧栏已承载详情，重复列表只增加扫描负担。
- 列表使用横向滚动的 chips：节省纵向空间，但窗口多时需要横向探索，可发现性弱于换行网格。
- 页面入场、列表错开出现或弹簧动画：视觉更丰富，但不表达状态变化，与基线中“动效只服务层级理解”冲突。
- 修改渲染器颜色并重新生成已发布资源：能让资源自身适配主题，但需要重新发布全部楼层，且 SVG 资源不应
  感知 Campus 的外观模式；由消费端映射 Token 只改变展示，不改变资源合同。
- 搜索菜品名称：更贴近“想吃什么”，但菜单按窗口懒加载，需要新的跨窗口查询接口，超出本次范围。
- 记住楼层、窗口或搜索词：能完全恢复上次位置，但会与分享链接和“切换楼层恢复总览”冲突；食堂是跨校区
  学生每次重复的那一步，只记这一项。
- 空菜单中再放一个“分享菜品”按钮：曾实现并经浏览器复查撤回。它与约 120px 下方的“投稿”打开同一 Sheet，
  正式菜单普遍为空时每个窗口都出现两个等价入口。
- 手机详情使用 vaul 模态抽屉：与校园地图的地点弹层一致，但会遮住地图、阻止直接换窗口，且评价、投稿
  抽屉要从抽屉中再叠加一层；常驻非模态面板保留地图交互，现有抽屉不变。
- 手机地图拉高到约半屏：画布按宽度等比缩放，拉高只增加上下留白，楼层平面不会变大。
- 保留食堂分段行：能一眼看全食堂，但九个选项占满一行并与楼层分段形成两套同形控件。
- 按词边界换行窗口标签：可避免“基本伙精/品菜”式断开，但需要分词并改变字号选择规则，本次不做。
- 统一放大全部标签：实现更简单，但小窗口会被截断或换行，名称反而更难读；按窗口框选择字号并限制行数。

## 后果

改动只影响 Campus Web 的 Dining 页面表现，不改变 API、地图资源、URL 合同或数据所有权；新增的浏览器
存储只有上次食堂一项，清除后回到默认食堂。若渲染器以后改用主题变量输出颜色，应删除 Campus 端覆盖；若
搜索改由服务端提供或支持菜品名称，重新评估分组与当前食堂优先规则。窗口列表与地图
共享选择入口，以后调整选择或过滤规则时两处同时生效。若移动端地图标签以后能在总览下直接阅读，应重新
评估窗口列表；若详情面板需要拖拽高度或更多内容，应重新评估非模态面板与现有抽屉的叠放。浏览器旅途覆盖
了列表选择、面板收起与关闭；动效节奏和视觉强调仍依赖人工浏览器验收。
