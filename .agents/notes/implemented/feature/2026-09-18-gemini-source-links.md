# Agent Note: Gemini 来源链接解析

Status: implemented

## 背景

Gemini grounding 返回的是 Google 的中转地址和通常不完整的来源标题。统一模型网关被多个业务共享，不能在网关层加入项目专用展示逻辑；本项目需要在 agent-runtime 内把新回答的来源卡片和正文引用还原到真实页面。

## 决策

- agent-runtime 只对 Gemini grounding 的公开 Google redirect 进行解析：跟随有限次数的 HTTP 重定向及独立脚本页中的静态 `window.location.href` 字符串跳转，验证目标地址和 DNS 结果不是本机或私网地址，再读取有限大小的 HTML 页面标题。
- `WebEvidence.url` 始终保留原始 grounding 地址作为证据身份和去重键；`sourceLink.href` 单独承载可展示的真实页面地址。
- 页面标题成功时使用真实标题；标题读取失败时保留可用直链，并依次使用有意义的上游标题或“网页标题暂不可用”加主机名。地址解析失败时保留答案和编号，但来源卡片不可点击并显示“来源暂不可用”。
- 静态脚本跳转只匹配完整的单语句独立页面，不执行 JavaScript，不解析动态表达式；与 HTTP 跳转共用次数、取消和公开地址校验。
- 不可用来源的 `unavailable_reason` 必须通过最终化严格合同；验证从 `WriteWorkflowFinalization` 入口覆盖到产品回调与完成状态，不能仅凭来源生成测试认定链路可用。
- 来源展开按钮与操作栏保留 12px 间距，以容纳图标按钮向上扩展的 10px 点击区域。
- Web 来源卡根据最终展示 URL 的 origin 请求 `/favicon.ico`，只作为前端装饰；请求失败回退到本地图标，不进入 evidence、去重或持久化合同。历史 Google 中转 URL、不可用来源和内部校内来源不发起外部 favicon 请求。
- 解析受单来源、整批超时和并发上限约束，支持取消；不做持久化缓存或自动重试。生产 server 注入解析器，直接使用 runner 的单元测试和受控 fixture 不发起网络请求。
- HTTP、Temporal、app-api 和 Campus Web 传递可空的 `source_link`；旧消息不回填，新消息才使用真实标题和直链。正文引用与来源卡片使用同一展示链接。

## 未采用方案

- **修改统一模型网关**：网关由其他业务共享，项目专用 URL 解析和标题语义不属于其 owner。
- **在浏览器中解析或用浏览器自动化**：增加客户端延迟和资源消耗，也会把网络安全边界下移到用户端。
- **替换原始 evidence URL**：会破坏证据身份、去重和历史合同，因此使用独立的 `sourceLink` 字段。
- **解析失败时猜测 URL 或阻断回答**：无法证明目标页面时不生成可点击链接，同时保留已生成的回答和引用编号。

## 后果

新 Gemini 回答在来源卡片显示原站页面标题并直接打开原站地址；无法解析的来源仍被编号展示但不可点击。解析器只允许公开 HTTP(S) 页面、限制响应大小和跳转次数，并在每个 DNS 跳转处拒绝本机及私网目标。验证覆盖了重定向、标题编码、失败保留、重复来源、取消和并发上限；真实公网样例已取得“民大概况-中央民族大学”及其原站地址。部署环境仍需具备访问 Google redirect 和目标页面的出网能力。

本决策部分取代 [Agent 输入输出](../architecture/2026-07-16-agent-io.md) 中“解析跳转获取原站域名”的未采用方案；该笔记关于输入信任边界、终态校验和跨轮 evidence 生命周期的其他内容继续有效。
