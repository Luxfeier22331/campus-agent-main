# Agent Note: 原生公开文档阅读器

Status: implemented

## 背景

文档阅读需要目录、稳定锚点、历史版本、本地搜索、真实 404 和无 JavaScript 的正文。Rspress 在
Campus Web 中引入了独立主题、第二套路由和搜索模型、额外静态命名空间及较重构建，仍需定制产品
导航和发布适配。

早期原生阅读器设计又把部分文档接入 App API 准入和 PostgreSQL 投影。当前产品不需要账号可见
文档，保留这条动态链会让公开阅读依赖认证、数据库和两个版本选择点，并增加无法证明价值的兼容面。

旧 ADR-0051 为共享来源卡片的固定链接、版本、锚点和高亮身份选择 Rspress；同时让公开正文随
Campus Web 交付，受限正文与索引经 App API 准入，Worker 与数据库投影固定到同一 release。
这避免逐页动态返回公开全文，却增加了受限资产、权限和双端 release 一致性的维护责任。

## 决策

- Campus Web 使用已有 React、TanStack Router 和共享组件实现 `/docs/*`；
- 所有已发布文档及历史版本都是公开内容；
- `/docs`、每份文档、历史版本和文档 404 在构建时生成独立 HTML；
- 正文进入预渲染 HTML，禁用 JavaScript 时仍可阅读；
- 全部阅读资产位于 `/_docs/**`，当前版本搜索索引由 FlexSearch 在浏览器 Web Worker 中查询；
- 文档页面不请求 Better Auth、App API 或产品 PostgreSQL；
- Worker 只交付静态文件并为缺失路径返回真实 `404`；
- 普通应用与文档阅读器使用不同前端入口，共享产品组件但不共享文档代码分块；
- Campus Web 在构建时读取固定来源清单，核对其引用并生成完整静态内容；`sourceDigest` 只记录在
  构建和候选元数据中，不进入 Worker 运行配置。

本决策只覆盖公开文档阅读器，不改变独立维护的知识检索系统。

站内进入文档目录、切换文档或版本时，使用 Motion mini 对已加载的内容执行统一进场：淡入并从下方 6px
进入，读取共享 `--motion-duration-standard` 和 `--motion-easing-standard`；现有箭头与
permalink 过渡也复用共享 token。动效由文档页面拥有，只动画 `opacity` 与 `transform`。正文页只让
面包屑以下的内容进场，导航外壳与面包屑保持稳定；同页锚点、高亮参数和数据刷新不重播进场。不新增
退出等待或滚动进场。
首次打开时预渲染内容已经可见，浏览器接管后不再进场，避免可见内容闪烁；减少动态效果时不启动动画，
运行中切换该偏好会立即取消动画。

文档目录分组展开和收起时，以 `--motion-duration-standard` 过渡分组高度；收起的分组仍不渲染，
打开时挂载、收起过渡结束后卸载。本页目录和正文内锚点跳转平滑滚动到章节，由阅读器统一负责锚点
滚动和聚焦；路由切换、返回恢复和带锚点链接的首次打开仍直接定位。减少动态效果时两者都立即完成。

阅读器样式只使用语义 token，层级靠字号、字重和留白而不是卡片。

- **侧栏**：文档树以小号大写式分组标题、悬停表面和选中表面区分层级；
- **本页目录**：用左侧细线加粗体文字标示当前章节，不再叠加填充背景；
- **标题区**：集合名与单版本标签是同一行的中性胶囊，版本选择器同为胶囊形；
- **出处信息**：文号、施行和原文作为标题下的一行“小标签 + 值”属性排列，不加边框；
- **正文**：规章段落开头的“第X条”只在渲染时加粗。条文结构仍以 reader 为准，不改变数据或目录；
- **表格**：保留完整网格线以闭合合并单元格，表头使用浅表面；
- **首页**：以自绘 chevron 和整行悬停表面代替浏览器默认 marker；
- **其他**：搜索命中以状态色下划线标记；上一篇/下一篇使用带边框的整块链接；返回顶部为圆形按钮。

所有新增过渡都在减少动态效果时关闭。

来源编辑与条件发布由[文档声明与生成发布](../architecture/2026-09-22-docs-source-declarations.md)补充；
生成的固定清单仍是构建输入，不改变这里的公开静态阅读边界。

当前保留单一 Campus Web 入口、稳定阅读身份以及阅读产物与检索产物分离的原则；不把检索块、
原始采集文件或对象存储内部位置直接作为用户页面，也不让浏览器选择内部发布状态或解释权限。
身份由[阅读器数据模型](../../../../docs/data/document-reader.md)维护，构建一致性改由
[静态交付合同](../../../../docs/contracts/document-reader-delivery.md)维护，旧 app-api release 投影不再承担它。

## 未采用方案

- **保留 Rspress 并继续适配主题**：成熟导航、静态页面与搜索能减少自建工作，但仍会保留双重路由、搜索和构建边界；
- **请求时从 App API 返回正文或资产地址**：公开阅读会获得不必要的认证、数据库和网络依赖；
- **按账号区分文档可见性**：当前没有产品需求，不能为假设场景保留受限资产链；
- **用检索分块拼接正文**：分块生命周期和阅读结构不同，无法提供稳定原文；
- **让文档组件进入普通应用入口**：会增加问答、地图和食堂页面的下载体积。
- **纯 CSS 进场**：能直接消费 token，但本次选择已有 Motion 的轻量入口，将动画生命周期绑定到
  已提交的页面，并支持运行中取消；不使用公共 Motion 默认曲线，因为文档动效要求复用标准 token。
- **等待旧正文退出后再显示新正文**：能提供完整退出效果，但会推迟导航与焦点交接；本次只给新内容进场。

## 后果

- 目录、正文和历史版本不再受 App API、认证或数据库可用性影响；
- 每个 Worker version 自带一致的目录、搜索索引、正文和关联资产；
- 删除 Rspress、`/_gated-docs/**`、`/api/docs/*` 和 `docs.*` 读取投影；
- 删除旧发布清单、当前版本指针和数据库投影合同，不提供运行时兼容；
- 仓库继续维护有限的目录、版本选择、固定链接和搜索交互。
- 动效不改变数据加载、路由、滚动恢复和无 JavaScript 阅读；只在内容身份变化时重新挂载动效边界。

受限访问能力已经放弃；以后若出现账号可见文档需求，需要新的访问与发布决策，不能沿旧路由
恢复兼容链。ADR-0051 未单独记录验收结果或测试覆盖缺口；当前验证要求见静态交付合同。
