# Agent Note: 文档版本出处信息

Status: implemented

## 背景

文档页只显示版本和集合，读者无法从页面判断文件的文号、施行时间或去哪里核对原文。对全部
184 份文档逐篇核对后，可靠来源只有三类：内部通知规章和信息公开网页面上的本文文号、正文写明的
具体施行日期、官网规章的公开原文页。发文单位、发布日期、培养方案元数据和内部通知的单篇链接
没有可核对来源；学生手册后来找到了学校公开的整本原文。用户确认能补就补、不能补的不补，并且这一轮
只改文档页，不改对话来源卡片。

## 决策

- 在 `campus_docs_source.v4` 版本上增加可选 `details`（`documentNumber`、`effectiveDate`、`source`），
  按版本登记，因为同一文档的不同版本有各自的文号和施行日期。字段为可选，所有解析方同批接受，
  不升级 schema 版本。
- 只登记能从 reader 正文或公开原文页逐字核对的值。文号只取正文开头或原文页标题下的本文文号，
  不取正文中引用、废止的其他文件文号；施行日期只取写明年月日的条款；原文链接只给公开 `https` 页面，
  链接文字用站点名，并与对应版本的正文比对确认后登记到该版本。
- `details` 经构建 catalog 和站点索引进入两条页面读取路径。阅读页标题下依次是集合与版本选择、
  历史版本提示和出处信息：版本选择作为紧凑控件放在集合标签之后；历史版本用整行提示写明正在阅读的
  版本、当前版本和返回链接；出处信息以“文号 / 施行 / 原文”标签和值对齐显示，两项及以上时
  放入浅色信息块，只有一项时显示为普通一行。没有 `details` 的版本不显示出处信息，原文在新标签页打开。
- 正文开头已有文号时，信息行显示后阅读页不再渲染正文前三个元素中与之完全相同的文号行；同段还有其他文字时
  只去掉首行。reader 正文保持来源原样，检索和其他消费者不受影响。
- 教务处网站“规章制度”栏目及其通知附件 PDF 是第二个原文来源。与 reader 正文比对一致的 9 个版本登记
  “教务处网站”链接；PDF 版头印有文号的，同时补登文号。
- 学生手册 2018 年版的原文是迎新网站“报到须知 / 学生手册”栏目公开的整本 PDF（261 页）。每篇在标题下
  印有本文文号，逐篇按页面图像核对后，43 个版本登记文号和原文链接，链接带 `#page=<页码>` 指向该篇起始页；
  各篇正文与该页码范围的 OCR 文字一致。PDF 的文字层是排版软件的私有编码，不能直接提取文字。
  手册中的国家规定只有发布日期，学校文件也多数不写施行日期，因此不补施行日期。
- 只有“（2021）150号”这类缺少发文机关代字的文号，在教务处、研究生院和信息公开网均找不到原文时不登记；
  正文首行仍显示原样文号。
- 同一轮核对发现 12 个版本把少数“第X条”存成标题、其余存成段落，正文和右侧目录因此不一致。
  按合同统一规则重新生成这些 reader：条文范围内只保留章节标题，其他标题改成段落，`rootUnitId` 不变，
  检索命中和高亮不受影响。指向被改标题锚点的旧链接只是不再跳转到该位置。临时调课第四条同批按
  教务处原文改正一处用字（“报告教务处”改为“报教务处”）。新 reader 写入新对象键后更新版本声明，
  RAG 需在发布后按运行手册重建。

## 未采用方案

- **同时补到对话来源卡片**：卡片数据来自检索链路，需要同时改 index publisher、检索 payload、
  campus-search、agent-control 和 app-api 并重建索引；卡片本身链接到文档页，用户决定这一轮不做。
- **把不完整文号补成“民大校发”**：同批相邻文号都是民大校发，但没有原文可核对，属于推断。
- **只在阅读页把条文标题降级显示**：会让页面和 reader、检索分块的结构不一致，问题仍留在来源里。
- **用官网页面的发布时间作为发布日期**：met 站点绝大多数页面是同一天集中上传，信息公开网的“更新时间”
  同样是上传时间，都不是文件发布日期。
- **用原文所在网站或栏目推断发文单位**：信息化建设管理处网站也收录餐厅等非本部门文件，栏目不能说明发文主体。
- **使用信息工程学院“学生手册（CookBook）”页面**：只收录约 15 篇，正文是标注 DRAFT 的 OCR 结果且有错字，
  整本 PDF 需要验证码下载，不作为原文来源。
- **从版本 slug 推断文件年份**：学生手册版本是手册年份，部分规章版本是收录年份，与文件本身年份不一致。

## 后果

- 新增出处信息只需编辑版本 YAML；离线检查拒绝空 `details`、未知字段、非法日期和非 `https` 链接。
- 发文单位、发布日期或新的链接来源出现后，按同一核对规则补到 `details`；字段含义变化时再评估 schema 版本。
- 对话来源卡片仍只显示标题、摘要和版本；需要在卡片上显示出处时，另行扩展检索链路。
