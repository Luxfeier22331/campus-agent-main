# Agent Note: 源码依赖与分组测试缓存

Status: implemented

## 背景

PR 的 Node 校验出现全部缓存失效。根包持有业务 workspace 依赖，使合同 fixture 内容进入全局
依赖 hash；整仓索引树又使脚本测试随不相关内容变化失效。应用测试依赖上游测试任务，传播了
不消费的测试修改。Ops 大量时间花在重复模块加载和环境初始化，而非测试断言。

## 决策

- 业务脚本依赖移入独立的私有 tooling workspace，保留脚本路径。根测试入口串行调度七个组，
  按实际读取范围分别缓存；读取 Git 清单的组只附加跟踪路径摘要，内容由任务输入负责。
- Node 任务使用不执行命令的 `source` 依赖节点传播生产源码变化。类型检查和测试不再要求执行
  上游同名任务。跨包引用 fixture 由 Go、前端等实际消费者显式声明，不依赖偶然的全局失效。
- 前端将 Node/DOM 与模块隔离分成缓存叶任务，聚合 test 保留本地使用。共享环境的测试在结束时
  恢复全局变量、mock 和定时器；需要模块 mock 的套件保留隔离。用随机顺序检验状态清理。
  共享 UI 套件曾在默认多 worker 下触发多项超时，改为文件串行，保持隔离和原超时阈值。
- 实际 Node 版本、OS 和架构在选定工具链内进入任务缓存。数据库集成与读取可变外部数据的构建
  保持原有不可缓存语义，成功结果之外不缓存。
- PR 前置检查失败后停止昂贵任务；汇总仍拒绝失败和意外跳过。hook 安装器确认实际文件存在且
  可执行，格式检查继续由原有 pre-commit 承担。

本篇部分取代[提交前验证与根测试缓存](../process/2026-09-16-pre-commit-validation.md)的根任务、
索引树与不拆分测试集合决定；提交与推送边界不变。
也部分取代[Ops 测试初始化与缓存](./2026-09-19-ops-test-initialization-and-cache.md)的全文件隔离与
普通测试依赖决定；真实数据库集成边界和页面可访问性断言仍保留。

## 未采用方案

- 全局依赖和完整索引树简单且保守，但已证实导致不相关任务失效。改为真实消费边界后，用实际
  Turbo 图验证相关失效和无关命中，不直接删掉仍被读取的输入。
- 提高并发可能缩短墙钟，但共享 runner 已出现资源饥饿；保留现有并发约束，减少重复初始化。
- 所有测试关闭隔离能减少加载，却会泄漏模块 mock；隔离由测试实际行为决定。
- 前置失败后继续运行能一次收集更多错误，但用户明确选择停止昂贵检查以节省资源。

## 后果

修改任务配置后的第一次运行需要重新生成缓存。真实仓库夹具验证 fixture、源码、测试、运行版本
变化的任务选择和缓存边界，以及热缓存复用和失败不缓存。全仓 CI 合同组仍保留广泛输入，因为
它实际读取各包定义；不通过缩窄声明掩盖消费者。没有新增缓存服务、浏览器门禁或性能报告 job。
