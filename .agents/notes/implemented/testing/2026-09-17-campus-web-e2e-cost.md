# Agent Note: Campus Web 浏览器回归成本

Status: implemented

## 背景

Campus Web 的业务状态与浏览器交互混在同一回归层，app 与 UI baseline 重复选择布局用例，
全量入口重复构建；部分视口不适用的用例提前返回，仍显示通过。用户要求降低整个 Campus Web
的 E2E 成本，并明确删除独立 smoke 入口，浏览器回归仅手动按变更选择。

## 决策

- Campus Web 功能维护者在既有 Vitest 文件中维护业务状态、失败映射和请求规则；新增 Dining
  详情组件测试承接菜单状态与评价重试。浏览器继续验证布局、触控、焦点、历史导航、剪贴板、
  照片输入、流式交互，以及编译后的 Worker 与静态资源边界。真实 dev-chat 链路保持独立。
- 删除 smoke 命令、标签与 Turbo 任务，不在 agent 指令或例行验证中要求执行 E2E。
  手动运行方式由[本地验证](../../../../docs/runbooks/local-verification.md)维护。
- 全量命令先构建一次，再顺序运行 app、Worker、UI baseline，三个阶段复用本次构建；
  单套件仍可自动构建。Turbo 全量任务保留构建输入且不缓存结果。app 排除 UI baseline。
- 三个浏览器套件默认两个 worker，保留文件内执行顺序；资源受限时使用单 worker。
  若出现实际资源争用或耗时退化，再调整默认并发，不增加自动重试掩盖失败。
- UI baseline 从 80 个组合缩为 36 个适用组合：布局覆盖五个宽度，导航覆盖断点两侧，
  通用交互覆盖移动和桌面代表宽度，专属行为只选择对应视口。项目 grep 决定选择，
  删除提前返回的空通过。反馈可访问性归入现有 accessibility 套件，320px reflow 合入布局用例。

## 未采用方案

- **保留手动 smoke 子集**：入口短且方便，但仍需要维护第二份选择规则。现有文件与 grep
  已能表达本次变更边界，用户明确选择删除独立入口。
- **只增加并发**：改动小，但保留重复构建和不必要的浏览器状态测试，无法消除这些成本。
- **删除低价值浏览器用例而不迁移断言**：立即减少耗时，但会丢失错误处理和请求规则覆盖。
  本次复用既有组件测试并补充缺失场景，浏览器独有行为继续保留。

## 后果

业务覆盖由功能所属组件和 Worker 单元测试承担，浏览器用例数量不再代表全部覆盖量。
窄视口布局仍覆盖 320px，跨端交互减少重复宽度，新增行为需要按实际浏览器边界选择所属层。
本次测量前旧全量入口在两个文档选择器处失败，未执行最后的独立 UI 阶段，因此不把旧失败
耗时与新成功耗时直接换算为完整回归加速比例。两处选择器随当前目录折叠和移动面包屑调整，
保留原历史导航与元数据断言。

本次本地验证中，app 63 个、Worker 浏览器 37 个用例通过；UI baseline 修复迁移中的引用和
选择器后单独复用构建运行，36 个全部通过，耗时 84.24 秒。旧独立 UI baseline 80 个用例
耗时 130.82 秒。Vitest 从 749 个增至 776 个，两阶段执行时间合计从 66.43 秒增至 72.32 秒，
下沉覆盖增加约 5.9 秒。各次运行存在启动与资源波动，这些结果用于确认成本方向，不作为耗时门禁。
