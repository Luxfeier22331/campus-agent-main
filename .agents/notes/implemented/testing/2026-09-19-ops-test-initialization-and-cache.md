# Agent Note: Ops 测试初始化与缓存

Status: implemented

## 背景

Ops 普通测试原先在每个隔离文件中加载 jsdom、React 测试库和完整内存后端，初始化成本占比较高。
跨应用数据库测试所需的开发依赖还让 Campus 页面改动沿普通测试任务依赖传播到 App API 和 Ops，
使无关普通测试缓存失效。

## 决策

本篇的全文件隔离和普通测试任务依赖已由
[源码依赖与分组测试缓存](./2026-09-19-source-and-test-cache-boundaries.md)部分取代。
数据库集成边界、内存后端初始化与页面可访问性断言继续有效；以下保留原选择理由。

普通测试拆成 Node 与 DOM 两个项目，保留串行执行和文件隔离；公共 setup 仅恢复全局 stub，
DOM setup 管理组件清理及浏览器 shim。内存后端由实际消费者 `ops-app.test.tsx` 显式创建，
每项测试获得独立 fixture。较慢的页面断言限制到已有语义区域，刷新按钮仍检查标签和按钮角色。

仅将 App API、Ops 普通测试的任务依赖改为实际共享包测试，保留跨应用 manifest 依赖和类型检查
任务图。跨应用源码、adapter 与数据库测试支持文件进入对应集成任务输入；集成任务保持不缓存。
Ops 普通测试读取根 `.dockerignore`，因此将其纳入输入。真实 Turbo 临时 workspace 回归覆盖
缓存命中、相关改动失效、无关改动保留缓存，以及跨应用 adapter 改动选择数据库任务。

## 未采用方案

- 关闭隔离或增加并发可以进一步降低耗时，但会改变测试状态边界或增加小规格 runner 的资源竞争；
  本次消除不需要的初始化，并保留已有串行约束。
- 删除跨应用开发依赖能简化任务图，但数据库集成测试仍消费这些 adapter，因此只调整普通测试边。
- 全面替换角色查询可以减少 DOM 查询成本，但会削弱可访问性断言；仅调整已测量的慢查询。

## 后果

原有测试文件和用例清单保持一致；运行结果不作为跨机器性能门禁。
新增共享包依赖时，需要同时检查这两个显式普通测试依赖列表；数据库输入仍由各应用任务配置维护。
没有新增测试入口、浏览器验证、性能门禁或远程缓存服务。

数据库集成套件共享一个临时数据库，文件隔离不隔离数据库记录。旧 Dining 数据迁移测试在恢复
旧约束前清理评价表，再构造并验证旧数据保留，避免其他测试留下的投稿评价干扰迁移。班车集成
测试依据现行接口合同验证通知关联和发布状态不改变生效班次；生效时间段没有已发布通知时返回
空通知列表，不退回其他时间段。两项修正只调整测试，不修改产品迁移或排班规则。
