# Agent Note: 决策笔记树治理

Status: implemented

## 背景

仓库决策原以 ADR 保存在已删除的 `docs/decisions/`，只有 `accepted` 状态。
维护者与仓库 Agent 需要区分仍能指导工作的决策、低指导价值的历史及真实故障的复盘。
本治理参考 DSH 原仓库提交 `0d1f500` 的笔记保留、取代与复盘分工，采用归档、模板、
独立 Skill 和软性引用报告；board 和新增 CI 工作流不在当前范围。

## 决策

决策迁入 `.agents/notes/{proposed,implemented,rejected,archived}/{class}/`。
42 篇存量 ADR 保留编号，移除 frontmatter，采用 `Agent Note:` 标题和 `Status:` 行；
新笔记按话题命名，不再分配 ADR 编号。六类分类及操作规则由
[笔记 README](../../README.md) 维护；根 [AGENTS.md](../../../../AGENTS.md) 路由到
[写作 Skill](../../../skills/write-notes-like-deepseek/SKILL.md)。

笔记保留按未来指导价值判断；实现事实更新、决定反转、部分取代及完全合并的规则由
[笔记 README](../../README.md#何时写与清理)统一维护。已实施但后来纠正的选择仍可能具有
指导价值，不能仅因被取代就归档。合并删除之前必须让当前 owner 保存独有的决策内容，
避免理由仅能从 Git 历史恢复；迁移前已删除 ADR 同样适用，历史编号只作标识，独有内容由现行 owner 承接。
ADR-0007 的检索取舍由 [ADR-0084](../architecture/2026-07-29-adr-0084-agent-knowledge-tools.md)承接；
ADR-0051 的阅读器取舍由 [ADR-0085](../feature/2026-08-01-adr-0085-native-reader.md)承接；
ADR-0055／0080 的控制台退役由 [ADR-0072](../architecture/2026-07-12-adr-0072-self-hosted-ops-web.md)及其后续 owner 承接；
ADR-0077 的采集编排取舍由 [ADR-0089](../simplification/2026-08-19-adr-0089-internal-portal-credential-resolution.md)承接。
这些内容保留历史选择与现行边界的区别，不把旧实现细节重新声明为当前要求。

真实故障的经过、机制与漏检原因属于[事故复盘](../../../../docs/postmortem/README.md)，
长期选择与代价属于 Agent Notes。二者互链，避免把事故叙事塞入当前规则，或为同一设计再建
一份决策正文；该分工也允许具体教训保留，而不要求每个 bug 都新增文档。

归档命令只处理 implemented 笔记，保留正文、原状态、分类和文件名，追加唯一归档行。
替代目标可选且须存在；目标路径在归档行中转换为相对 Markdown 链接，其他入站链接由
调用者同批调整。归档正文不再参加当前章节、Markdownlint、EditorConfig、出站链接和语言检查；
默认搜索排除归档，历史查阅显式指定目录。
专用检查以 Git HEAD 中已提交的归档逐字比较，拒绝修改或删除；首次归档只检查结构，
提交后建立冻结基准。已进入 HEAD 的改写不在该比较的检测范围内，不提供独立历史封存保证。

三种写作模板和归档结果示例保存在 `templates/`，不当作正式笔记检查。
`docs:check` 复用现有入口，包含树、格式、归档、预算、链接和语言检查；
各生命周期的章节要求由笔记 README 与检查器维护；提案包含可观察的验收目标和风险，
拒绝保留提案与真实备选，实施后将计划改写成当前事实。42 篇迁移笔记已按背景、决策、未采用方案、
后果整理，格式检查不再按文件日期豁免；原记录缺少的权衡明确说明，不补造历史选择。
贡献指南和 PR 模板衔接非平凡改动的笔记要求及机械改动豁免，供人类贡献者与 Agent 共用。
入口预算仍由 `scripts/docs/doc-budgets.json` 拥有；笔记入口新增生命周期转换与冻结能力说明，
行数预算由 95 调整为 105，保留必要规则及少量余量。

`docs:notes:anchors` 只作观察，扫描仓内 Markdown 的链接和反引号路径，并按来源文件去重。
它区分 owner 文档引用与笔记／入口引用，避免仅扫描笔记而把已有 owner 引用误报为孤立。
没有 owner 引用和高入站数都不是缺陷判定，不进默认检查，不推断自然语言中的取代关系。

## 未采用方案

- **继续扩展 ADR frontmatter**：改动小，但与用户选择的路径生命周期和笔记头块重复。
- **保留所有旧篇或一律删除**：前者累积重复内容，后者丢失仍有价值的理由；按未来指导价值取舍。
- **以错误或取代关系直接决定归档**：容易把仍能防止重蹈的理由移出活动记录；取代范围与
  未来价值须分别判断，完全合并后才可在保全独有内容的前提下删除旧篇。
- **另建 SHA-256 封印清单**：能提供独立冻结基准，但本仓库已有 Git 历史；当前要求可由
  已提交归档的逐字比较满足，避免增加另一份需要维护的状态。
- **长期保留旧日期的格式豁免**：迁移初期可以降低改动量，但整理完成后会让不完整的新内容
  继续借旧文件名绕过同一结构要求，因此移除豁免。
- **强制每篇笔记都有 owner 引用**：易于自动检查，却会制造无实际读者的链接；采用软报告。

## 后果

文档操作规则由[文档规范](../../../../docs/AGENTS.md)维护，分工理由见 [ADR-0038](./2026-07-16-adr-0038-documentation.md)，
本笔记仅拥有决策记录治理。说明、Skill、脚本和测试须保持一致；验收应覆盖实际归档行为，
不能用空目录检查代替能力验证。故障经过、漏检原因和对应修复见
[归档完成误报复盘](../../../../docs/postmortem/0001-note-archive-false-completion.md)，本笔记不重复事故叙事。

board 和新增 CI 工作流不在当前范围内。若以后需要跨提交历史追溯首次封存、归档迁移，
或该冻结基准不再满足维护者需求，再重新评估当前实现；不因对齐外部项目而直接增加机制。
