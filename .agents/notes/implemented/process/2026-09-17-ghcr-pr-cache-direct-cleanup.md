# Agent Note: PR 缓存直查与暂停全量清理

Status: implemented

## 背景

关闭 PR 的 GHCR 清理在组织级包枚举接口返回 HTTP 400；同一 workflow token 能直接读取已知包。
原有测试模拟了枚举成功，没有覆盖这个能力边界。读取异常也发生在报告写入前，导致后续上传追加
误导性的文件缺失错误。本次只修复当前故障，不提前实现 #512 的正式版本发布与回滚。

## 决策

PR-close 自动协调、暂停 full apply 和手动历史 PR 清理的部分已由新决定取代；已知包直查与错误分类仍有效。
见[候选复用与镜像清理边界](./2026-10-03-source-publication-retention.md)。

正式版本的保留根现由[正式版本与环境选择](./2026-10-02-formal-release-versioning.md)维护；
原有 SHA 数量/年龄窗口不再作为 full report 策略，暂停全量删除继续有效。

部分取代[原镜像保留与退役决策](./2026-09-04-ghcr-retention.md)：PR 关闭协调仍有效；组织枚举、
定时 report、旧全量手动入口及其最近 5 个 release / 七天规则停止执行。原策略函数暂存供后续改造，
不作为当前 CLI 或 workflow 能力。

包名曾由当前镜像目标和 PR 编号推导，只在 package metadata GET 返回 404 时跳过；其他错误、
versions 404、传输失败及无效响应均失败。可见权限是缺失判断的前提，不把 404 泛化为任何资源都不存在。
该包名推导和直查入口已随 PR 缓存清理一起移除；同样按 404 与传输/解析错误区分的失败分类继续用于
登记包的直查。

复用现有 PR 状态、构建取消和等待机制；手动入口同样检查同仓、非 Dependabot、closed 状态。
自动和手动路径使用同一 per-PR 并发组。报告模式不取消或删除；apply 在删除前保存计划，在失败后
写明操作及原因，删除后直查复核。没有新增长期 inventory 或恢复状态。该 PR 状态、取消、并发组和
清理入口同样已随 PR 缓存清理移除。

正式镜像自动清理等待 #512 提供正式版本、当前部署及发布恢复目标的保留依据，再由 #511 接入。
当前主线镜像和缓存没有被本次清理入口操作的路径。

## 未采用方案

- **扩大 token 权限恢复枚举**：可能恢复未知包发现，但当前消费者只需要已知 PR 的包，不增加凭据依赖。
- **按 PR 历史窗口探测**：能补查部分遗留包，却不能解决未知名称发现，并增加 API 成本；失败清理直接指定 PR 补做。
- **保留旧定时或全量手动策略**：便于延续旧操作，但与用户已确认的正式版本回滚、普通构建无默认七天承诺冲突。
- **仅忽略报告上传失败**：消除第二个错误却丢失原始失败信息；在清理 owner 内统一记录实际失败。

## 后果

PR 关闭清理无需 GitOps checkout、registry login 或组织包枚举；删除范围限于当前目标名称。
已移除目标的历史缓存不在本次自动发现范围，需要按已确认对象处理。正式镜像版本将继续积累，直到
正式版本保留依据与 #511 Work B 完成；不能把本次 PR 清理修复当作整个 #511 完成。

直查、分页、错误分类、PR 协调、部分删除失败和重复执行由脚本与 workflow 配置测试验证。
包删除与 main 构建的真实发布结果由 release owner 按发布记录确认；源码测试不替代环境交接结论。
