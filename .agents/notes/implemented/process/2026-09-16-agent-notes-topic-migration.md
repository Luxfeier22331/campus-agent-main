# Agent Note: ADR 编号迁移为话题命名

Status: implemented

## 背景

ADR 迁入 Agent Notes 时采用过渡政策：迁移笔记保留 `adr-NNNN-` 文件名和编号标题，新笔记
使用话题命名。过渡期结束后，编号文件名与话题文件名并存，同一决策有两种引用方式；标题中的
编号也让“按话题找决策”多一层无信息的标识。`ADR-0003` 与 `ADR-0024` 仅剩链接修复，独有
决策内容仍未由现行 owner 承接，违背“合并删除前必须保全独有内容”的规则。

## 决策

全部活动笔记使用话题文件名和话题标题，ADR 编号只保留在正文的历史叙述中：

- 41 篇编号笔记改名为话题文件名，去掉标题编号；`ADR-0021`、`ADR-0037` 从 feature 重新
  分类到 architecture；
- `ADR-0003 评测数据集` 完全并入 [评测数据与平台边界](../testing/2026-08-21-eval-boundaries.md)：
  调用方拥有评测输入、稳定 case ID 不静默改义、case 表达输入/预期结果/预期工具/证据与禁止项、
  运行时 fixture 留在所属模块、公开/私有边界由任务决定、独立 synthetic RAG asset 退役；
- `ADR-0024 认证通知来源` 完全并入
  [内部门户通知来源合同](../architecture/2026-08-14-internal-portal-notice-source.md)：
  `internal_portal` 独立通道、`notice`/`file_release` 不互转、不按登录主体分区、采集不自动
  发布、采集/认证/凭据三方职责边界；
- 现行引用的显示文字改用话题名；已删除编号（0007/0051/0055/0080/0077 等）的历史叙述保留；
- 笔记 README 的命名政策改为“文件名和标题不含 ADR 编号”，检查器拒绝活动笔记的编号
  文件名和编号标题，归档原文与模板豁免，测试反例继续作为负例 fixture。

## 未采用方案

- **长期保留双轨命名**：避免本次改动，但同一决策存在两种引用方式，检查器也无法阻止
  新笔记重新使用编号。
- **只改文件名不改标题**：文件名与标题一致是话题定位的基础；标题编号会让检索和引用
  继续依赖编号。
- **建立编号到话题的跳转页**：多一份需要维护的映射，Git 历史和话题搜索已能定位原文。

## 后果

- 活动笔记共 47 篇：architecture 26、feature 5、process 11、simplification 3、testing 2；
- 入库链接全部指向话题文件名；`ADR-0003`、`ADR-0024` 的独有内容由合并目标承接，
  Git 历史不再承担唯一保存职责；
- `scripts/docs/check-notes-tree.ts` 校验活动生命周期文件名，`check-notes-format.ts` 校验
  活动笔记首行标题，正则允许正文历史叙述、归档原文和模板豁免；
- 后续新增笔记不得恢复 ADR 编号；如需引用迁移前决策，直接链接现行话题笔记。
