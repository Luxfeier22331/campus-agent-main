# Agent Note: 提交前验证与根测试缓存

Status: implemented

## 背景

本地 pre-push 在 Git 建立远端连接之后运行根脚本和受影响模块检查。长时间冷缓存检查可能让
远端连接在验证完成前断开，导致检查结果与推送结果脱节；保活只能缓解连接问题，不能承诺所有网络
和任意时长的推送都可靠。

用户要求将重验证迁到提交前，并同时缓存原本每次执行的根目录测试。包级 Turbo 缓存已通过相同
输入命中、源码变化失效和恢复输入后命中的验证；缺口是根目录脚本测试未通过 Turbo 执行。

本 PR 改动根级输入使 affected 覆盖完整依赖边界；共享 runner 上 Node 任务并发会造成测试超时和
失败漂移，而本地执行可以通过；同一执行器内 native 任务已有串行约束。

## 决策

本篇的根命令命名进一步由
[工作区脚本与验证入口治理](./2026-09-22-workspace-command-governance.md)部分取代：
hook 调用 `test:tooling`，根 `test` 成为全仓单测入口。提交范围、资源额度与 pre-push 退役决定不变。

本文的根任务、完整索引树和不拆分测试集合条目已由
[源码依赖与分组测试缓存](../testing/2026-09-19-source-and-test-cache-boundaries.md)部分取代。
pre-commit 所有权、pre-push 退役、并发额度和失败阻断继续有效；以下保留原选择理由。
PR 重复执行 Node typecheck 的范围由
[PR 类型检查去重](../testing/2026-09-21-pr-typecheck-deduplication.md)部分取代。

重验证由 pre-commit 拥有，沿用现有静态检查、Secret 扫描和 Node/Go 任务集合。静态检查成功后
按暂存文件选择统一 registry 中的 repository checks，再执行根脚本测试和受影响模块任务；失败阻止提交。
CI 使用同一 registry、命令和 Nix shell，只把选择范围换成 PR 分支差异。contracts 固定在 `ci-go` 中运行，
Actions 配置固定在 `ci-light` 中运行，避免依赖开发机或 runner 的全局 PATH。pre-push 的重验证与适配入口
删除，安装器只卸载当前 worktree 的受管理 shim。PR 仍检查完整分支差异，不把一次本地提交检查作为合并证明。

PR 的 affected Node 检查中，`test:generators` 虽由 Node 启动，仍需用 `gofmt` 格式化生成的 Go 合同，
因此按原 affected 范围单独在 `ci-go` 执行一次；其余 Node 测试继续使用 `ci-core`。不向所有 Node
检查加入 Go 工具链，也不依赖生成器缓存命中掩盖工具缺失；生成器失败仍阻断后续检查。

提交前复用 prek 的未暂存修改隔离和 Turbo 的工作区 affected 选择，保留依赖传播与输入声明。
首次提交运行全量模块任务；空暂存差异只运行可缓存的根测试。不创建临时提交、额外快照、验证
凭证或第二套包依赖映射。`pnpm lint` 排除 validation group，保持全仓静态检查职责；repository checks
不在 lint hook 中复制命令。

私有仓库在 Free 计划下没有分支保护和 rulesets（API 返回 403），曾有 agent 直接提交并推送 main，
文档也未约束。pre-commit 第一项用 prek 内置的 `no-commit-to-branch` 拒绝 main 上的提交，AGENTS.md
同时写明所有改动经分支和 PR。分离 HEAD 不受影响，PR CI 照常运行；`pnpm lint` 跳过该 hook，
以便在 main 上做全仓静态检查。它可被 `--no-verify` 绕过，只防误操作；以后启用服务端分支保护时
仍可保留为本地提前失败。

执行器内 Node 任务的 Turbo 并发以半核数（最少 2）为 CPU 上限，再受进程内存额度约束：
每 2 GiB 允许一个任务，最少一个；运行时未报告内存限制时保留 CPU 上限。6 核、2 GiB 的 runner
曾在三个任务同时执行时由 cgroup OOM 杀掉 tsc，故不能只按核数调度；该额度用于降低并发，
不承诺单个任务永不耗尽内存。native 任务维持既有串行；约束在
统一命令构造处生效，同时覆盖提交 hook、PR affected 与 verify。全量任务分波执行会拉长 CI 墙钟，
以消除共享 runner 上 vitest 默认超时的进程饥饿为准。

根目录 `pnpm test` 通过薄入口设置索引树和实际运行工具版本，再调用根任务 `//#test:scripts`。
原有测试集合不拆分、不缩减；根任务的默认文件输入覆盖脚本实际读取的应用源码、工作流、配置、
文档和工具链。索引树是既有 Git 对象标识，用于区分跟踪文件集合，并非新的持久化验证记录。
工具版本与 OS/架构只影响根任务缓存，不扩大所有模块的全局输入。提交 SHA 和机器路径不作为键，
相同内容可在提交前后复用。测试临时仓库不继承 hook 的 Git 路径环境变量。

本地和现有 PR 步骤共用 Turbo 缓存机制，不增加缓存服务或 workflow；根任务只缓存成功结果，
原有数据库、浏览器等不可缓存任务的边界不变。任务定义、入口与使用说明由
[测试与验证](../../../../docs/reference/verification.md)及可执行配置维护。

## 未采用方案

- **只增加 SSH 保活**：对照实验支持它能缓解空闲断线，但仍让网络连接等待本地重验证；提交前运行
  可以直接消除该等待路径。SSH 配置不作为本次迁移的必需改动。
- **保留 pre-push 再跑一次**：缓存热时开销较小，但冷缓存仍可能长时间等待；PR 已拥有分支验证。
- **用 pre-push 拦截推送 main**：pre-push 已按上文退役；实测 prek 的 pre-push 在强制回退 main
  时不触发，拦不住 `--force-with-lease` 一类推送。提交前拦截覆盖了产生直推的源头。
- **用 workflow 检测非 PR 的 main 提交**：只能在推送后报警，main 已被修改且发布已触发。
- **只修改 hook stage**：改动少，但原适配器依赖远端提交范围，不能表达待提交工作区。
- **只缓存 scripts 目录或按提交 SHA 缓存**：前者遗漏根测试消费的应用与配置变化，后者使相同内容
  在提交前后失去复用机会，因此采用文件输入、索引树和实际工具版本。
- **新增验证凭证或缓存服务**：Turbo 已具备成功结果缓存和输入失效能力，没有新的消费者需要第二份状态。

## 后果

冷缓存时提交仍需等待真实测试，迁移不承诺恒定提交时延。相同输入重复执行可以命中缓存；源码、
索引或工具环境变化会重新执行。完整仓库默认输入偏保守，文档变化也可能使根测试失效，以保留跨目录
测试覆盖；若未来要缩小范围，应先调整真实测试消费者，而非排除仍被读取的输入。

验收覆盖 main 上提交被拒、实际 Git 提交、部分暂存恢复、失败阻断、依赖传播、根缓存失效与提交前后复用，以及旧 hook
卸载和本地裸仓库推送不执行验证。外部 CI 缓存命中与部署状态不由本地验证证明。
