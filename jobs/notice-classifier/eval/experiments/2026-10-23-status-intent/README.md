# status 拆分为读者动作（intent）：初稿映射、试标与评测

数据分类：`internal-only-not-for-public-repo`，见上两级 README。

`intent-draft.tsv` 由 `../../labels.tsv` 的 category、status 与 `../../titles.tsv` 的标题机械生成，是判定文本
加入 intent 之前的初稿，不是标准答案；`basis` 记录每条按哪条映射得到。映射顺序：completed → result、
static → reference、procurement upcoming → action；其余 upcoming 先看标题办事动词（动作优先，归 action），
teaching_schedule 与 service_info 归 notice，再看事件词归 event，最后按类别兜底（application / affairs /
recruitment / international → action，讲座、考试、培训、活动、竞赛 → event，governance → notice）。
判据与未决点见决策笔记第 8 节。

`runs.tsv` 是判定文本 0.3.x 的两模型试标记录：每行一次模型调用的解析标签（batch、judge、backend、
notice_id、category、intent），调用失败时 `error` 记供应商错误、标签为空。批次 1–17 为首轮，`r` 开头为按
新版本重判旧落盘条目，同一批次号带后缀的是网络错误后的重跑；这些批次的 backend `jev` 为 TypeSafe Jev。
Jev 停服后 backend `decision` 为 Nace drex-max：`x` 开头为 0.3.21 起按每批 50 条重判模型车道全部条目，
`y` 开头为 0.3.27 的确认轮，带 `c` 后缀的是上一批分歧条目改文本或规则后的重跑。0.3.33 起的记录由
`classify:eval` 的输出整理：`f33`、`f44` 为两种后端的全量评测；`s<N>` 为第 N 批新抽样（50 条，`s13` 为余下 45 条，
`s0` 为 0.3.39 的试跑），带 `c` 后缀的是改动后同批重跑；`p<N>` 是第 N 批判错条目的复查（按旧版本判定文本回放，或 LLM 单独
重跑），judge 列为实际使用的版本。评测不重跑判对的条目，LLM 只对判错条目重跑 5 次，重跑各记一行。

## 试标与评测过程

结论与取舍在决策笔记
`.agents/notes/proposed/feature/2026-10-21-notice-classification-redesign.md` 第 8 节；本节按时间记录每个版本的
改动、依据与结果，收敛流程见 `docs/runbooks/ingestion/ingestion.md` 的「分类评测」。

直到判对；不人工落盘。

- 首轮 17 批跑完 736 条，判定文本 0.3.0 → 0.3.16，主要口径：「组织开展」活动与线下培训无办事词归 event；
  网课学习、网络培训与网课期末考试在时间窗口内自行完成归 action；「做好 / 开展…工作」按谁来做判断，学生或
  教师个人完成的归 action，各单位完成、标题无办事词的考核、总结、换届、抽检、普查归 notice；单届赛事实施方案、
  答辩会、典礼工作提示归 event；科室人员调整、管理比例调整、常备服务信息归 reference。车道新增名额分配、
  公费医疗、设立支持项目三条规则，收走 10 条。
- 之后按版本从旧到新、每批 50 条重判旧版本落盘的条目（重判批），到 0.3.21 已完成 r1 至 r9：带入的分歧均

  action），随即落盘。
- 现状：标准答案模型车道 725 条全部是两模型一致的标签，规则车道 2650 条；`classify:eval --backend rules`
  2650 / 2650。625 条落盘于 0.3.9 至 0.3.19、尚未按 0.3.21 重判（r10 至 r15）。r10 起 Jev 网关持续返回

### 评测成本与决策模型判据裁剪（0.3.34 至 0.3.44）

引入决策模型期间 Jev 与 Drex 合计约 10 美元，LLM 约 4 美元。
两处原因：drex-max 没有提示缓存、按输入计费，每次发出完整的两个 choice 问题（3.2 万字，约 1.5 万 token），其中
易混裁决按点名类别复制 118 次占 1.95 万字，而 deepseek 的系统提示约 99% 命中缓存；0.3.28 至 0.3.33 每次改
判定文本后两种后端都跑全量评测，每轮决策模型只有 0 至 8 条差异，而这 17 条差异各重跑 6 次全部一致，重跑
只付费不提供信息。改动：

- `classify:eval` 增加 `--notice-ids`、`--categories`、`--intents`，按标准答案的期望标签只评一部分；决策模型
  默认不重跑差异，LLM 仍重跑 5 次。收敛顺序写进 runbook：能由标题信号判定的改车道规则，用 `rules` 免费验证；
  其余合并成一次判定文本升版，先跑差异条目与涉及的期望标签；一轮改动落定后两种后端各跑一次全量，检查共享
  判定文本的回归。
- 判定文本 0.3.34 给易混裁决加 `title_signal`：标题命中该正则才把这条裁决发给决策模型。四条对象太宽的裁决
  （governance 与 service_info、governance 与 affairs、affairs 与 application、affairs 与 service_info）不设信号，
  每次都发。模型车道 703 条的问题长度从 3.2 万字降到中位 1.61 万、最长 2.2 万字。LLM 系统提示不变。
  信号是对标题的宽匹配，漏发一条裁决的代价是该条可能判错，评测会以差异暴露，届时补信号词。
- 判定文本 0.3.35 把同样的机制用到类别定义与 intent 判据：第一句核心定义之后的特例条款按 `。`、`；` 拆开，
  条款各带 `title_signal`；governance 的单位工作清单与 notice 的「包括」清单按并列项拆分，只发命中的项；
  上述四条宽口径裁决内部的特例句也各带信号。互为对照的条款挂同一组信号词，一起发或一起省，避免只发半边：
  例如「课堂」同时带出 event 的国旗下课堂到场、lecture_forum 的思政课堂归 activity 与 notice 的行业专家
  进课堂。宽口径条款（「做好…工作」「开展…工作」）用宽词宁可多发。条款按原顺序拼接即原文，LLM 系统提示与
  0.3.34 逐字相同（离线比对），不需要重跑 deepseek 评测。模型车道 703 条的问题中位 7.7k 字、90 分位 9.5k、
  最长 1.4 万字，约为 0.3.33 的四分之一。
- 判定文本 0.3.36 压缩每条都发的固定部分（标题不命中任何信号时从 6.2k 降到 5.1k 字）：没有标题信号的四条
  宽口径裁决不再复制到点名的类别下，只在 category 问题的 instructions 里发一次；栏目说明按栏目名分条，只发
  本条通知所在栏目的一条，栏目不在表中时发全部；news 泄漏防护的竞赛、读书、文化活动三条按标题信号发送。
  省掉的条款以句号收尾时，前一条保留条款末尾的分号改成句号。模型车道 703 条中位 6.5k 字、90 分位 8.4k、最长
  1.3 万字；LLM 系统提示仍与 0.3.34 逐字相同。
- 判定文本 0.3.37 按离线审计收紧与补全信号词。审计对模型车道 703 条逐条统计每个带信号条款的发送次数、与期望
  标签无关的发送，以及标题与条款共享三字以上片段却没发的疑似漏发。收紧的是单字子串误命中：「展」命中开展、
  「课」命中任何课程、「团」命中团结与支教团、「考」命中考研、「记」命中登记，改成具体词；网课与期末考试的
  对照裁决只在网课、在线学习、结课等词出现时发送，不再由裸「考试」「学习」带出；「做好…考试工作」条款只由
  考试工作、期中、期末带出。补全的是漏发：极端天气补大风、降温等词，常备信息汇总补后勤服务，课程修读与
  「课程…工作」带出教学日程的对照裁决。service_info 定义按并列项拆分，只发命中的设施或服务项。对照条款
  仍挂同一组信号。省掉清单末项时保留的最后一项改用句号收尾，已有问题逐字不变。模型车道 703 条中位 5.9k 字、
  90 分位 7.4k、最长 1.2 万字，平均每条与期望标签无关的条款从 0.7k 字降到 0.5k；规则车道 2672 条全对，LLM
  系统提示仍与 0.3.34 逐字相同。
- 判定文本 0.3.38 把标题命中的易混裁决也移到 category 问题的 instructions 里发一次，不再复制到裁决点名的
  每个类别下（原来平均每条通知 956 字裁决里约 560 字是复制）；类别判据只剩按标题拼装的定义，news 仍附泄漏
  防护。703 条每条发出的裁决集合与 0.3.37 相同（离线比对），只是位置不同；判定文本未改，LLM 系统提示不变。
  模型车道中位 5.4k 字、90 分位 6.1k、最长 7.8k。这依赖决策模型同时读 instructions 与 criteria，0.3.36
  起已经这样放置四条宽口径裁决，由下一次决策模型全量评测一起验证；评测显示裁决放进 instructions 后判错，
  就退回挂在类别下的放置。
- 判定文本 0.3.39 删去与类别定义重复的文本，改动同时进入 LLM 系统提示。四条宽口径裁决的主句复述两边的类别
  定义，删去后只留带信号的特例句：「制度制定」「纪检」并入 governance 定义，「认定」「登记」「按既定流程」
  并入 affairs 定义，「组织干部填答问卷」并入 governance 与 affairs 的特例句；affairs 与 application 的裁决
  两句都已在定义里，整条删除。主栏目（教学、办公、学工、科研通知，占模型车道 94%）的栏目说明只是「按标题
  判」与九个常见类别，删去；news 泄漏防护里每次都发的两句并入 news 定义，防护只剩按标题发送的三条。决策
  模型不再收到输入说明：规则筛选与栏目分布对选类别没有作用，「notice_type 只作形式参考」由栏目说明的引导句
  保留；标题不命中任何裁决时也不发「易混裁决：」标题。intent 问题与 0.3.38 逐字相同。模型车道中位 4.4k 字、
  90 分位 5.1k、最长 6.8k，标题不命中任何信号时 3.6k；LLM 系统提示 1.99 万字。之后不再为省输入改判定文本，
  改动只看判对率。
- 判定文本 0.3.40 恢复 affairs 与 application 的裁决，每次都发。0.3.39 的 50 条抽样中决策模型把「社会类奖助学金
  评定工作」从 application 判成 affairs（0.3.38 判对，决策模型确定性输出）：拆开后两边定义各自读，affairs
  定义新增的「认定」与「评定」字面相近，缺了「主动争取对既定流程」的并列对照。按标题信号发送会漏掉 28 条
  application 与 119 条 affairs（微专业招生、岗位评聘、领取、学位授予），这组对照对两类都适用，所以不设信号。
- 判定文本 0.3.41 让 intent 判据每次发全文，类别定义仍按标题裁剪。0.3.40 第一批 50 条新抽样决策模型错 4 条
  （LLM 全对），按提交逐版回放：0.3.34 四条全对，0.3.35 起 intent 判据按标题裁剪后陆续出错（「鼓励师生预约
  教室」reference 判成 action，「导师遴选专项自查」notice 判成 action，「受灾学生临时困难补助工作」action 判成
